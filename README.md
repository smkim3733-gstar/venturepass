# 벤처패스 · VenturePass

벤처기업확인 **혁신성장유형 전용** 신청 준비 앱입니다. 회사 자료를 모아 아이템 분석, 사업계획서 작성·검토, 증빙 관리, 신청 진행 관리로 연결합니다.

## 시작하기

Node.js 24와 pnpm 11.19.0을 사용합니다.

```sh
git clone https://github.com/smkim3733-gstar/venturepass.git
cd venturepass/web
pnpm install --frozen-lockfile
pnpm dev
```

[로컬 앱](http://127.0.0.1:3000)을 엽니다. API 키 없이 기업 자료 관리와 자료 기반 정리 기능을 사용할 수 있습니다. AI 기능은 [환경변수 예시](web/.env.example)를 참고하여 `web/.env.local`에 서버용 API 키를 설정합니다.

## 현재 제공하는 기능

- 기업별 자료 보관·추출, 아이템 분석, 사업계획서 편집·검토·버전 관리·내보내기
- 증빙 준비와 실사 예상 질문, 담당 업무·기한·진행 단계 관리
- 2026년 8월 혁신성장유형 명단의 기업 검색과 업종·지역 통계
- Windows DPAPI를 이용한 기업별 벤처인 계정 암호화 보관과 별도 Edge 로그인 연결
- 공식 신청 화면의 항목·원본 대응표, 제출 전 점검, 값·파일 검토와 승인 후 1회 입력·첨부, 최근 화면별 실행 이력
- 담당자가 기록한 확인서 통보와 사용자가 정한 차기 준비일을 연결하는 업무 관리

입력·첨부 실행 경로는 가상 자료와 모의 브라우저로 검증했습니다. 실제 회사의 공식 입력·업로드와 기관 처리 결과는 아직 검증하지 않았습니다. 추가 인증·브라우저 권한 선택·공식 화면의 다음 단계 이동은 사용자가 진행합니다. 저장·동의·최종 제출·납부 및 기관 상태 수신은 자동 실행하지 않습니다. AI API의 실제 생성 품질과 공식 제출 흐름은 추가 검증이 필요하며 벤처확인 통과를 보장하지 않습니다.

## 확인서와 차기 준비 업무

1. 기업의 **진행 관리**에서 기관 통보를 **확인서** 분류로 기록합니다. 확인서 번호와 유효기간 등은 담당자가 원문을 확인해 입력하며, 모르는 값은 비워 둘 수 있습니다.
2. **확인서·차기 준비**에서 연결할 최신 통보 버전을 확인하고 준비일을 직접 선택해 업무를 만듭니다. 준비일은 자동 입력하지 않으며, 확인서에 기록된 만료일을 법정 갱신기한으로 계산하지 않습니다.
3. 생성한 업무의 담당자·기한·완료 여부는 기존 업무 편집에서 관리합니다. 같은 통보 버전으로 다시 요청해도 업무를 중복 생성하지 않습니다. 이미 만든 업무의 날짜를 바꾸려면 해당 업무를 편집합니다.
4. 통보를 정정하면 과거 버전에 연결된 업무의 기한과 완료 상태를 보존하고 재확인을 표시합니다. 최신 확인서 통보 버전의 업무는 내용을 확인한 뒤 별도로 만들 수 있습니다.

기업 목록에는 기록된 만료일, 날짜 미확인·준비 필요·통보 변경 건수를 표시합니다. 날짜만으로 확인서 효력이나 취소 여부를 판정하지 않습니다. 기한 경과·7일 내 필터는 사용자가 입력한 업무 기한을 기준으로 하며, 업무 완료는 기관 신청·접수·갱신 완료를 의미하지 않습니다.

## 데이터와 로컬 저장

앱 실행에 필요한 `web/data`의 명단·통계 JSON은 포함되어 있습니다. 대표자명은 제외했으며, 명단의 기업 주소 등은 원본 표기를 유지합니다. 이 명단의 분포는 합격률이나 개별 기업의 심사 통과 사유를 뜻하지 않습니다.

원본 PDF·Excel, 중간 분석 파일과 보고서 산출물은 이 저장소에 포함하지 않습니다. `pnpm data:import`는 해당 원본 Excel과 `분석/workbook_data.json`을 별도로 갖춘 개발 환경에서만 실행합니다. 일반 실행과 테스트에는 포함된 JSON을 사용합니다.

사용자가 입력한 기업 자료·원본 업로드·저장 계정은 기본적으로 `web/.venture-pass`에 보관하며 Git에서 제외합니다. `.env.local` 등 실제 환경설정과 API 키도 업로드하지 않습니다. 앱은 기본적으로 이 PC의 `127.0.0.1`에만 연결되는 로컬 작업공간이며, 공개 서비스 배포에는 별도의 사용자 인증·접근권한과 운영 저장소 설계가 필요합니다.
