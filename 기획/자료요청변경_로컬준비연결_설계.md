# 자료·요청 변경 뒤 로컬 준비 연결

상태: R07의 코어·저장·서비스·API·화면 구현과 범위 검사·독립 검토, 고정 전체 검사와 격리 API/UI 검증을 완료했다. 명시적으로 시작한 로컬 준비의 변경 사건 연결이며, 무인 서버·외부 AI·기관 실행을 새로 허용하지 않는다.

## 기존 흐름 재사용

`studio-preparation.ts`의 assisted 진단→자료 기반 분석→후보 선택 대기→원고 준비를 재사용한다. `source`·프로필·기관 요청/답변 저장 때마다 별도 분석기를 만들지 않는다. 회사별 허용 상태를 사용자가 한 번 선택하고 이후 저장된 최신 변경만 묶어서 준비한다. 기본은 비활성이고 기존 회사에 소급 적용하지 않는다.

## 저장과 실행 경계

- 허용 범위는 로컬 자료 정리·진단·기존 로컬 준비 연결로 고정한다. 외부 AI, 파일 판독/전사, 후보 자동 선택, 사실 확인, 기존 원고 덮어쓰기, 기관 행동은 포함하지 않는다.
- 프로필·자료 본문/종류·기관 요청/답변의 실제 변경을 저장 트랜잭션에서 감지한다. 분석 결과·원고·업무·진행 단계 변경이 새 준비 사건을 재귀 생성하지 않게 한다. 원본만 접수한 pending 자료는 검토 대기를 표시한다.
- 사건에는 종류·대상 ID/버전·원문을 포함하지 않는 식별 해시·기록 시각만 둔다. 같은 원인 재전송은 중복 생성하지 않는다. 대기 사건은 최신 회사 상태로 묶고, 과거 완료한 준비·원고는 보존한다.
- 앱 화면이 열려 있고 편집·기관 입력·다른 작업이 없을 때 허용된 준비를 이어간다. 브라우저 종료 후 계속 실행된다고 표시하지 않는다. 회사 전환·새 버전·dirty·busy 상태에서는 요청하지 않는다.
- 처리 시작 전에 사건 묶음·요청 nonce·허용 버전·현재 자료 fingerprint를 기록한다. 재시작·응답 유실은 해당 기록을 조회해 이어가며 새로운 nonce로 같은 완료 작업을 재생성하지 않는다.
- 연속 변경이 실행 도중 들어오면 현재 결과의 CAS를 지키고 최신 사건을 남긴다. 새 변경을 과거 결과로 덮어쓰지 않는다. 자료·후보·본문 확인이 필요한 곳에서는 기존 확인 UI로 연결한다.
- 기관 요청/답변만 바뀐 경우 기존 진단·원고를 불필요하게 다시 만들지 않는다. 해당 요청의 기존 작업/답변 준비 화면으로 연결하고, 최신 요청 버전과 담당자 검토가 필요함을 표시한다.
- 허용 해제는 새 실행을 막는다. 이미 원자 저장한 산출물은 지우지 않는다. 보관 한도를 넘으면 기록을 몰래 삭제하지 않고 새 연결을 보류한다.

## 검증 종료 조건

기본 비활성·한 번 허용→본문 저장→자동 로컬 준비→후보 대기, 여러 변경 합치기, 같은 요청/완료 단계 중복 없음, 수동 원고 보존, dirty/busy/회사 전환 차단, 재시작/응답 유실 복원, 기관 요청만 변경 시 분석·원고 불변, 외부 AI/공식 사이트 호출 0을 합성 API/UI로 검증한다. 기존 명시 준비 버튼은 호환 경로로 유지한다.
