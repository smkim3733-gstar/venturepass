# 기준과 제출서류 조건의 버전 기록

상태: R11 최소 버전 기록·회차 연결·과거 출력 구현과 전체 검사·격리 API/UI 검증 완료(2026-09-26 00:06). 현행 기관 규정 검증 기록은 아니다. 기존 정적 제도 안내·사전진단·공식 화면의 입력/첨부 조건 수집을 대체하지 않는다.

고정 전체 3,296개·lint·타입·격리 빌드 통과. 합성 화면에서 새 기준 추가 후 과거 회차 연결 유지·재확인, 과거 정확한 버전의 명시 연결, 정정 확인일 초기화와 날짜 편집 후 확인 해제를 검증했다. 세 연결의 출력이 각각 고정한 조건/SHA를 보존하고 회사 JSON을 바꾸지 않음을 확인했다.

## 목표

담당자가 확인한 출처·확인일과 서류별 적용 대상·기간·발급일·대체자료 조건을 한 버전에 보관한다. 회사의 신청 회차에서 적용한 정확한 버전을 선택해 남기며, 이후 기준을 정정해도 과거 준비·제출 기준을 바꾸지 않는다.

## 최소 입력과 이력

- 기준의 제목, 내부 버전 표기, 적용 경로, 담당자 확인일, 출처 제목·URL, 해당 조건의 원문 인용 또는 확인 메모를 받는다. 날짜·조건이 없으면 미확인으로 남긴다.
- 서류별 이름, 적용 대상, 대상 기간, 발급일 조건, 대체자료 조건, 확인할 사항을 기록한다. 기관 원문에 없는 일수·대상·대체 가능 여부를 추정하지 않는다.
- 작성자와 수정 이유, 이전 버전 ID를 둔다. 이력은 추가 방식으로 보관하고 동시 수정·같은 요청 재시도·회사 격리·한도를 검사한다.
- 신청 회차에 연결할 때 기준 버전과 전체 내용 해시를 고정한다. 최신 버전으로 자동 교체하지 않는다. 수동 입력한 확인일은 앱이 직접 기관을 조회했다는 의미가 아니다.
- 자동연계 가능 안내와 실제 자료 수신 성공은 구분한다. 관측된 결과가 없으면 자동연계 성공·서류 확보 완료로 표시하지 않는다.

## 현재 코드와 연결할 때 검토할 경계

회사에 적용한 기준 변경은 준비 상태 재확인 사유가 된다. 기존 준비 fingerprint·원고 근거 revision·사전진단의 기준 버전과 어떻게 연결되는지 실제 코드를 확인한다. 구형 자료의 직렬화/해시를 무조건 바꾸지 않고, 과거 진단을 새 기준으로 실행한 것처럼 표시하지 않는다.

현행 기준을 기본값으로 제공하려면 공식 출처와 실제 확인일을 별도로 조사한다. 조사하지 않은 설계 예제는 합성 자료 또는 미확인으로 표시한다. 운영자 전용 대형 관리 화면·외부 규정 수집 자동화는 이 최소 기능의 필수조건으로 추가하지 않는다.

## 완료 검증

서류 조건 저장 → 새 버전 정정 → 정확한 회차 적용 → 과거 버전 보존 → 준비 상태 변경 표시 → 출력의 기준 버전 확인을 합성 API/UI에서 검사한다. 출처가 없는 값·미확인 조건·구형 이력·다른 기업/회차·재전송·동시 변경도 검사한다. 실제 기업의 적격성·기관 접수·규정 해석이 확인됐다는 결론은 내리지 않는다.
