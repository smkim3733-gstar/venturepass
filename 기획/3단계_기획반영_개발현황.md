- 일반 승인 화면은 준비본 선택→로컬 대조→정확한 검토안→전송 승인 순서다. 준비본 변경과 문맥 변경 시 이전 대조·승인 표시를 폐기하고 확인 필요 상태는 유지한다. v2 부분 복구는 원래 전체 선택과 준비본을 보존한 채 미시도 빈 텍스트만 새 승인에 포함한다. v1 기록·승인과 ID 없는 API의 기존 호환 경로는 준비본 미연결로 남기며 자동 승격하지 않는다. 첨부 실행의 자동 복구는 계속 제한한다.
- 응답 유실 복구에서 최신 실행 ID만으로 성공을 판단하던 문제를 수정했다. 전송 직전 회사·계정·세션·화면·revision·준비본·입력/보호 범위와 이전 실행 근거를 고정하고 POST/GET 모두 대조한다. 다른 최신 기록·진행 중·결과 미확인은 이번 요청의 확인으로 취급하지 않는다. 내부 검토 사유는 한국어로 표시한다.

## 실제 실행 전에 필요한 사항

실제 AI 품질 검증에는 사용할 자료·제공자·목적·비용 범위가 명확한 승인이 필요하다. 공식 사이트에는 현재 계정·회사·화면·정확한 입력 및 첨부·법적 동의·최종 제출·납부를 구분하여 기존 승인 범위부터 확인한다. 가상 자료를 공식 기관에 제출하지 않는다. 공식 미관측 동작을 추측해서 구현 완료로 표시하지 않는다.

기존 개발 서버와 사용자 자료·원본·미커밋 작업은 보존했다. Git push·공개 배포·실제 기관 실행은 수행하지 않았다. 이번 후속 범위는 v2 별도 전송 승인·합성 관측/정산·중단 복구·v6 백업이다. 다음 검토 화면 연결을 위한 자동 연속 개발 예약은 활성 상태다.
