# 인터넷 서비스 운영 준비 안내 (대표님용)

작성일: 2026-10-25. 이 안내는 6단계(계정 만들기·설정 넣기)를 대표님이 직접 하실 때 쓰는 순서입니다. 코드는 1~4단계까지 준비되어 있고, 아직 실제 계정·배포는 하지 않았습니다.

**지켜 주세요:** 비밀번호·키·DB 주소는 채팅에 붙여 넣지 마세요. 아래 화면에 직접 입력하시면 됩니다.

## 1. Supabase 프로젝트 만들기

1. https://supabase.com 에 로그인 → **New project**.
2. 이름: `venturepass` (자유), 지역: **Northeast Asia (Seoul)** 권장, DB 비밀번호는 안전한 곳에 보관.
3. 만들어지면 **Project Settings → API** 에서 두 값을 확인합니다.
   - Project URL → `SUPABASE_URL`
   - `anon` `public` 키 → `SUPABASE_ANON_KEY` (service_role 키는 쓰지 않습니다)
4. **Project Settings → Database → Connection string** 에서 **Transaction pooler** 주소(포트 6543)를 복사합니다 → `DATABASE_URL`. `[YOUR-PASSWORD]` 부분을 DB 비밀번호로 바꿉니다.

## 2. 표 만들기

1. Supabase 왼쪽 메뉴 **SQL Editor** → New query.
2. 저장소의 `web/supabase/schema.sql` 내용을 통째로 붙여 넣고 **Run**.
3. 여러 번 실행해도 안전합니다(이미 있으면 건너뜀).
4. 표 4개(`venture_organizations`, `venture_cases`, `venture_memberships`, `venture_prepared_packages`)에 행 단위 보안이 켜집니다. 이미 예전 `schema.sql`을 실행하셨더라도 새 내용을 한 번 더 실행하면 빠진 표만 추가됩니다. 이 때문에 anon 키로는 표를 직접 읽을 수 없고, 서버만 DB 주소로 접근합니다.

## 2-1. 원본 파일 저장소(Storage) 만들기

1. Supabase 왼쪽 메뉴 **Storage → New bucket**.
2. 이름: `venturepass-originals`, **Public bucket은 끈 채로(비공개)** 만듭니다.
3. **Project Settings → API** 의 `service_role` 키를 확인합니다 → `SUPABASE_SERVICE_ROLE_KEY`. 이 키는 모든 데이터를 다룰 수 있으니 Vercel 서버 환경변수에만 넣고, 다른 곳에는 절대 쓰지 마세요.
4. 이 두 가지를 하지 않으면 웹에서 파일 올리기·원본 내려받기만 "설정되지 않았습니다"로 막히고, 나머지 기능은 그대로 됩니다.

## 3. 첫 관리자 만들기

1. **Authentication → Users → Add user → Create new user** 에서 대표님 이메일·비밀번호로 사용자를 만듭니다(Auto Confirm 체크).
2. 만든 사용자의 **User UID**를 복사합니다.
3. SQL Editor 에서 아래를 실행합니다. `여기에-UID`, 이메일, 이름만 바꾸세요.

```sql
INSERT INTO venture_organizations (id, name)
VALUES ('11111111-1111-4111-8111-111111111111', '한국기업가치평가원');

INSERT INTO venture_memberships (user_id, organization_id, email, display_name, role, status)
VALUES ('여기에-UID', '11111111-1111-4111-8111-111111111111',
        '대표님@이메일', '표시할 이름', 'admin', 'active');
```

첫 관리자만 이렇게 SQL로 만들고, 그다음 담당자는 화면에서 관리합니다. 로그인 후 상단 **담당자 관리**에서 이름·이메일·역할(관리자 / 작성 담당 / 조회 전용)·처음 비밀번호를 넣으면 로그인 계정까지 함께 만들어집니다. 처음 비밀번호는 담당자에게 직접 전달하세요. 같은 화면에서 역할 변경, 사용 중지(바로 로그인 차단), 비밀번호 다시 정하기가 됩니다. 본인의 역할·상태는 바꿀 수 없어서 관리자가 0명이 되지 않습니다. 이 기능은 2-1의 `service_role` 키가 있어야 동작합니다.

## 4. Vercel 프로젝트 만들기

1. https://vercel.com → **Add New → Project** → GitHub `smkim3733-gstar/venturepass` 선택.
2. **Root Directory** 를 `web` 으로 지정합니다.
3. **Environment Variables** 에 아래를 넣습니다(Production).

| 이름 | 값 |
|---|---|
| `VENTUREPASS_MODE` | `server` |
| `VENTUREPASS_ORIGIN` | 배포 주소, 예: `https://venturepass.vercel.app` (처음 배포 후 실제 주소로 수정) |
| `DATABASE_URL` | 1-4의 Transaction pooler 주소 |
| `SUPABASE_URL` | 1-3의 Project URL |
| `SUPABASE_ANON_KEY` | 1-3의 anon 키 |
| `SUPABASE_SERVICE_ROLE_KEY` | 2-1의 service_role 키(원본 파일 저장용, 서버 전용) |
| `SUPABASE_STORAGE_BUCKET` | `venturepass-originals` (생략 가능) |
| `OPENAI_API_KEY` | OpenAI 키(AI 기능을 쓸 때만) |
| `OPENAI_MODEL` | `gpt-5.4` |

4. **Deploy**. 주소가 나오면 `VENTUREPASS_ORIGIN`을 그 주소로 고치고 한 번 더 배포합니다.

## 5. 확인

1. `https://배포주소/login` 에서 3단계의 관리자 계정으로 로그인합니다.
2. 회사 추가 → 회사 설명 → 정리본 만들기가 되는지 확인합니다.
3. 설정이 하나라도 빠지면 화면에 "웹 서비스 설정이 완료되지 않았습니다"가 나옵니다. 이때 이 PC 자료로 몰래 돌아가지 않습니다.

## 6. 이 PC 앱 자료를 웹으로 옮기기 (필요할 때만)

이 PC 앱에 넣어 둔 회사를 웹 서비스의 한 조직으로 복사합니다. 이 PC 자료는 읽기만 하고 바꾸지 않습니다. 웹에 이미 있는 기록은 덮어쓰지 않습니다.

1. 이 PC의 `web/.env.local`에 `DATABASE_URL`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`를 직접 넣습니다. 값은 4단계 Vercel에 넣은 것과 같습니다. 채팅에 붙여 넣지 마세요.
2. Claude에게 "PC 자료를 웹으로 옮겨줘"라고 하거나, `web` 폴더에서 직접 실행합니다.

```bash
pnpm data:to-web
```

조직 목록이 나오면 옮길 조직의 ID로 먼저 미리 보기를 합니다. 미리 보기는 아무것도 쓰지 않습니다.

```bash
pnpm data:to-web --organization 조직ID
```

3. 결과가 맞으면 같은 명령에 `--apply`를 붙여 실제로 옮깁니다. 다시 실행해도 이미 옮긴 회사는 건너뜁니다.

| 결과 | 뜻 |
|---|---|
| 옮겼습니다 | 회사 기록과 원본 파일을 웹에 복사함 |
| 이미 같은 내용으로 옮겨져 있습니다 | 예전에 옮긴 그대로라 건너뜀 |
| 같은 회사로 보이는 기업이 있습니다 | 사업자번호(없으면 회사명)가 같은 회사가 웹에 있어 건너뜀. 그래도 옮기려면 `--allow-duplicate 기업ID` |
| 내용이 다릅니다 | 웹에서 이미 고친 기록이라 덮어쓰지 않음 |
| 원본 파일이 이 PC에 없습니다 | 원본이 빠진 회사는 옮기지 않음 |
| 보관본이 보관 당시와 다릅니다 | 원고·첨부 보관본(준비본)의 기록이나 ZIP이 바뀐 회사는 옮기지 않음 |

원고·첨부 보관본(준비본)은 회사와 함께 옮깁니다(버전 순서·ZIP 대조 후). 벤처인 계정·벤처인 진행 기록·접수 단계 원본은 이 PC 전용이라 옮기지 않고 개수만 알려 줍니다.

## 웹의 제출 준비 ZIP·실사 준비 ZIP

웹에서도 원고와 선택한 원본을 ZIP으로 내려받을 수 있습니다. 실사 준비 ZIP도 같습니다. 웹 서버가 한 번에 돌려줄 수 있는 크기(약 4.5MB)보다 ZIP이 클 수 있습니다. 그래서 서버가 ZIP을 원본 저장소(`venturepass-originals`)의 `exports` 폴더에 잠시 두고, 5분짜리 다운로드 링크로 넘겨줍니다. 만든 ZIP은 1시간 동안만 내려받을 수 있고, 같은 회사의 다음 ZIP을 만들 때 지워집니다.

## 웹의 원고·첨부 보관본(준비본)

간단 화면의 **원고·첨부 보관 및 내려받기**에서 원고와 선택한 원본을 한 버전으로 보관합니다(이 PC 앱과 같은 기능). 보관 기록은 DB 표 `venture_prepared_packages`에, ZIP은 원본 저장소의 `prepared` 폴더에 둡니다. 임시 ZIP과 달리 시간이 지나도 지워지지 않습니다. 회사마다 최대 20개까지이고, 회사를 지우면 보관본도 함께 지워집니다. 내려받을 때 서버가 ZIP이 보관 당시와 같은지(SHA-256) 확인한 뒤 5분짜리 링크로 넘겨줍니다. 조회 담당자는 내려받기만 할 수 있습니다.

## 아직 웹에서 안 되는 것

- 벤처인 자동 입력·Windows 글자 읽기(OCR)·품질평가 도구 — 이 PC 앱 전용으로 유지

회사 삭제는 웹에서 **관리자만** 할 수 있습니다. 회사를 지우면 저장소에 있던 그 회사의 원본·ZIP·보관본·올리다 만 임시 파일도 함께 지웁니다. 4MB 넘는 파일을 올리다가 끝내지 않은 임시 파일은 1시간이 지나면 같은 회사에 다음 파일을 올릴 때 지워집니다.

담당자는 화면 위의 **내 계정**에서 자기 비밀번호를 직접 바꿀 수 있습니다. 지금 비밀번호를 확인한 뒤 바꾸고, 다른 기기의 로그인은 끝냅니다.

## 비용

Supabase·Vercel 무료 한도 안에서 시작할 수 있습니다. 사용량이 늘면 월 비용이 생길 수 있습니다. OpenAI는 AI 기능을 쓸 때마다 비용이 듭니다.
