1. 명시 v11 전환은 감사된 v10의 비교 native suffix가 비어 있을 때만 허용한다. 과거 v9 prefix·전환 coverage의 target10/원문 bytes와 실제 행 삽입 순서를 바꾸지 않는다. 기존 constructor는 자동 승격하지 않는다.

4. 한 BEGIN IMMEDIATE 안에서 전체 읽기/nonce 우선→순수 계획→모든 행 쓰기→전체 사후 감사→COMMIT한다. 현재 회사 입력과 검토 근거를 다시 확인할 caller guard의 범위를 명시한다. 이 격리 단계에서 실제 회사 DB 잠금/파일 신원이나 사람 동의·가격 진위를 완료했다고 주장하지 않는다.
5. 예약/취소 재열기·같은 nonce 다른 명령·취소 내부 종료·원래 예산 누적, insert별 실패/COMMIT 반환 유실·다른 연결 경쟁·old writer 차단을 합성 검증한다. 실제 COMMIT 뒤 응답 유실이면 새 행/ID/owner 없이 원래 nonce를 읽는다. 부분 취소/불명 연결 상태를 성공이나 미전송으로 추정하지 않는다.
6. 실제 고객/운영 DB·키/SDK/route/UI·전송을 열지 않는다. 백업 보호/.git/경로는 유지하며 알려진27개 왕복을 반복하지 않는다. 출시에는 별도 backup/restore·실제 회사 guard/복원 증인·예약/전송 동의·현재 공식 금액/보관 조건과 AI 의미 품질 검증이 필요하다.

이번은 SQL writer가 아닌 사전 계획이며, 후속 DB 저장 성공도 공급자 실행/공식 진위나 사람 인수를 뜻하지 않는다.
