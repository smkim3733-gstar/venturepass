## 2. 원래 선택 취득과 서버 보관

신뢰하는 내부 호출자는 이미 보유한 service와 그 원래 runId/dispatchCommandDigest를 사용한다. 명시 mode는 historical 또는 inspect-current다. 요청/화면의 임의 경로·DB handle·session token·SDK 옵션·current snapshot을 서버 권한 입력으로 받지 않는다. 현재 UI에는 원래 run 취득 기능이 없으므로 실제 route를 열 준비가 끝난 것이 아니다.

같은 service.readStoredReviewByRun을 정확히 한 번 호출한다. 내부 두 감사는 기존 구현 그대로이며 단일 snapshot이라고 표시하지 않는다. 반환 전에 원래 SQL13/증인3/event/hash·archive/request/capture/validated 대조와 자기 정리가 끝나야 한다. 서버 encoder는 이 반환을 wire 형태로 제한한다. encoder의 형태 검사만으로 호출자가 만든 임의 객체를 저장 증거로 인정하지 않는다.

session/service는 화면 컴포넌트나 HTTP Response의 소유가 아니다. 현재 서비스는 동기 읽기이며 request.signal을 받아 중간 SQLite를 중단하지 않는다. 실제 전달 계층을 나중 설치하면 호출 전 이미 취소된 요청은 시작하지 않고, 호출 후 취소는 결과 전달만 버린다. 이미 진입한 서버 호출은 자기 finally/원래 명령 복구 책임을 마쳐야 한다. 시간 초과/소켓 닫힘을 성공적인 rollback/미실행으로 기록하지 않는다.

새 session/driver/owner/전역 registry·TTL eviction·요청별 factory는 다음4I36에도 만들지 않는다. server-only encoder와 기존 service를 합성 시험의 호출자가 보관한다. storage-only 재개방은 기존 명시 경로만 사용하고 새 전송은0이다. 운영에서 이 보관자를 설치/재시작하는 계약은 아직 미완료다.

## 3. Strict wire1 입출력

한 번의 명시 요청은 다음 세 필드만 가진다. JSON UTF-8 합계8KiB 이내다.

```ts
type Query = {
  runId: UUID;
  dispatchCommandDigest: LowercaseSha256;
  mode: "historical" | "inspect-current";
};
type SuccessWire = {
  wireVersion: 1;
  kind: "public-comparison-stored-review";
  query: Query;
  result: StoredComparisonRead; // 4I32/4I34의 원래 읽기 DTO, 축약/현재 재생성 없음
};
type ErrorWire = {
  wireVersion: 1;
  kind: "public-comparison-stored-review-error";
  code: PublicReadErrorCode;
};
```

success는 status200만 사용한다. error에는 원문 message/stack/회사·본문·파일 경로/명령·nonce를 싣지 않는다. status/code 고정 쌍은 INVALID_QUERY/400, LOCAL_ONLY/403, RESULT_UNAVAILABLE/404, READ_BLOCKED/409, TOO_LARGE/413, CONTENT_TYPE/415, READ_FAILED/500이다. 서버의 확인된 result-missing만 RESULT_UNAVAILABLE로 매핑하며 unknown·정리/복구 대기는 READ_BLOCKED다. 명시 매핑 밖 예외는 READ_FAILED다. 코드로 자동 복구/재시도하지 않는다. 기존 studioRoute가 돌려주는 다른 오류 envelope는 이 wire의 성공으로 받지 않으며 클라이언트의 고정 일반 오류로만 처리한다.

클라이언트 로컬 실패는 CANCELLED/TIMEOUT/RECEIVE_LIMIT/INVALID_RESPONSE/RECEIVE_FAILED로 구분한다. 화면에 표시할 문구는 로컬 고정 매핑이다. 서버 body.error, reason 문자열을 임의 사용자 오류로 노출하지 않는다. 현재성 reason은 아래 유한 코드만 구조화 상태로 허용한다.

### Result의 정확한 형태/연관성

- root key는 source/resultIdentity/historical/database/current/owner/runtimeObserved/authority뿐이다. source는 synthetic-comparison-stored-review, owner:null, runtimeObserved:false, comparisonPlanAuthority의9필드는 모두false다. optional fallback/default/coercion/unknown key strip을 하지 않는다.
- resultIdentity는 선택5필드(runId/dispatchCommandDigest/comparisonEventDigest/responseArtifactSha256/validatedArtifactSha256)에 requestIdentity/preparationDigest/selection/binding을 더한 기존 형태다. query의 원래2개와 같아야 한다. UUID/소문자64자리SHA·기존 strict selection/requestIdentity schema를 재사용한다.
- historical은 prepared/result/currentContextVerified:false만 포함한다. prepared의 contractVersion/경계 literal·selection/binding/input/preparationDigest/inputCharacters는 기존 archive 준비 schema와 한도를 공유한다. section 전체/선택 발췌를 잘라서 반환하지 않는다.
- identity와 prepared의 selection/binding/preparationDigest, result.requestIdentity와 identity.requestIdentity, result.responseArtifactSha256와 선택 hash가 각각 같아야 한다. requestIdentity.preparationDigest도 일치한다. wire에 canonical response/DB 행은 없으므로 브라우저에서 responseArtifact의 SHA나 DB 증인을 새로 검증했다고 주장할 수 없다.

wire decoder는 UTF-8 해독/JSON.parse 후 unknown을 받아 재귀 strict shape와 위 연관성을 대조한다. 공용 데이터 schema 및 인용 대조의 순수 부분을 기존 코드에서 추출할 수 있다. 서버의 기존 해시/직렬화/오류 동작을 유지하고 동일 기능을 두 벌로 복사하지 않는다. 브라우저 실행 경로에 node:crypto/SQLite/SDK/production 모듈을 넣지 않는다.

전용 encoder는 고정 key 순서의 JSON.stringify로 출력한다. decoder가 schema 대조 후 같은 정규 순서로 만든 JSON과 원래 해독 문자열이 정확히 같아야 한다. 추가/중복 key, trim/coerce/default, 공백/키순서 변경·BOM을 조용히 정규화해 통과시키지 않는다. 이는 새 wire1 전용 직렬화 약속이며 과거 DB artifact bytes를 다시 쓰는 요구가 아니다. 결과는 독립 사본이고 ticket으로 넘겨도 모든 false 권한을 유지한다.

## 4. 수신·해독과 중단 수명

| 대상 | 다음 구현의 고정 한도/정책 | 의미 |
|---|---|---|
| query JSON | UTF-8 8KiB | 기존 selection 사본 한도 유지 |
| result DTO JSON | UTF-8 4MiB | 기존 저장 결과 사본 한도 유지 |
| success wire 전체 | UTF-8 4MiB+8KiB | envelope 포함 누적 cap, DTO 자체 증액 금지 |
| error wire 전체 | UTF-8 8KiB | status 실패도 성공 cap으로 읽지 않음 |
| 수신 기한 | 생성/start 준비 시점부터30000ms 단조 deadline1개 | 단순 로컬 읽기용 설계값. 서버 SQLite 강제 중단/SLA가 아님 |
| 호출 | 주입 start1회, 자동 retry0 | URL/fetch/SDK 기본값0, 같은 reader1개 |
| 전달/정리 | delivery와 completion/cleanupFailed 분리 | 빠른 실패 뒤 원래 I/O 책임 유지 |

다음4I36은 네트워크를 열지 않는다. 호출자는 고정 query와 signal을 첫 await 전에 보관하고, 주입된 합성 start(signal) 하나에서 Response를 얻는다. 서버 encoder가 만든 합성 Response도 같은 수신기를 통과시켜 ticket까지 확인한다. start가 임의 ready DTO를 반환하면 거절한다. 실제 fetch/endpoint 설치는 후속 범위다.

수신 시작 전 중단/기한을 확인하고 원래 start promise에 성공·실패 observer를 즉시 건다. Response의 native 접근자로 status/body/headers/bodyUsed/redirected를 확인한다. status0/redirect/이미 사용/잠긴 body는 거절한다. Content-Type은 application/json 또는 application/json; charset=utf-8만 대소문자/합리적인 구분 공백을 허용하고 다른 charset/추가 매개변수/HTML은 거절한다.

Content-Length가 있으면0 또는 선행0 없는 정수·안전 정수·해당cap 이내인지 조기 확인한다. 없어도 EOF까지 실제 노출 Uint8Array 길이로 누적 검사한다. 브라우저가 해제한 압축 본문과 헤더 길이가 다를 수 있으므로 헤더와 누적값의 동등성을 근거로 DB진위나 wire 압축량을 보장하지 않는다. 큰 한 청크는 복사 전에 거절하고 prefix를 성공 값으로 반환하지 않는다. 수신 cap은 브라우저가 노출한 본문 bytes의 보관 상한이며 TLS/압축wire/헤더/전체heap/이미 할당된 청크 상한은 아니다.

본문없음·EOF0은 success/error 모두 유효 wire가 아니다. 완전한 EOF와 reader.releaseLock 완료 뒤에만 fatal TextDecoder UTF-8 해독1회·JSON.parse1회·strict검사를 수행한다. byte cap 이전 response.json/text/arrayBuffer/clone을 호출하지 않는다. JSON 문자열 안의 별도 encoded JSON을 다시 해독하지 않는다. 기한/취소를 매 read 전후와 최종 수락 직전에 다시 검사한다. 동기 decode/JSON/스키마 실행은 선점 중단할 수 없으므로 그 시간을 지난 결과도 폐기하지만 CPU 시간 하드 상한이라고 주장하지 않는다.

취소·초과·오류·기한 만료는 delivery를 한 번 실패시킨다. 자기 AbortController만 중단하고 원래 stream/reader cancel은 최대1회 요청한다. pending read/cancel과 늦게 도착한 Response의 정리는 completion까지 추적한다. cancel 거절/throw·release 실패는 cleanupFailed를 남기며 pending 원래 promise가 남으면 settled를 보고하지 않는다. unhandled rejection/자동 재수신/타 timer로 재시작을 만들지 않는다. 호출자는 수신 객체를 원래 I/O 정리 완료까지 보관한다. 이 클라이언트 객체의 완료도 서버 owner/session 종료 증거는 아니다.
