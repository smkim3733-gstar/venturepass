## 3. URL·시간·본문·취소 경계

허용 외부 origin은 `https://kosis.kr`, 경로는 `/openapi/statisticsSearch.do`, `/openapi/statisticsData.do` 둘뿐이다. GET와 위 정확한 매개변수 조합만 허용한다. 전송 시도 전에 전용 실행기의 단일 카운터로 전체9/검색5/종류별1을 예약하고, 남은 예산이 없으면 네트워크0으로 중단한다. redirect:error·credentials:omit·no-referrer·cache:no-store·Accept:application/json을 유지한다.

로컬은 실행기가 새로 만든 127.0.0.1 임시 포트의 `POST /api/studio/public-research/search`만 허용한다. 검색 본문1KiB, metadata8KiB와 strict 명령·동일 origin/Host 검사를 재사용한다. 모든 다른 외부 주소·SSO·npm/telemetry·서버 쓰기·계정·회사 API는 차단한다. 원래 URL/헤더를 출력하는 디버그/HTTP trace/HAR는 끈다.

기존 transport는 응답당512KiB를 content-length와 실제 body bytes로 검사하며 엄격한 UTF-8/JSON을 사용한다. 총9회가 모두 상한까지 왔다면 수신량 산술상4.5MiB지만, 이는 저장량이나 서비스의 전체 합산 제한이 아니다. 배열/문자 한도는 별도다. TBL≤1행, PRD≤32행, SOURCE≤10행, CMMT≤100행은 앱 정책이다. 초과를 자르지 않는다.

최초 검색20초, metadata는 재검색+설명 전체20초다. 5개 명령의 응답 기한 합은 최대100초지만, timeout이 원래 I/O 종료를 증명하지 않는다. 슬롯은 원래 fetch/read/cancel 종료까지 유지된다. timeout/취소/HTTP 실패/리디렉션/수신 초과/형식 거절/원래 후보 변경/키 소실/카운터 위반이 하나라도 발생하면 이후 명령0이다. 취소를 무시하는 원래 I/O는 종료 미확인으로 보고하고 새 호출을 시작하지 않는다. 전용 child의 종료를 관측해도 제공자 쪽 취소 완료를 주장하지 않는다.

## 4. 승인 뒤 격리 환경·키 확인

현재 실제 API 실행기와 키 주입은 만들거나 실행하지 않았다. 승인되면 다음 준비를 먼저 마치고 합성 경계 검사 뒤 한 번만 활성화한다. 기존 합성 metadata-validation 전체를 키만 바꿔 실행하면 호출 수/실패 주입/서버 재시작이 달라지므로 금지한다.

1. 기존 X7EitN 프로덕션 빌드 사본의 관련 소스와 구성 SHA·BUILD_ID·env파일 부재를 대조한다. 최신 입력과 일치할 때만 재사용한다. 고객 앱 서버는 건드리지 않고 현재 빌드와 맞지 않으면 실제 호출 전에 종료한다.
2. 지정 루트 `.venturepass-tools/build-temp/` 아래 새 `venturepass-kosis-read-<random>` 폴더와 그 안의 결과 요약을 사용한다. 기존 운영 검증 디렉터리/고객 data/control/lock과 분리한다. SQLite/회사 생성·원장 writer·SDK/AI 모듈을 실행하지 않는다.
3. 기존 route/service/transport를 재사용하는 전용 임시 실행기에 정확한 요청/카운터·오류 비노출을 넣는다. 첫 실제 호출 전 소스/빌드 전이와 차단 경계를 점검하고, 합성 fetch로 허용9회·10번째 차단·리디렉션/키 노출/취소 이후0을 확인한다. 이 합성 점검을 실제 KOSIS 검증으로 세지 않는다. 제품이 바뀌면 필요한 영향 검사 순서를 다시 적용하며 완료 전체 회귀를 반복하지 않는다.

## 5. 남길 기록과 성공·미확인 구분

로컬 요약은 시작/종료 UTC·KST, 빌드 ID, 후보 기관/표 ID, 종류별 시도 수/상태/받은 행수, HTTP 상태, 수신 바이트 수, 원래 I/O 종료 여부, 차단 횟수, 안전한 내부 오류 코드만 보관한다. 키·키 포함 전체 URL·헤더·stdout 원문 오류·전체 API body·Q&A 작성자/연락처·고객자료는 저장하지 않는다. 로그 파일은 Git에 넣지 않는다. 공개된 제공자 문자열이라도 key가 반사돼 포함될 수 있으므로 자유 문자열을 진단에 그대로 기록하지 않는다.

응답은 메모리에서 기존 서비스/strict decoder로 검사한다. 임의 복제 JSON을 실제 응답으로 바꾸지 않고 실제 전송 성공 여부와 decoder 수락을 각각 기록한다. 원문 bytes를 보관하지 않는 만큼 요약은 원문 재현 가능한 영속 공식 증거가 아니다. 오류 때에는 안전한 상태/분류만 보고하며 실패 원문을 붙여넣거나 parser를 즉석 완화하지 않는다.
