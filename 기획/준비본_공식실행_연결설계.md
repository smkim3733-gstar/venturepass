# 준비본과 공식 실행 연결 설계

작성일: 2026-09-26. 기존 실행기 코드를 읽고 정리한 다음 구현안이다. 이 문서 작성으로 공식 동작이나 승인을 실행하지 않았다.

## 확인한 기존 계약

- `venturein-preflight.ts`의 대응표는 기업·계정·세션·화면·원고 ID/버전, 확인한 본문 항목과 원본 ID/변경시각에 묶인다. 입력값을 자르거나 변환하지 않고 프로필 또는 해당 원고 항목의 정확한 문자열을 사용한다.
- `venturein-execution.ts`의 실행 전 검토는 현재 화면·대응표·본문·원본 SHA를 지문으로 만들고 2분 유효한 승인 요청을 발급한다. 실행 직전에도 현재성을 검사한다. 재시작하면 승인 요청은 소멸하고 기존 실행 기록은 보존된다.
- `venturein-execution-schema.ts`의 실행 기록에는 대상 항목과 지문이 있으며 준비본 ID/ZIP SHA는 아직 없다. 부분 입력·첨부의 완료가 공식 저장·최종 접수를 뜻하지 않는다.
- 불변 준비본은 기업·원고·선택 원본·검토 상태와 ZIP을 보관한다. 원본 삭제 뒤에도 내려받지만, 현재 공식 실행기는 안전하게 읽은 현재 원본을 사용한다. ZIP 보관만으로 현재 원본의 실행 가능성이 복구되지는 않는다.

## 다음 구현 범위

1. 먼저 읽기 전용 대조 결과를 만든다. 사용자가 선택한 준비본과 현재 입력 대응표의 기업, 원고 ID/버전/본문, 프로필 값, 선택 원본 ID/크기/이름/형식/SHA를 비교한다. 준비본 생성 시점과 이후 회사 변경도 표시한다.
2. 대조 결과는 현재 화면에 선택한 항목 범위로 한정한다. 이번 화면에서 선택하지 않은 원고 항목·원본을 누락 오류로 취급하거나, 일부 일치를 전체 신청 일치로 표시하지 않는다. 현재 대응표에 연결한 원본이 준비본에 없다면 별도 준비본 보관을 안내한다.
3. 불일치하면 덮어쓰기·문자 변환·파일 교체를 수행하지 않고 정확한 대상과 차이를 표시한다. 계정·비밀번호·원문을 감사 로그에 복제하지 않는다.
4. 대조 성공 후에도 기존 사전점검·공식 화면/기업 관측·원본 보호·입력 허용 범위가 모두 유지돼야 한다. 준비본의 사실 확인이나 내부 검토 상태를 자동 변경하지 않는다.
5. 새 승인 계약에는 준비본 ID·원고 내용 SHA·선택 파일의 SHA·ZIP SHA와 대조한 입력 지문을 함께 고정한다. 기존 승인에 준비본이나 새 동작의 권한을 소급 추가하지 않는다.
6. 저장·다음 화면·최종 제출은 각각 현재 공식 화면에서 버튼과 결과 신호를 관측한 뒤 별도 계약으로 연결한다. 미관측 버튼명·URL·성공 신호를 추측하지 않는다.
7. 실제 결과를 확인한 경우에만 기존 신청회차·공식 기록과 연결한다. 준비본, 실행 시도, 화면의 값 일치, 공식 접수 결과는 서로 다른 상태로 남긴다.

## 합성 검증 조건

- 같은 기업의 정확한 본문/파일 선택과 다른 회사·다른 원고·같은 ID의 변경 본문·다른 SHA·누락 원본을 대조한다.
- 선택 항목만 입력하는 경우와 전 항목을 준비한 경우를 구분한다. 준비본의 미선택 원본을 실행에 추가하지 않는다.
- 검토 후 원고/원본/대응표/계정/화면 변경, 같은 승인 재사용, 서버 재시작, 부분 실행·응답 유실에서 새 승인 없이 이어 쓰지 않는다.
- 실제 사이트 호출 없이 합성 화면과 기존 모의 실행기를 사용한다. 실환경 검증은 정확한 회사·현재 화면·입력/첨부 범위와 기존 승인부터 확인한다.

현재 구현된 준비본 보관을 공식 입력 승인 연결 완료로 표시하지 않는다. 이 연결은 품질평가 기록 저장·조회 묶음 이후의 독립 개발 시작점이다.


## 2026-09-27 구현 상태

`venturein-prepared-binding.ts`의 순수 대조와 합성 시험 55개를 구현했다. 정확한 전체 원고 SHA와 선택 값·원본·서버 검증 ZIP 상태를 대조하고 선택 순서를 보존한 연결 지문을 만든다. 준비본 생성 이후 회사 revision만 달라진 것은 안내값으로 남기며 기존 공식 사전점검의 최신성 검사를 면제하지 않는다. `accept:null`과 같은 원본의 서로 다른 공식 항목 선택을 기존 preflight 계약대로 허용한다. 파일 읽기·기관 접근·승인 발급은 수행하지 않는다.

다음 변경은 기존 `venturein-execution-schema.ts`/`venturein-execution.ts`/execution API와 승인 화면이다. 서버 내부에서 `downloadPreparedPackage()`로 ZIP 바이트를 검증한 결과를 대조 helper에 전달하고, 새 승인과 영속 실행 manifest에 정확한 준비본 연결을 고정한다. 기존 v1 기록/승인은 보존하고 준비본 권한을 소급 부여하지 않는다. prepare와 execute에서 다시 대조하고 텍스트 복구도 이전 연결 범위를 보존해야 한다. 이 연결 완료 전까지 순수 대조 통과를 공식 실행 가능·접수 완료로 표시하지 않는다.

## 2026-09-27 후속 연결 구현

서버의 `compare-prepared-package`는 보관 ZIP을 실제로 읽어 검증하고, 현재 원고 전체 내용과 선택 입력·원본을 대조한다. 승인이나 실행 기록을 만들지 않는다. 준비본 ID를 명시한 `prepare`는 v2 검토안과 단회 승인에 준비본 연결을 고정한다. `execute`는 다시 대조하고 최초 쓰기 전에 v2 manifest를 영속 저장하며, 실행 중 검사와 결과 확인에서도 같은 연결을 유지한다. ID가 전달됐는데 대조에 실패한 경우 준비본 없는 실행으로 돌아가지 않는다.

일반 승인 화면에서는 보관 준비본을 명시적으로 선택하고 대조한 뒤 검토안을 준비한다. 기존 v1 기록과 이미 발급된 승인은 보존한다. 이전 클라이언트와의 호환을 위한 준비본 ID 없는 API 요청은 v1이며 준비본이 연결됐다고 표시하지 않는다. v1 복구에 새 준비본을 붙이지 않고 v2 복구도 원래 준비본과 전체 선택 범위를 유지한다. 새 승인은 확인된 미시도 빈 텍스트에만 한정하며 첨부가 포함된 실행의 자동 복구는 제공하지 않는다.

화면에서 준비본을 바꾸거나 회사·원고·대응표·계정·세션이 바뀌면 이전 대조와 승인 표시를 재사용하지 않는다. 실행 응답 유실 후 조회에서도 전송 직전 회사·계정·화면·준비본·입력 및 보호 범위와 정확히 일치한 기록만 해당 요청 결과로 인정한다. 다른 최신 실행, 진행 중 기록, 결과 불명은 미확인 상태를 유지한다.

이 연결은 선택 항목 입력·첨부에 한정된다. 기관의 저장·이동·법적 동의·최종 접수·납부 성공은 별도 관측과 승인·결과 확인이 필요하다. 준비본의 확인 필요 표시와 전체 제출 전 보완사항은 연결 성공 후에도 유지한다. 검증 세부 결과는 `web/VALIDATION.md`와 개발현황의 최신 기록을 따른다.
