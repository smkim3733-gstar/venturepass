# 혁신성장유형 신청 사전진단 기능설계

작성일: 2026-09-23. 상태: 사용자 요구를 반영한 개발 설계안. 사전진단 기능은 아직 앱에 구현하지 않았으며, 개별 기업의 실제 진단 결과가 아니다.

심사준비도 항목은 [심사 중점·실사 준비 반영안](./혁신성장유형_심사중점_실사준비_반영안.md)의 기술 차별성·개발 역량·시장확대·실행 가능성과 연결한다. 진단 근거를 사업계획서 및 실사 질문에서 재사용하며, 공개 배점을 임의 합산한 합격점수·통과확률로 표시하지 않는다.

## 1. 첫 단계와 사용자 결과

첫 시작 버튼은 ‘우리 회사 혁신성장유형 사전진단’으로 한다.

회사 기본정보·보유자료 입력 → 추출 내용 확인 → 사전진단 → 필요한 질문·자료 보강 → 신청 아이템 선택 → 사업계획서 작성 → 제출 준비의 순서로 연결한다.

사용자는 다음 내용을 먼저 확인한다.

- 현재 자료에서 신청의 기본요건을 확인할 수 있는가?
- 기술혁신성과 사업성장성을 무엇으로 설명하고 입증할 수 있는가?
- 확인되지 않은 사항과 실제 약점은 무엇인가?
- 바로 원고 작성을 시작할지, 어떤 자료·활동을 먼저 보강할지?

## 2. 최초 입력

기업명, 법인·개인 구분, 설립일, 실제 업종, 신규·재확인 여부를 확인한다. 사업자등록증과 상담 녹취·제품설명서·회사소개서 중 보유한 자료부터 등록할 수 있게 한다. 자료에서 추출 가능한 정보를 먼저 채우고 사용자가 확인한다.

중소기업확인서, 재무자료, 특허, 시험성적서, 인력 경력 등은 있으면 함께 입력한다. 최초 진단에 모든 공식 제출서류를 요구하지 않으며, 확인되지 않는 항목은 후속 질문이나 자료 요청으로 남긴다. 녹취가 없는 기업은 짧은 문답으로 기술·고객·개발 상태를 설명할 수 있다.

## 3. 판단 영역

| 영역 | 확인 내용 | 항목별 상태 |
|---|---|---|
| 기본요건 | 중소기업 해당 여부, 공식 신청 제외업종 해당 여부 등 확인된 기준 | 충족 근거 있음 / 미충족 근거 있음 / 확인 필요 / 해당 없음 |
| 기술혁신성 준비도 | 자사 기술의 내용·개발 단계, 차별성, 개발 인력·이력, 검증자료, 향후 개발계획 | 설명·근거 확보 / 보강 필요 / 판단자료 부족 |
| 사업성장성 준비도 | 목표 고객과 문제, 수요·시장 근거, 사업화 방식, 실적 또는 실행계획, 인력·자금 실행 가능성 | 설명·근거 확보 / 보강 필요 / 판단자료 부족 |
| 자료 신뢰성과 일치 | 기업·기간 일치, 읽기 실패, 숫자 충돌, 실적·계획 구분, 발급·유효기간 | 확인 완료 / 확인 필요 / 불일치 |

공식 혁신성장유형 안내는 중소기업 해당 여부와 기술혁신성·사업성장성에 대한 기관 평가를 명시하고 신청불가 업종을 별도로 안내한다. 최종 기관 평가를 앱이 대체하지 않는다. 구체적인 기준과 예외는 구현 시 공식 근거·적용일·기준 버전을 함께 관리한다.

특허·연구소 보유를 모든 기업의 공통 필수조건으로 설정하지 않는다. 서류 부재, 매출 미발생, 대표의 설명 부족만으로 신청 불가를 단정하지 않는다. 대표 진술, 문서 기재, 외부 확인 결과를 구분한다. 자료에 기재되었다는 사실만으로 진실성이 검증됐다고 표시하지 않는다.

## 4. 진단 결과와 다음 행동

| 대표 결과 | 의미 | 다음 행동 |
|---|---|---|
| 사업계획서 작성 진행 권장 | 검토 범위에서 요건상 뚜렷한 문제가 없고 핵심 기술·고객 설명을 구성할 수 있음 | 아이템 비교·원고 작성, 남은 제출자료 계속 준비 |
| 보강 후 진행 권장 | 설명이나 근거, 실행계획에 중요한 부족이 확인됨 | 구체적인 질문·자료 요청·실행 과제 후 재진단 |
| 신청요건 문제 확인 | 공식 기본요건과 맞지 않는 근거가 확인됨 | 적용 근거와 사실관계 확인, 해결 가능한 원인 및 후속 경로 안내 |
| 자료 부족으로 판단 보류 | 핵심요건이나 기술·사업의 상태를 판단할 정보가 없음 | 필요한 최소 질문과 자료 요청 |

대표 결과와 별개로 기본요건·준비도·미확인 사항을 모두 표시한다. ‘작성 진행 권장’은 신청자격 확정이나 심사 통과 판정이 아니다. 통과확률이나 임의의 합격점수를 표시하지 않는다.

진단 항목마다 판단 사유, 자료명·페이지 또는 확보된 위치·원문 인용, 미확인 사항, 다음 행동을 연결한다. 실제 수행이 필요한 성능시험·고객검증 등을 문장 수정으로 해결했다고 처리하지 않는다.

## 5. 사업계획서로 연결

사전진단은 최종 아이템을 정하지 않은 상태에서도 기업의 기술·사업 근거를 살펴본다. 이후 후보 아이템을 선택하면 해당 아이템과 관련된 근거·약점을 다시 확인한다.

핵심 기술·고객 설명이 있으면 미확인 사항을 표시한 초안을 준비할 수 있다. 공식 제출 준비 완료는 필요한 기본요건·제출자료·주요 주장 검토를 별도로 마친 뒤에만 표시한다. 요건 미충족 근거가 있으면 해결 전 ‘신청 준비 완료’로 표시하지 않는다.

자료 변경 시 기존 진단을 과거 결과로 보존하고 재진단 필요 상태를 표시한다. 버전이 다른 진단과 원고를 최신 결과로 혼동하지 않게 한다. 새 자료 없이 표현만 바꾸어 진단 결과를 상향하지 않는다.

## 6. 현재 앱과의 연결

- `/application`의 준비 체크리스트와 `/studio`의 자료함을 기업별 작업공간으로 통합한다.
- 현재 아이템 분석 앞에 사전진단 결과 화면을 추가한다.
- 기본요건은 버전 관리한 규칙과 확인된 사실로 검토하고, AI는 기술·사업 분석과 근거별 보강 질문을 담당한다.
- 진단에는 `sourceRevision`, `criteriaVersion`, 생성일, 검토항목, 근거, 미확인 사항, 보강과제, 다음 행동을 저장한다.
- 첫 화면에서 장문의 사업계획을 작성하게 하지 않고, 자료 입력과 짧은 추가 질문으로 시작한다.
