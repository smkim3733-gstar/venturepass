# 4I18 — 캡처 이후 판정·정산/종료와 runtime owner 연결 명세

고정20개 기능 기준15/20=75%, 미완료5/20=25%, 직전 대비+0%p. 이번4I18은 캡처 이후 판정·정산/종료와 runtime owner 연결 계약 점검1건이며 제품 소스 변경0개다. 신규 제품 시험0/0(미실행), 기존 회귀 재실행0·새 HTTP/브라우저/lint/typecheck/빌드0회다. 과거4I17 신규39+기존234=273/273·제외6개·zzeTSv는 별도이며 재실행/합산하지 않는다. 백업27개 DESTINATION_REPOSITORY 제한은 미해결·이번 미실행이다. 실환경1/5=20%는 과거 사용자 직접 인증/접근이며 앱 자동실행 성공0단계·KOSIS 실제0/1이다. 필수 결정0개, 다음4I19 비교 사용량 정책·전송 binding4와 판정/정산종료 순수 계획3~6시간(잠정), 전체 완료시간 미정, 자동후속 ACTIVE.

이 문서는 **소스 대조로 확정한 후속 구현 계약**이다. 아래의 새 정책·전송 binding4·판정/정산종료 planner·SQL13/증인3·비교 runtime owner는 이번에 구현·시험하지 않았다. 현재 완료 코드의 마지막 저장 단계는 SQL12/증인2의 response-captured다. 공급된 자료의 구조적 정합성, 로컬 COMMIT 관측, 실제 가격/사람 동의/제공자 실행을 구분한다.

| 새 논리 작업 | 기존 표에 낼 행 | 금액·회사·동의 의미 |
|---|---|---|

비교 의견 기록은 응답 파싱/인용 실패 상태도 기존 native가 기대하는 정확한 artifact로 남긴다. 원래 strict response decoder와 validatePrepared를 공통으로 사용하고 응답/예산 parser를 재구현하지 않는다. 현재 회사로 원래 문맥을 대체하지 않는다. 현재 적용성 확인과 원고 채택은 다른 작업이다.

비교 결과가 comparison-ready라도 사용량이 없으면 정산할 수 없다. 반대로 refusal·불완전 응답·모델 별칭/인용 실패가 있어도 정책상 사용량이 정확하면 비용을 산정할 수 있다. 비교 decoder의 exact model과 비용 정책의 명시 모델 대응은 목적이 다르다.

최종 artifact는 기존 native4의 정확한 필드/순서로 만들며 cancelled:false, 원래 response hash/comparison state/assessment digest와 costSettled:true를 대조한다. source/currentContextVerified:false/dispatchAllowed:false/costAssessmentVerified:false를 그대로 둔다. 새 필드를 소급 추가하지 않는다.

## 3. 전송 전에 고정할 비교용 사용량 정책

현재 금액 근거의 최고 요금 × 전체 context + 출력16000은 **예약 상한**이다. 이 숫자를 실제 비용으로 쓰거나 legacy phase를 generation으로 꾸며 사용량을 계산하지 않는다. 새로운 정책은 기존 financialBasis의 요금을 참조하는 정규화·선택 규칙이며 별도 가격표/예산/승인 원장이 아니다.

비교 정책은 strict version1, kind `public-comparison-usage-policy`, purpose `compare-public-claim`로 다음을 묶는다.

| 입력 | 확정 계약 |
|---|---|
| 고정 요청/요금 신원 | 원래 financialBasisDigest·모델·request contract/identity digest·currency/unitScale·requestedTier:null·maxCalls1/retry0/output16000 |
| 응답 모델/등급 | 허용 response model과 service_tier의 명시 대응·근거. 모델 별칭은 문자열을 추정하지 않음. nullable requestedTier를 default로 채우지 않음. 응답 등급이 없거나 대응 밖이면 unknown |
| 생략 옵션 | service_tier/truncation/background/stream의 생략 의미와 모든 허용 응답 등급이 기존 금융/전송 근거의 all-in 요금 범위에 포함됨. 근거 없는 추가 요금/조건은 blocked |
| input 분할 | 적용 요금이 정확한 유리수로 동일한 equal-rates 방식 또는 명시 disjoint cache 방식. aggregate input 안에 read/write가 포함됨을 고정. cache field path 또는 근거 있는 not-applicable을 사용 |
| 구간 선택 | 근거 있는 short-only 또는 정확한 input threshold. 기존 short/long 요금 참조이며 예약 때보다 유리한 요금을 임의 선택하지 않음 |
| output | output 전체에 reasoning 포함. reasoning을 별도 재가산하지 않음 |
| 근거 | 출처 ID/URL/발췌·record/excerpt digest, 조회/검토/만료 시각과 근거 설명. financial/transmission source와 참조 연결. official-reviewed도 supplied 표식이며 진위 인증이 아님 |
| 형식/한도 | 원래 plain JSON strict 검사, 정책 canonical JSON 최대32KiB. 정책 포함 review/binding 각각64KiB, 전체256MiB 한도도 별도 적용. raw JSON overhead를 빠뜨리지 않음 |

캐시 분할은 기존 안전한 field path·prototype 금지·중복/겹침 금지·합계 검사와 같다. 선택하는 모든 응답 등급에 같은 기존 요금 해석이 유효하다는 근거가 있어야 한다. 다른 가격표가 필요하면 원래 미전송 예약을 취소한 뒤 새 근거/예약을 검토해야 한다. 이미 전송한 예약의 financialBasis/retention/만료 bytes는 수정하지 않는다.

다음 구현은 기존 usage 모듈의 **숫자 해독·정규화·유리수 비교·ceilRate 계산**을 좁은 내부 공통 함수로 추출/재사용한다. legacy public schema/phase/default 의미와 응답/정책 bytes는 동일하게 유지한다. 비교 wrapper는 비교 목적/null 등급의 명시 입력만 받는다. 단순 type cast, 호출자 supplied 결과 금액, 별도 복제 산술은 금지한다.

### 전송 binding 버전

| 기존/새 형식 | 읽기와 새 계획 |
|---|---|
| legacy transmission1/2 | 기존 decoder/과거 bytes 보존. 비교 정책을 부착하지 않음 |
| 비교 transmission3 + review1/command1 | 원래 재조회·unknown/capture·비교 의견 계획 보존. 이미 dispatch된3에 정책을 사후 부착하지 않으며 새 정책 기반8행 정산은 blocked |
| **비교 transmission4 + review2/command2** | 같은 기존 transmission 표의 새 discriminator. 원래 검토안의 모든 신원/head/문구/기한에 usage policy+digest를 포함. 동의 명령은 정확한 policy digest와 review digest를 함께 대조. 기존 dispatch event/receipt와 binding의3행 구조 유지 |
| reservation binding3 / native4 / request1 | 버전·bytes 그대로. 미전송 예약에만 원래 근거가 유효한 동안 새 review2를 만들 수 있음 |

검토안2의 만료는 원래 검토+10분·예약/financial/transmission/usage policy 근거의 가장 이른 만료 중 최솟값이다. 승인 이후 근거를 바꾸면 다른 명령이다. 정책 digest를 자기 dispatch event hash에 의존시키지 않아 순환 hash를 만들지 않는다. 전송 binding4는 전체 정책/명령/검토안과 dispatch 영수증을 감사하며 정책 신원만 보고 허용하지 않는다.

unknown/capture 명령의 기존 필드는 transBindingDigest로 원래3 또는4를 가리킨다. 다음 전체 감사에서 명시적3/4 union으로 처리하되 기존3 digest 입력/decoder를 바꾸지 않는다. 기존 상태 wrapper/digest도 버전 분기를 통해 과거 신원을 그대로 유지한다.

## 4. 사용량 판정·가격 만료·초과 처리

1. 전체 prefix/native/reservation/transmission/정책 감사를 먼저 한다. 정책은 **원래 dispatch 승인/기록 시각**에 유효해야 하며 현재 시각으로 만료를 연장하거나 원래 승인 때 이미 만료된 정책을 허용하지 않는다.
2. 원래 response artifact의 canonical bytes만 기존 capture/metadata 규칙으로 해독한다. 새 공급 응답·누락 값 보충·현재 모델 기본값을 받지 않는다.
3. input/output/total은 모두 명시한 안전한 정수여야 하고 합계가 맞아야 한다. 기존0..1e9 범위·cache/reasoning의 유효한 값/aggregate 상한·분할 중복 검사도 적용한다.
4. 정책이 정한 구간과 cache partition만 사용한다. 적용 동일 요금일 때만 equal-rates 계산이 가능하다. 필요한 캐시 count가 없으면 unknown이며 미사용0을 추정하지 않는다.
5. category별 양의 유리수 요금 × count를 기존 BigInt ceil 산술로 올려 합산한다. output에는 reasoning이 이미 포함되므로 한 번만 센다. 금융 근거의 단위와 출력 units(최대30자리) 범위를 유지한다.
6. 정책/모델/등급/합계가 불명하면8행 없음. 실제 명시0이 모든 검사를 통과한 경우만 known0이다. API실패/사용량 누락/refusal을0으로 변환하지 않는다.
7. 계산 가능한 context/output/reservation 초과는 금액을 자르는 사유가 아니다. 위반 목록과 확인 가능한 전체 비용을 보존한다. 적용 구간을 알 수 없거나 비용 자체를 계산할 수 없으면 unknown이다.

비용C·현재 원래 holdH에 대해 consumed=min(C,H), released=max(H-C,0), excess=max(C-H,0). budget의 기존 recognize-comparison-usage와 그 fold만 사용한다. 같은 scope의 전체 recognized는C만큼 증가하고 해당 hold는0이 된다. cap/예약 초과·위반은 boundBreached/deficit 등 기존 거절을 유지하여 새 실행을 막는다. 다른 DB/scope의 금액을 합치거나 cap을 올리지 않는다.

현재 가격/동의가 만료됐어도 원래 전송 때 유효했던 고정 정책과 저장된 캡처로 계산·기록할 수 있다. 이것은 새로운 실행 승인이나 지금 가격의 유효성 확인이 아니다. binding3·누락 정책은 사후 정책을 받지 않는다. 청구서/교정 사용량을 받아 기존 캡처를 덮어쓰는 경로와 수동 hold 해제는 이번 계약에 없다.

## 5. strict 명령·nonce·행 연결

새 명령 이름/입력은 아래로 고정한다. UUID/hash/head는 기존 validator를 사용하고 명령 canonical bytes8KiB 이하를 유지한다. 시각·새 event/artifact ID·내부 nonce는 planner의 새 기록 입력이며 사용자 명령 필드와 혼동하지 않는다. caller가 결과 JSON·금액·final artifact를 임의로 선택하지 못한다.

| 명령 | 전체 대조 필드 |
|---|---|
| `record-public-comparison-result` commandVersion1 | purpose, clientRequestId, runId, transmissionBindingDigest, dispatchEventDigest, responseArtifactSha256, responseArtifactByteLength, expectedRunHead, expectedValidatedArtifactSha256 |
| `settle-finalize-public-comparison` commandVersion1 | purpose, clientRequestId, runId, transmissionBindingDigest, dispatchEventDigest, responseArtifactSha256, comparisonEventDigest, usagePolicyDigest, expectedAssessmentDigest, expectedRunHead, expectedBudgetHead |

result 명령의 expectedValidatedArtifactSha256는 기존 decoder/원래 context로 미리 계산한 값이며 저장 body는 같은 함수로 재생성하여 대조한다. close의 expectedAssessmentDigest도 고정 정책/응답에서 계산한 native assessment digest다. 이것은 사용자가 입력한 금액을 승인하는 기능이 아니다.

result nonce는 comparison-recorded 영수증의 nonce다. close 사용자 nonce는 **cost-settled 영수증 및 그 금액 투영**의 nonce다. usage/final receipt의 내부 nonce는 새 ID와 함께 입력 받아 전역 충돌을 검사하고 같은 연속8행에만 포함한다. 추가 승인 소유자나 별도 budget receipt SQL 행을 만들지 않는다.

close expectedRunHead는 usage-assessed 직전 head다. usage→cost→final event는 같은 run에서 연속 revision이며 각 previousDigest가 바로 앞 event와 같아야 한다. 이 세 event/영수증은 한 계획의 같은 recordedAt을 사용하고 금액 event/비용 receipt 시각도 일치시킨다. 원래 comparisonEvent와 response/binding/policy, usage 직전 head·금액 이전 head, cost receipt nonce에서 전체 close 명령을 다시 구성한다. 내부 receipt nonce/IDs·assessment/final bytes도 원래8행 그대로 조회한다.

새 commandDigest와 기존 nativeInputDigest는 같다고 가정하지 않는다. native4는 그 원래 inputDigest 규칙을 그대로 쓴다. 새 별도 command/nonce 표 없이 재구성한 strict 명령의 **전체 값**을 요청과 대조한다. 내부 nonce로 온 요청은 원래 close 명령의 replay 권한을 얻지 못한다. 비용 receipt가 없거나 usage/cost만 있는 상태는 새 close 완료가 아니다.

모든 planner는 전체 감사 후 동일 nonce를 **현재 회사/시계/새 근거/새 ID 검사보다 먼저** 조회한다. 정확한 replay는 원래 행/명령만 반환하며 rows:null, owner:null이다. 서로 다른 명령·목적·본문·head의 같은 nonce, binding 없는 점유 nonce, 내부/legacy nonce 충돌은 거절한다. 손상된 전체 원장의 nonce 한 건만 읽어 성공으로 표시하지 않는다.

신규 close는 비교 의견이 있고 아직 usage/cost/final이 없는 상태에서만 가능하다. 기존 native parser가 읽는 유효한 과거 partial 사용량/정산은 read-only supplied 상태로 남기되 새8행으로 이어 붙이거나 재해시하지 않는다. 새 binding4/postcapture planner 감사는 자신이 생성한 연속 그룹의 완결성을 추가로 요구한다. 과거 decoder 의미는 유지한다.

## 6. SQL/증인 후속 연결 경계 — 이번 미구현

4I19는 위 순수 계획/정책 감사까지만 구현한다. 이후 기존 저장기와 증인을 다음 **하나의 통합 저장 단계**에서 확장한다. 이미 검증한 SQL/파일 helper를 새 helper로 계속 분할하지 않는다.

- 명시 SQL12→13, 증인2→3. 기본 생성자/SQL12 gate/증인2 decoder를 자동 승격하지 않는다. 새 표/병렬 승인·금액 원장은 없다. native4와 coverage target10·원래 prefix/JSON/BLOB bytes 및 legacy 전송1/2/비교3를 보존한다.
- 전환은 같은 root/DB/두 증인 경로의 완전 일치·pending 없음·전체 감사 상태에서만 한다. 기존 dispatch/capture가 있어도 과거 행을 그대로 읽을 수 있으나 binding3의 정책/실행 권한을 추가하지 않는다.
- 기존 증인2 파일 prefix 뒤 transition intent 두 사본→정확한 DDL COMMIT→원문/schema 재대조→transition ack를 덧붙인다. COMMIT 반환 유실/부분 사본은 원래 intent·DB/영수증 대조만 하며 새 경로 결합/이력 재생성을 하지 않는다.
- private writer의 같은 BEGIN IMMEDIATE 안에서 exact table/SQL values/body/hash/BLOB bytes/행 순서·횟수를 허용한다. 새 result3행·close8행을 기존 reserve/cancel/dispatch/unknown/capture와 같은 거래 엔진에 결합하고 gate 종료 뒤 전체 사후 감사·전체 명령 재구성까지 맞아야 COMMIT한다.
- 새 reserve/dispatch만 필요한 회사 SELECT 잠금을 유지한다. 캡처 이후 result/close는 회사·현재 키·현재 가격을 읽지 않는다. 원래 정책을 현재 공급 정책으로 바꾸는 callback도 없다.
- intent에는 원래 nonce/전체 command digest·before/after checkpoint·원래 receipt와 exact3/8행 digest를 남긴다. 새 가격/동의/회사 원문은 증인에 복사하지 않는다.
- 128기록/4MiB/record32KiB 유지. 같은 원장의 미완료 run 최악 경로 자리까지 새 예약/전송 전에 예약한다. 기존8종 event 기준의 보수적 잔여 계산을 근거 없이 줄이지 않는다. close는3event라도 하나의 intent/ack 쌍이며 행 수8을 별도 대조한다.
- intent 뒤 DB없음·ack 뒤 DB되돌림·부분8행·다른 영수증·남은 lease는 새 쓰기 차단. 정확한 DB3/8행이 있으면 ack 파일만 복구한다. 행 재삽입/hold 재생성·PID/시간 기반 lease 삭제는 없다.
- 금액 settle만으로 저장 예약을 해제하지 않는다. 마지막 final artifact/event/receipt와 전체 native 감사가 성공해야32MiB 잔여 저장 예약을 푼다. final 보관 공간이 없으면8행 전부 계획/저장 거절.

SQL/증인 COMMIT 관측이 별도 프로세스 전원차단 전체 복구나 제공자 실행 성공을 증명하지 않는다. 일반 v10/v11/v12 backup/restore 미지원과 알려진27개 경로 제한은 별도 미완료다.
