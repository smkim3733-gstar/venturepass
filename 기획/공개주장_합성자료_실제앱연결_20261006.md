## 1. 실제 화면과 사용자 동선

실제 AppShell의 다른 메뉴에서 **공개 근거 검토 예제**를 연다. 경로는 `/studio/review-example`이다. 서버 페이지는 고정 fixture의 회사/원래 선택·주장·발췌만 전달하며 결과는 명시 POST 이후에 표시한다.

1. 합성 예제 시작: 현재 root의 보관자/screen을 최초1회 생성한다. HTTP0.
2. 검토 결과 읽기: 현재 화면을 대조하고 원래 handle을 보관한 뒤 기존 start를 실행한다.
3. 표시 비우기: fresh canForget을 재확인하는 기존 release. 새 HTTP0.
4. 스튜디오 이동/복귀: 동일 root 보관자를 유지하고 표시를 새 화면에 자동 복원하지 않는다. 새 명시 읽기가 필요하다.
5. 예제 종료: 기존 screen.close의 최종 통지로 DOM을 비우고 이후 새 읽기/새 보관자를 거절한다. 같은 창의 화면 이동으로 종료를 우회하지 않는다.

예제는 고객 회사 목록에 등록하지 않는다. 새로고침·root 종료 후 원래 I/O 보관은 지원하지 않는다. 운영 데이터가 아닌 고정 합성 비교 결과이며 실제 사실 확인·채택·전송 동의는 모두 미완료다.
