구독의 등록 객체에 active를 둔다. 새 구독은 직전 등록을 retire하고 반환된 unsubscribe는 그 등록만 retire한다. close 뒤에 남은 마지막 통지 대상도 자기 unsubscribe로 취소할 수 있다. 옛 unsubscribe가 현재 등록의 통지를 취소하지 않는다.

안정된 닫힘 snapshot을 게시하고 기존 microtask에서 terminal을 먼저 소비한 다음 listener를 최대1회 호출한다. listener 중 close/throw에도 재귀·자동 재시도·무한 통지가 없다. 구독 없음/자기 unsubscribe/unmount이면 마지막 callback0이다. 최종 통지 뒤 등록은 해제되며 원래 I/O의 내부 관측은 계속된다.

현재 표시를 비우는 React commit과 close 반환은 다르다. 정상 통지 뒤 실제 개발 React에서 display:null·NOT_ATTACHED·canPrepare:false를 확인했다. callback 취소/실패·이미 unmount한 화면은 이 통지로 다시 장착하지 않는다. 실제 상위 호출자의 명시 UI 제거와 원래 I/O 강한 참조 책임은 여전히 필요하다.

## 6. 남은 범위 결정1개와 후속 일시 정지

현재 heartbeat는 `실제 상위 운영 보관자/service 취득·앱 root/route/UI/HTTP ... 0`을 요구한다. 또한 `승인 범위를 마치거나 필수 외부 결정으로 독립 개발이 불가할 때 ... PAUSED로 전환`하도록 지시했다. 이번에 확정된 격리 보완·관련 검증을 완료했으므로 다음 실제 앱 연결은 범위 확대 승인을 기다린다.

**결정1개: 합성 자료를 사용한 실제 앱의 상위 보관자·명시 읽기·화면 연결 개발까지 진행할지.**

승인 시 검토할 구체적 연결 대상은 다음과 같다.

| 대상 | 이어야 할 기존 경계 | 현재 상태 |
| --- | --- | --- |
| 상위 보관/고정 주입 | 회사/화면 공통 슬롯1·이미 보관한 screen·StrictMode 자기 cleanup | Providers는 후보 위치이며 실제 취득 경로 없음 |
| 명시 읽기 | 원래 service/선택을 고정한 기존 handler·현재 회사/요청 대조 | handler는 격리 부품이며 endpoint 없음 |
| 현재 표시/종료 | 기존 hook·순수 snapshot/현재 props·이번 마지막 통지 | 합성 장착만 검증, 기존 화면에는 미설치 |
| 원래 I/O/서버 복구 | 외부 강한 참조·동일 entry fresh canForget·같은 service의 원래 명령 복구 | 각 부품 계약은 있으나 운영 취득/인계 연결 미완료 |

승인 후 처음1~3시간(잠정)은 실제 소유/주입·원래 service 취득 경로와 합성 검증 경계를 확정한다. 실제 앱 연결 구현시간과 전체 완료시간은 그 점검 전 확정할 수 없다. 이 제안은 고객자료/운영 DB 변경·실제 로그인/신청/제출·납부/서명·유료 AI·키/공식 가격/외부 전송 승인을 포함하지 않는다.

자동후속은 **PAUSED**다. 승인이 없는 heartbeat 재도착은 범위 확대 근거가 아니다. 완료한 합성 시험·빌드·백업 제한을 다시 실행하지 않으며 새 registry/session/owner/store·자동 조회·실제 앱 설치를 추가하지 않는다. 보호 변경은 계속 보존한다.

이번에 승인된 종료 통지·표시 해제의 격리 구현/검증은 완료했다. 현재 지시가 실제 앱 root/route/UI 설치와 상위 운영 보관자/service 취득을 제외하므로 후속 실제 앱 연결을 시작하지 않고 자동후속 PAUSED로 전환한다. 필요한 결정은1개다: 합성 자료를 사용해 실제 앱의 상위 보관자·명시 읽기·화면 연결 개발까지 범위를 확대할지. 승인되면 기존 SQL13 service·원래 선택 취득·강한 참조 수명과 실제 주입/endpoint의 연결 범위를 먼저1~3시간(잠정) 점검하고 구체적 구현 범위를 정한다. 실제 고객자료/운영 DB 변경·로그인/신청/최종 제출·납부/서명·유료 AI·키/공식 가격/외부 전송은 이 제안에 포함하지 않는다. 승인 전 새 보관자/registry/session/owner/store·route/UI 설치·자동 재조회/실제 계정 polling을 추가하거나 완료 시험·빌드·백업27개를 반복하지 않는다. 실제 앱 연결의 구현시간과 전체 완료시간은 미정이다.
