# 벤처패스 v2 — 3단계 자동 진행 서비스 기획안

후속 최종 기획: [벤처패스 최종 서비스 기획안 v3](./벤처패스_최종서비스기획안_v3.md). AI 사업계획서 품질을 핵심으로 한 제품 정의와 사용자가 선택한 밝은 남색·금색 디자인, 최신 개발 우선순위는 v3를 기준으로 한다. 이 문서는 이전 기획 이력으로 보존한다.

작성일: 2026-09-26  
상태: 사용자 요구를 반영한 재기획안. 아래 목표 기능의 구현·기관 연동 완료를 의미하지 않는다.  
대상: 혁신성장유형 벤처확인을 처음 준비하는 기업 대표와 실무 담당자.  
문서 관계: 기존 서비스 기획과 상세 기능 정의는 보존한다. 이 문서는 일반 사용자의 기본 동선, 자동 진행 원칙, 개발 우선순위를 새로 제안한다.

## 1. 기획 판단

현재 앱에는 자료·원고·근거·기관 기록을 관리하는 기능이 많이 들어 있다. 그러나 신청자가 판독, 본문 채택, 아이템 선택, 원고 버전, 검토 상태, 벤처인 연결을 각각 이해하고 실행해야 한다. 기능을 갖추는 과정에서 전문가가 쓰는 작업대에 가까워졌다.

제품의 중심을 **“우리 회사 자료를 주면 AI가 신청서를 준비하고, 필요한 확인만 받아 접수와 후속 절차를 이어 주는 서비스”**로 바꾼다. 사용자가 다음 작업을 고르는 부담을 앱이 맡는다.

메뉴를 7개에서 3개로 줄이는 것만으로는 충분하지 않다. 사용자가 누르던 정상 처리 버튼은 앱의 연속 작업으로 바꾸고, 판단이 필요한 질문과 외부 실행 승인은 필요한 순간에만 보여 준다. 회사의 사실을 확인하는 일과 기관의 심사는 없어지지 않지만, 그 일을 하기 위해 앱의 내부 구조까지 배울 필요는 없게 만든다.

제품이 지향하는 고객 성과는 벤처확인 획득이다. 제품이 책임질 범위는 신청 준비, 제출 결과 확인, 보완 대응, 실사 준비, 결과와 확인서 보관까지 절차가 끊기지 않도록 돕는 것이다. 기관의 확인 결정을 보장하는 문구는 사용하지 않는다.

**대표 문구 제안:** “회사 자료를 올리세요. AI가 신청서를 준비하고, 접수부터 보완까지 함께 진행합니다.” 실제 제공·검증된 단계에 맞춰 출시 문구의 범위를 조정한다.

## 2. 사용자가 기억할 전체 흐름

| 단계 | 사용자에게 보이는 이름 | 사용자가 하는 일 | 앱이 이어서 하는 일 |
|---|---|---|---|
| 1 | 회사 자료 넣기 | 가입, 보유자료 업로드, 중요한 정보 확인 | 자료 읽기·분류, 회사 정보 채우기, 부족·불일치 확인 |
| 2 | AI 신청서 만들기 | 추천 신청 주제 확인, 모르는 사실에 답변, 제출본 검토 | 신청 아이템 도출, 사업계획서 작성, 수치·근거 점검, 온라인 입력값·첨부 준비 |
| 3 | 접수하고 진행하기 | 공식 인증, 필요한 동의·제출 승인·납부, 보완 답변·실사 참여 | 허용된 입력·첨부·저장·제출, 공식 결과 확인, 보완안 준비, 일정·확인서 관리 |

3단계는 사용자가 기억하는 업무 구분이다. 화면을 정확히 세 장으로 제한하거나 세 번의 클릭만으로 모든 기업의 신청이 끝난다고 약속하지 않는다. 재방문하면 마지막 메뉴 대신 **지금 필요한 일**을 먼저 보여 준다.

가입은 최초 1회 처리하고, 벤처인 인증은 공식 사이트 연결이 필요한 3단계에서 요청한다. 사용자의 첫 경험을 두 사이트의 가입·인증부터 시작하게 만들지 않는다.

## 3. 단순하게 만드는 화면 원칙

1. 기본 화면은 **현재 상태, 지금 필요한 일, 주 실행 버튼 한 개**로 구성한다. 이미 끝난 일과 다음 순서는 접어 둔다.
2. 자료만으로 알 수 있는 내용을 다시 타이핑하게 하지 않는다. 이전에 확인한 사실은 관련 자료가 바뀌지 않으면 다시 묻지 않는다.
3. 질문은 중요한 순서대로 한 묶음에 최대 3개만 보여 준다. 전체 필수 질문을 숨기지 않고 남은 수를 표시한다.
4. 파일을 올린 뒤 분류·판독·분석·원고 작성마다 별도의 실행 버튼을 요구하지 않는다. 허용된 처리 범위에서 자동으로 이어 간다.
5. 모든 문장을 개별 승인시키지 않는다. 금액·기간·권리·완료 여부·자료 충돌 등 실제 확인이 필요한 쟁점을 묶고, 마지막에 제출본을 검토한다.
6. 출처는 언제든 펼쳐 볼 수 있게 한다. 자동으로 읽은 값, 사용자가 확인한 사실, 아직 확인하지 않은 사실은 내부적으로 구분해 보존한다.
7. 처리 중에는 실제 상태와 마지막 저장 시점을 표시한다. 측정하지 않은 완료율이나 남은 시간을 만들어 보여 주지 않는다.
8. 뒤로 가기와 나중에 이어 하기를 제공한다. 예기치 않은 오류가 나면 마지막으로 확인한 지점에서 복구한다.
9. 일반 사용자에게 API 키, 판독 엔진, 해시, revision, 실행 대응표, 규칙 점검 같은 구현 용어를 노출하지 않는다.
10. 자세한 자료 관리·버전 비교·검토 기록은 같은 데이터의 ‘자세히 보기’ 또는 권한 있는 담당자의 전문가 화면에 둔다. 화면을 숨기는 것이 권한 통제를 대신하지는 않는다.

### 기본 화면의 예

> **AI 신청서를 준비하고 있습니다.**  
> 회사 자료 5개를 읽었습니다. 매출 기준연도만 확인하면 작성을 이어갈 수 있습니다.  
> **[매출 기준연도 확인하기]**  
> 마지막 저장: 오늘 14:20 · 자세히 보기

이 예시는 화면 문구이며 실제 회사의 상태나 처리 성과가 아니다.

## 4. 1단계 — 가입하고 회사 자료 넣기

### 4.1 가입과 회사 연결

초기 출시안은 이메일 인증으로 시작하는 단일 가입 경로를 권장한다. 소셜 로그인은 후속 선택지로 둔다. 벤처패스 회원과 벤처인 계정은 별개라는 설명은 공식 사이트 연결 시 짧게 안내한다.

최소 입력은 계정 인증과 담당 역할이다. 사업자등록증을 올리면 회사명·사업자번호 등 읽을 수 있는 정보를 채워 준다. 서류가 없는 사용자는 회사명부터 직접 입력해 시작할 수 있다. 사업자번호를 알고 있다는 이유만으로 기존 회사 자료에 접근시키지 않으며, 회사 소유자 확인·초대·역할에 따른 접근 통제가 필요하다.

### 4.2 첫 화면

- 제목: **“가지고 계신 회사 자료부터 올려 주세요.”**
- 설명: “사업자등록증, 회사소개서, 재무자료, 제품설명서가 있으면 함께 넣어 주세요. 부족한 자료는 확인 후 알려드립니다.”
- 주 실행: **[자료 올리기]**
- 보조 경로: **[자료 없이 회사 설명부터 시작]**

처음부터 모든 기업에 동일한 서류 목록을 강제하지 않는다. 파일명이나 형식을 사용자가 정리할 필요 없이 여러 파일을 한 번에 넣게 한다. 지원하지 않는 형식은 해당 파일 옆에서 변환·대체 방법을 안내한다. 모든 파일을 다시 올리게 하지 않는다.

### 4.3 자동으로 처리할 범위

업로드 저장 → 형식 확인 → 문서·표·이미지 읽기 → 자료 종류 추정 → 기업별 사실 정리 → 중복·충돌 탐지 → 필요한 질문 선별까지 연결한다. 파일명과 추출문은 신뢰할 수 없는 입력으로 다루며, 문서 안의 지시문이 앱 동작이나 자료 전송 범위를 바꾸지 못하게 한다.

외부 AI에 자료를 보낼 때는 최초 처리 시 대상 서비스, 보낼 자료 범위, 목적과 보관 조건을 이해할 수 있게 안내하고 허용을 받는다. 동일 기업·동일 목적·동일 범위의 처리마다 같은 확인창을 반복하지 않는다. 새 자료의 범위나 외부 제공자가 바뀌면 필요한 내용을 다시 확인한다.

### 4.4 사용자에게 물어볼 일

사업자번호처럼 식별에 중요한 값, 기간·단위가 충돌하는 금액, 현재 개발 상태, 자료만으로 알 수 없는 사실을 질문한다. 전체 판독문을 일괄 읽고 채택하는 작업을 일반 사용자의 필수 통과 화면으로 두지 않는다. 자동 판독문을 사람이 검토했다고 기록하는 것도 금지한다.

예를 들어 손익계산서가 없으면 매출과 이익을 추정하지 않는다. 작성 가능한 기술·고객 설명은 계속 준비하고, 재무 항목에는 필요한 자료와 해결 방법을 남긴다. ‘나중에 제출’은 작성 계속을 허용하는 선택이며, 필수 제출서류의 부족을 해소한 상태로 바꾸지 않는다.

**완료 조건:** 회사를 구분할 정보와 초기 신청 주제를 검토할 자료가 확보되면 2단계를 시작한다. 나머지 자료 요청 때문에 모든 준비를 멈추지 않는다.

## 5. 2단계 — AI가 아이디어와 접수용 사업계획서 준비

### 5.1 아이디어 도출의 의미

AI가 기업의 실제 제품·개발내용·고객 문제를 읽고 **신청서에서 설명할 사업 주제**를 정리한다. 기본 화면에는 가장 근거가 있는 추천안 1개와 짧은 이유를 보여 준다. 적절한 대안이 있는 경우에만 펼쳐 볼 수 있게 한다.

추천안은 자동으로 준비하되 신청 주제를 사용자의 검토 없이 확정하지 않는다. “우리 회사가 실제로 하는 일과 맞나요?”라는 질문으로 확인한다. 아직 개발하지 않은 아이디어는 ‘앞으로의 계획’으로 분리하고, 현재 보유 기술·완료 실적처럼 원고에 넣지 않는다. 새로운 아이디어만 만들어 혁신성을 증명한 것으로 처리하지 않는다.

### 5.2 신청서를 준비하는 내부 순서

1. 확인된 공식 서식 버전의 신청 항목·분량·첨부 조건을 기준으로 준비한다. 로그인 후에만 알 수 있는 회사별 조건은 3단계 연결 직후 다시 대조한다.
2. 회사별 사실과 증빙을 정리하고 신청 주제를 추천한다.
3. 확인된 범위에서 사업계획서 각 항목을 서술형으로 작성한다.
4. 별도 검토 과정으로 수치·기간·단위·인용, 현재 사실과 미래 계획, 항목 간 모순을 확인한다.
5. 부족한 사실은 중요도순 질문으로 묶는다. 답변 또는 자료가 들어오면 관련 부분만 수정한다.
6. 사용자가 최종 내용을 확인하면 온라인 신청 항목별 입력값, 첨부 목록, 검토용 통합본을 하나의 제출본으로 고정한다.

작성과 검토가 모두 AI라고 해도 사실 검증이 자동으로 완료되는 것은 아니다. 문장의 근거와 사용자의 확인 기록을 보존한다. AI를 이용할 수 없는 경우 자료 정리만 수행했다는 상태를 표시하며, AI 접수용 원고가 완성됐다고 표시하지 않는다.

### 5.3 사용자 화면

처음에는 신청 주제, 고객 문제, 해결 기술, 차별성의 근거, 현재 성과와 향후 계획을 한 장 요약으로 보여 준다. 전문과 근거는 펼쳐 볼 수 있게 한다. 직접 원고를 수정할 수 있지만, 항목 열 개를 모두 편집하는 작업을 기본 사용법으로 요구하지 않는다.

- 사실이 부족하면: **[질문에 답하기]**
- 자료가 충분하고 원고가 준비되면: **[신청 내용 확인]**
- 확인 결과 준비가 끝났으면: **[벤처인 신청 준비]**

위 버튼은 상태에 따라 한 개씩 나타난다. 사용자가 세 버튼을 정해진 순서대로 매번 눌러야 한다는 뜻이 아니다.

### 5.4 ‘접수용 작성 완료’ 기준

- 확인된 공식 서식 버전의 필수 입력 항목에 맞는 값과 글자 수가 준비돼 있다. 실제 연결 전에는 ‘신청서 준비 완료’로 표시하며, 회사별 화면 대조까지 마쳐야 ‘제출 준비 완료’로 표시한다.
- 필요한 첨부자료의 기업·기간·내용을 확인할 수 있고, 누락은 해결됐거나 공식적으로 적용되지 않는 이유가 기록돼 있다.
- 중요 수치와 권리·실적 주장이 근거와 연결되며, 제출을 막는 충돌이 남아 있지 않다.
- 자료가 없는 내용을 AI가 사실처럼 채우지 않았다.
- 사용자가 제출할 내용과 파일을 확인했고, 그 뒤 내용이 바뀌면 필요한 확인을 다시 받는다.

혁신성장유형 안내에는 사업계획서의 온라인 작성이 명시돼 있다. 따라서 완성 파일 하나만 만드는 것으로 끝내지 않고, **온라인 항목별 원고와 첨부자료까지** 준비해야 한다. [공식 유형별 안내](https://www.smes.go.kr/venturein/institution/requireGuide?rgCd=C)

## 6. 3단계 — 벤처인 자동 작성·등록과 후속 진행

### 6.1 목표 경험

**벤처인 연결 → 사용자 공식 인증 → 준비한 내용으로 입력·첨부·저장 → 최종 신청 확인 → 승인한 제출 실행 → 공식 처리 결과 확인**을 같은 진행 화면에서 이어 준다.

로그인 직후 회사별 실제 입력 항목·분량·첨부 조건을 준비한 서식 버전과 대조한다. 차이가 없으면 추가 확인 없이 이어 간다. 차이가 있으면 앱이 필요한 부분을 보완하고, 제출 내용이나 승인 범위가 실질적으로 달라지는 경우에만 사용자에게 확인받는다. 2단계 원고 준비를 시작하기 위해 공식 로그인을 미리 요구하지 않는다.

사용자에게 신청서 문장을 다시 복사하고 파일마다 경로를 찾게 하는 일을 줄이는 것이 목표다. 정상적인 반복 입력과 다음 화면 이동은 앱이 수행한다. 인증·동의·비용·최종 제출에 사람의 확인이 필요한 순간에만 해당 작업을 보여 준다.

### 6.2 아이디·비밀번호만으로 끝내는 방식에 대한 판단

개발 목표는 로그인 이후의 반복 작업을 최대한 자동화하는 것이다. 다만 현재 근거로 ‘아이디·비밀번호만 입력하면 모든 계정에서 무인 접수 완료’라고 약속할 수는 없다. 공개 공지에는 로그인 2차 인증 관련 안내가 있으며, 약관에는 계정의 제3자 이용 제한이 있다. 제3자 앱용 신청 API와 자동화 허용 범위는 이번 공개자료 조사에서 확인되지 않았다. 이것이 API 부재나 모든 자동입력의 금지를 입증하는 것은 아니다. [공식 공지사항](https://www.smes.go.kr/venturein/board/viewNotiBoardList), [이용약관 제20조](https://www.smes.go.kr/venturein/cmmn/terms)

따라서 **사용자의 기기에서 공식 로그인·본인인증을 완료하고, 허용·검증된 연동 방식으로 입력과 첨부를 이어 가는 구조**를 우선 검토한다. 기관이 공식 API 또는 위임 연계 방식을 제공하면 이를 우선한다. 사용자 기기에서 실행한다고 약관 검토가 불필요해지는 것은 아니다. 상용 연동을 출시하기 전에 허용 범위와 계정 이용 방식부터 확인한다.

자격정보를 AI 프롬프트·원고·분석 로그에 넣지 않는다. SaaS 서버에 벤처인 비밀번호를 모아 보관하는 방식을 기본안으로 삼지 않는다. 일반 고객에게 원격 디버깅 포트나 브라우저 실행 옵션을 설정하게 하지 않으며, 연동에 별도 설치가 필요하면 이것도 실제 사용성 검증 대상에 포함한다.

### 6.3 자동 실행과 사용자 확인

| 작업 | 목표 동작 | 사용자에게 요청할 일 |
|---|---|---|
| 공식 로그인·추가 인증 | 공식 인증 화면을 정확히 안내하고 인증 상태를 확인 | 로그인, 추가 인증, 필요한 권한 선택 |
| 회사·유형 대조 | 대상 회사와 혁신성장유형이 맞는지 확인 | 정보가 다른 경우에만 정정 |
| 신청서 입력·파일 첨부 | 허용된 항목을 연속 입력하고 업로드 결과 확인 | 실행 전 정확한 대상·자료 범위 확인 |
| 임시저장·다음 화면 | 기관이 허용하고 검증된 버튼을 순서대로 실행 | 정상 흐름에서는 추가 클릭 요구 없음 |
| 최종 신청 | 제출할 회사·원고·첨부·필요한 동의를 한 화면에 제시 | 해당 신청의 최종 제출 명시 승인 |
| 수수료 | 기관이 안내한 금액·기한·납부 경로 표시 | 공식 결제 절차에서 직접 납부 |
| 제출·납부 결과 | 기관의 실제 상태·접수 식별정보와 증빙 확인 | 결과를 읽을 수 없으면 해당 화면 확인 |
| 보완 | 요청별 필요한 자료와 답변 초안 자동 준비 | 새로운 사실·자료 제공, 수정 제출본 승인 |
| 실사 | 현재 원고·증빙에 맞는 질문과 설명자료 준비 | 현장 준비, 실제 내용 설명과 조사 참여 |
| 결과·확인서 | 공식 결과와 확인서의 기업·발급일·유효기간 보관 | 자동 확인이 어려운 경우 원문 제공 |

이는 제품의 실행·승인 설계안이며 모든 항목이 현재 구현됐거나 기관이 특정 승인 UI를 법적으로 요구한다는 뜻은 아니다. 법적 동의의 구체 내용은 실제 문서를 보여 주고 해당 시점에 확인한다. 재무 거래는 사용자가 공식 결제 화면에서 직접 처리한다.

입력·첨부 허용과 최종 제출 승인을 구분하되, 중간의 조회·분류·화면 이동·진행 확인마다 승인창을 만들지 않는다. 동일 제출본으로 승인한 범위는 유지하고, 제출본 변경·회사 변경·새 보완 제출처럼 실질적인 내용이 달라지면 다시 확인한다.

### 6.4 공식 결과에 맞는 상태 표시

기본 화면의 큰 단계는 계속 ‘접수하고 진행하기’로 유지한다. 그 안에서 현재 상태를 한 줄로 보여 준다.

`신청 준비 → 제출 내용 확인 → 신청서 제출됨 → 서류 확인 중 / 납부 필요 → 접수 완료 → 평가·심의 중 → 확인 결과 도착 → 확인서 보관`

보완 요청은 접수 전과 평가 중 모두 발생할 수 있으므로, 해당 단계에 붙는 할 일로 관리한다. 보완이 끝났다는 이유로 납부·실사·심의를 완료 처리하지 않는다. 반려·철회·미확인 결정은 별도의 실제 결과로 기록하고 개선·이의신청 검토로 연결한다.

공식 절차상 신청서 최종 제출 뒤 서류 확인과 필요한 보완을 거쳐 납부하며, 납부 완료가 접수 완료에 연결된다. 혁신성장유형은 이후 서류·현장실제조사와 심의를 거친다. 그러므로 ‘파일 업로드 성공’과 ‘접수 완료’, ‘벤처확인 완료’를 같은 상태로 표시하지 않는다. [공식 확인절차](https://www.smes.go.kr/venturein/institution/processGuide)

### 6.5 신청 후의 기본 화면

| 상황 | 가장 크게 보여 줄 안내 | 주 실행 |
|---|---|---|
| 기관 검토 중 | “현재 서류를 확인 중입니다. 마지막 확인: 오늘 10:00” | 사용자가 처리할 일이 없으면 실행 버튼을 억지로 만들지 않음 |
| 자료 보완 | “매출 근거 1개가 더 필요합니다.” | 자료 추가하기 |
| 답변 준비 | “보완 답변을 준비했습니다. 바뀐 내용만 확인해 주세요.” | 보완 답변 확인 |
| 납부 요청 | “공식 납부 요청이 도착했습니다.” | 금액·기한 확인하고 납부 |
| 실사 예정 | “실사에 필요한 설명과 자료를 준비해 주세요.” | 실사 준비 보기 |
| 확인 결과 도착 | “공식 결과를 확인했습니다.” | 결과와 확인서 보기 |

기관 요청을 자동으로 수신할 수 없는 초기 버전에서는 안내문이나 이메일 내용을 붙여넣는 경로를 제공한다. 이를 기관 자동 조회로 표시하지 않는다. 자동 수집·알림은 사용자의 동의와 허용된 연결 수단을 갖춘 뒤 추가한다. 화면에는 마지막 확인 시점을 남겨 오래된 상태와 현재 상태를 구분한다.

## 7. 사용자에게 보여 주지 않을 복잡성

| 현재 노출 | 새 기본 경험 | 내부에 남길 기능 |
|---|---|---|
| 기업정보 폼 전체 작성 | 자료에서 읽은 회사 정보 확인 | 전체 필드 편집 |
| 파일 분류·판독 실행·본문 채택 | 자료를 올리면 읽고, 중요한 오류만 질문 | 판독 원문·교정·출처·검토 이력 |
| 사전진단 별도 실행 | 준비 중 확인할 사항으로 통합 | 요건·증빙 상세 대조 |
| 후보별 화면 탐색 | 추천 신청 주제 한 장 | 대안 비교·선택 이력 |
| 항목별 저장과 버전 선택 | 내용 자동 저장, 제출본 검토 | 불변 제출본·수정 이력·비교 |
| ZIP 생성 | 앱이 제출파일을 준비 | 묶음 다운로드·원본 선택 |
| 기관 단계·기록 수동 관리 | 받은 요청과 다음 할 일 | 수신 원문·단계 근거·회차 이력 |
| 실행 대응표·브라우저 세부 상태 | “로그인이 필요합니다”, “입력을 이어가는 중입니다” | 연결 진단·실패 지점·개별 실행 기록 |

전문가 기능은 없애지 않는다. 현재 기능을 같은 데이터 위의 상세 보기로 재사용한다. 대표가 어려운 상황에 놓였을 때 담당자가 자료·원고·실행 기록을 확인하고 도와줄 수 있어야 한다.

## 8. 자동 진행을 실제로 가능하게 할 구조

사용자 화면은 세 단계로 단순하게 만들고, 내부에서는 회사별 하나의 신청 작업이 각 처리의 상태를 관리한다.

| 구성 | 책임 |
|---|---|
| 회원·회사 권한 | 계정 복구, 회사 소유권, 담당자 초대, 기업 간 자료 접근 분리 |
| 자료·사실 저장 | 원본과 추출 결과 보존, 출처 연결, 미확인·사용자 확인 구분 |
| 준비 작업 관리자 | 자료 변경을 모아 필요한 AI 작업만 실행, 질문 대기·재개·실패 복구 |
| AI 작성·검토 | 사실 기반 아이템·사업계획서·보완 초안, 모델/처리범위·비용 관리 |
| 공식 신청 연결 | 인증 상태, 화면별 입력·첨부·저장·제출, 결과 대조 |
| 신청 이후 관리 | 공식 상태·기관 요청·기한·담당자·실사·확인서 연결 |
| 일반/전문가 화면 | 동일 상태를 서로 다른 상세 수준으로 표현 |

자료를 다시 넣었다고 전체 원고를 무조건 덮어쓰지 않는다. 바뀐 자료와 관련된 내용만 새 초안으로 만들고, 이미 제출한 원고·첨부·승인 이력은 보존한다. 중복 클릭은 하나의 요청으로 처리하며 결과가 불명확한 제출을 자동 재시도하지 않는다. 공식 상태부터 확인한다.

공유서비스의 AI 준비 작업은 브라우저를 닫아도 서버에 진행 상태가 남아야 한다. 반면 사용자 PC의 공식 사이트 연결이 필요한 작업은 해당 기기·세션이 살아 있어야 할 수 있다. 이때 “이 기기에서 신청을 이어 주세요”라고 안내하고 무인 실행을 보장하지 않는다.

처리 실패는 세 종류로 나눈다. 읽기·초안 생성 같은 안전한 작업은 제한적으로 재시도하고, 사실 부족은 질문으로 바꾸며, 저장·제출 결과 불명확은 결과 확인 상태로 둔다. 셋을 모두 “다시 실행” 버튼 하나로 처리하지 않는다.

## 9. 현재 구현과 새 기획 사이의 차이

2026-09-26 저장소를 읽어 확인한 상태다. 과거의 ‘로컬 기능 완료’는 새 고객용 서비스 전체가 완료됐다는 뜻이 아니다.

| 영역 | 현재 확인한 기반 | v2에서 필요한 변화 |
|---|---|---|
| 화면 | 기업정보·자료함·사전진단·아이템 분석·사업계획서·진행 관리·벤처인 연결 7탭 | 3단계 기본 화면과 상태에 따른 다음 할 일 |
| 자료 | 복수 접수, 문서·OCR·음성 처리, 교정·채택, 출처·재개 | 업로드 이후 연속 처리와 핵심 쟁점만 확인 |
| AI | 실제 AI 분석·서술형 작성·별도 검토 경로 있음 | 기본 준비 흐름을 AI 작성까지 연결하고 실제 품질 검증 |
| 로컬 자동 진행 | 기본 준비 흐름은 자료 정리 모드로 고정 | 모드 선택을 일반 화면에서 없애고 승인 범위의 AI 작업 연속 실행 |
| 공식 신청 | 로그인·관측·기업 대조, 일부 표준 입력·파일 실행 기반 | 실제 전 화면, 업로드 확정·저장·이동·최종 제출·결과 확인 검증 |
| 신청 후 | 기관 요청·통보·보완·실사·회차 기록 기반 | 허용된 실제 수신·상태 조회·답변 재제출·알림 |
| 회원 서비스 | 로컬 접근 보호·회사별 자료 보관 | 회원가입·복구·회사 권한·공유 저장소·운영 체계 |

현재 실제 공식 사이트 검증을 전체 입력·첨부·접수 성공으로 확대해서 설명하지 않는다. 로그인 및 신청 유형·사전확인 화면 진입과 관측 이후의 자동 신청은 별도 검증이 필요하다. 가상 자료의 모의 접수는 연결 코드 시험 근거이며 실제 기관 접수의 증거가 아니다.

## 10. 개발 순서와 출시 기준

개발 달력보다 완료 조건을 먼저 정한다. 기존 데이터를 지우거나 새 앱을 처음부터 다시 만들지 않고, 현재 기능을 재사용해 기본 경험과 실행 연결을 바꾼다.

| 순서 | 개발 묶음 | 통과해야 할 기준 |
|---|---|---|
| A | 일반 사용자 3단계 화면, 상태별 주 실행, 기존 기능 매핑 | 처음 보는 사용자가 설명 영상 없이 자료 업로드와 다음 할 일을 찾음 |
| B | 업로드→핵심 확인→AI 추천→접수용 원고의 연속 처리 | 충분한 자료·부족한 자료·충돌 자료 모두에서 올바르게 작성 또는 질문 대기 |
| C | 실제 벤처인 연결의 허용 범위 확인과 화면 검증 | 실행 가능한 범위를 문서화하고 합성 시험 뒤 허가된 실제 건으로 입력·저장·제출 결과 검증 |
| D | 회원가입·회사 권한·서버 작업·보관 정책·복구 | 사용자·기업 간 접근 격리와 계정 복구, 외부 AI 동의·비용 통제가 동작 |
| E | 보완 수신·답변 준비·재제출·납부·실사·결과 관리 | 원 요청부터 공식 처리 결과·확인서까지 같은 신청 건으로 추적 가능 |
| F | 초보 사용자 검증과 제한된 시범 운영 | 조작 난도·작성 품질·중복 실행 방지·공식 결과 표시 기준 통과 |

A와 B로 사용성 핵심을 먼저 검증한다. C의 기관 조건 확인은 초기에 병행해 나중에 자동접수 가정이 뒤집히지 않게 한다. D는 외부 사용자가 실제 자료를 올리기 전에 완료해야 하며, 공개 서비스 가입 화면만 먼저 열지 않는다. C가 막혔을 때 수동 복사·다운로드를 임시 보조 경로로 제공할 수 있지만, 이를 전 과정 자동화 완료로 선언하지 않는다.

### 첫 개발 묶음의 구체 범위

- 기존 앱 앞에 일반 사용자용 3단계 동선을 추가하고, 상세 화면은 같은 상태를 공유한다.
- 자료 한 번 업로드 후 읽기·분류·핵심 정보 제안까지 이어지게 한다.
- AI 준비 상태와 필요한 질문을 한 화면에 모으고, 현재의 자료 정리 모드를 AI 원고 완료로 오해하지 않게 한다.
- 작성·보완·기관 요청을 모두 ‘지금 할 일’ 구조로 표시한다.
- 새 흐름을 가상 자료로 검증한 뒤 실제 사용자 자료는 허용된 범위에서 별도로 검증한다.

## 11. 사용성·품질 완료 기준

아래 수치는 현재 성과가 아니라 초기 테스트의 제안 목표다.

| 검증 항목 | 제안 목표·판정 |
|---|---|
| 초보 사용성 | 사전 교육 없는 대상 사용자 5명 중 4명 이상이 자료 업로드와 다음 행동 찾기를 도움 없이 완료 |
| 첫 시작 | 가입·자료 선택부터 초기 자료 접수까지 사용자 조작 시간 5분 이내 목표. 파일 처리 대기시간은 별도 측정 |
| 화면 복잡도 | 기본 메뉴 3개, 화면별 주 실행 1개, 한 질문 묶음 최대 3개 |
| 불필요한 재입력 | 이미 확인한 값은 관련 변경 없이 다시 묻지 않음 |
| 작성 품질 | 제출본의 핵심 숫자·권리·현재 실적에 근거 또는 명확한 확인 기록이 있음. 무근거 확정 주장 발견 시 출시 불가 |
| 자동 진행 | 사용자 확인이 필요 없는 정상 단계에서 별도 ‘다음 실행’ 클릭 요구 없음 |
| 재개·중복 | 새로고침·세션 종료·통신 불명확·중복 클릭에서 자료 보존 및 중복 제출 방지 |
| 공식 상태 | 입력 성공·제출됨·접수 완료·확인서 발급을 구분하고, 실제 기관 근거 없이 완료 표시하지 않음 |
| 접근·자료 보호 | 회사 격리·역할 검사·비밀값 마스킹·보관과 복구 검증을 통과 |

원고 검수는 자료가 충분한 기업만 대상으로 하지 않는다. 개발 초기, 재확인, 재무자료 누락, 자료 간 금액 충돌, 권리 주체 불일치 사례를 포함한다. 코드를 통과한 테스트 수만으로 사업계획서의 실제 품질이나 벤처확인 가능성을 평가하지 않는다.

## 12. 이번 기획의 권장 결정

기본 사용자는 기업 대표·실무 담당자로 정하고, 컨설팅 담당자의 상세 기능은 유지한다. 3단계를 기본 화면으로 채택하고, 정상 진행은 자동 연결한다. AI가 사실을 대신 만들어 내는 자동화는 하지 않는다. 사용자는 중요한 사실과 외부 제출을 확인하고, 앱은 반복 작성·정리·이동·진행 관리의 부담을 맡는다.

사용자가 직접 가입하는 고객용 서비스를 최종 목표로 잡되, 실제 외부 자료를 받는 공개 서비스는 계정·권한·운영 조건이 준비된 뒤 연다. 공식 자동접수는 기관 조건과 실제 결과 검증을 통과한 범위부터 제공하며, 고객이 그 차이를 이해할 수 있게 표시한다.

다음 구현의 우선순위는 추가 기능의 개수를 늘리는 것이 아니라 **새 3단계 화면과 ‘자료 → AI 신청서’의 실제 연속 동작을 완성하는 것**이다. 이 기획안 작성 단계에서는 실제 앱 동작, 사용자 데이터, 공식 신청 상태를 변경하지 않았다.
