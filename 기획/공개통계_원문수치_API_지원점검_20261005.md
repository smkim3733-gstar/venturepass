## 기존 구현에서 재사용할 것

검토한 제품 파일은 `studio-public-research.ts`, `studio-public-research-result.ts`, `studio-public-research-service.ts`, 기존 검색 route와 `PublicResearchLinks`다.

기존 검색은 고정 일반 주제 8개만 전송하고 첫 페이지 최대 10개 후보를 읽는다. 후보의 기관/표 ID와 제목·제공기관·수록기간은 수치를 대신하지 않는다. HTTPS KOSIS 표 링크는 정확한 ID만 재구성하며 임의 URL·추가 query·자격증명을 전달하지 않는다. UI는 명시 버튼으로 조회하고 후보 제목/주소만 빈 칸으로 옮긴다.

기존 서버의 20초·512KiB·진행 중 1개·리디렉션 거절·무재시도·취소 처리와 비밀/오류 원문 비노출을 다음 전송 경계의 기준으로 삼는다. 공유 함수를 추출할 경우 검색 회귀를 실행한다. 새 수치 서비스와 검색 서비스의 합계 동시 실행도 1개가 되도록 공유 범위를 명시해야 하며 서비스별 잠금 두 개를 전체 1개라고 보고하면 안 된다. 회사 DB·자료 writer·AI SDK를 새 조회의 의존성으로 넣지 않는다.

### 해결된 지원 확인과 남은 모호성

1. 공식 통계 수치 API가 존재하므로 임의 사이트 HTML 수집이나 계정 세션 복사가 필요하지 않다. 통계자료 응답 일부를 읽는 것은 표 전체·주석·원문 파일 전체 수집과 다르다.
2. 검색으로 찾은 이전 공식 PDF 매뉴얼의 ITM 입력은 `objId/itmId` 선택으로 설명됐지만 현재 HTML은 필수다. `OBJ_ID_SN` 형식도 이전 NUMBER와 현재 VARCHAR 설명이 다르다. 최신 HTML 계약을 우선하며 빈 값/ALL/특정 OBJ_ID를 넣으면 전체 항목이 나온다고 추정하지 않는다. [이전 공식 매뉴얼 검색 근거](https://sso.kosis.kr/openapi/file/openApi_manual_v1.0.pdf), [현재 ITM 가이드](https://kosis.kr/openapi/devGuide/devGuide_060104List.do)
3. NCD를 표 제목으로 합쳐 특정 표의 갱신일이라고 단정하지 않는다. 우선 수치 행에 결합된 LST_CHN_DE를 원문 문자열로 보존한다. 이것도 발행일·담당자가 읽은 날짜·조회 시각과 다르다.
4. 실제 응답의 오류 envelope와 모든 null/빈 문자열 조합, ITM의 전체 코드 탐색 값, 분류 순번에서 objL1~8로 이어지는 전체 매핑은 이번에 운영 확인하지 않았다. 파싱 성공을 지원 범위의 실증으로 바꾸지 않는다.

세부 HTML 7개는 웹 검색 도구에서 직접 열리지 않아, 공개 메인 가이드의 실제 탭 URL을 읽고 해당 문서만 일반 HTTPS GET으로 확인했다. 최초 제한 셸의 네트워크 접근은 권한 오류로 실패했고 도구의 권한 절차를 거쳐 성공했다. 키/쿠키/고객정보 없이 문서의 요청·출력 필드만 읽었고 원문 파일은 저장하지 않았다. 공식 PDF 전체는 도구에서 열리지 않아 검색에 노출된 해당 표 부분만 비교했으며 전체 PDF 검수 완료로 보고하지 않는다.

## 이용 범위와 오류

출처 표시·정해진 인터페이스·인증키 관리·트래픽 제한과 라이선스 예외를 유지한다. 약관에 일반 활용 근거가 있어도 이 PC의 활용신청/권한/키 유효성이 완료됐다는 뜻은 아니다. 신청/약관 동의/키 발급·갱신을 대신하지 않는다. [KOSIS 통계정보 활용약관](https://kosis.kr/openapi/introduce/introduce_02List.do)

공식 FAQ는 KOSIS·작성기관 출처 표시, 조회일자 권장, 라이선스 예외와 자료 변경 가능성을 설명한다. 인증·파라미터·자료 없음·조회량/호출 제한·서버 오류도 별도다. 특히 31번은 40,000건 이상 조회결과 제한으로 설명된다. 이를 이 앱이 40,000건을 수집해도 된다는 한도로 사용하지 않는다. 개별 키의 호출 허용량은 이번에 확인하지 않았다. [공식 FAQ](https://kosis.kr/openapi/community/community_0401List.do)

다음 서비스는 상위 오류 객체를 빈 성공 배열로 바꾸지 않는다. 오류 body의 실제 wire 계약을 확인하기 전에는 임의 err/errMsg 형태를 공식 계약으로 만들어 분기하지 않는다. 비배열·HTML·파싱 실패·알 수 없는 오류는 안전한 미확인으로 처리하며 원문 오류·요청 URL·키는 화면/로그에 내보내지 않는다. 자료가 없다는 응답은 통계값 0이나 회사 주장이 거짓이라는 판정이 아니다.

## 다음 4H2의 구현 계약 — 아직 구현하지 않음

### 최초 범위

공개 통계의 정확한 한 셀을 지정하는 내부 타입/순수 응답 대조와 서버 전용 서비스부터 구현한다. UI/외부 route가 임의 명령을 받도록 먼저 열지 않는다. 항목 탐색 방식이 미확인인 동안 실제 선택 메뉴를 가짜 목록이나 추정 코드로 만들지 않는다. 다음 단위의 성공 기준은 합성 입력/응답과 전송 경계 검증이며 F12 전체 완료가 아니다.

- 대상: 기관 1개/표 1개/항목 1개, 분류 1~8개 각각 코드 1개, Y/M/Q/S 중 주기 1개/시점 1개.
- 입력은 코드만 받는 strict 구조다. 임의 URL·자유 검색문·회사 ID/본문·source 객체·키·관측 JSON·DB 명령을 받지 않는다. 문자열 코드의 대소문자·앞자리 0을 바꾸지 않는다.
- 기존 표 ID 링크의 허용 문자/길이 검사를 재사용한다. 분류/항목 코드는 첫 범위에서 구분자·공백·제어문자·와일드카드 없는 단일 식별자로 제한한다. 이는 앱의 보수적 부분집합이며 모든 KOSIS 코드를 지원한다는 주장이 아니다.
- `ALL`, 합계/최신 자동 선택, 복수 코드 `+` 등 구분자, 범위/빈 기간·`newEstPrdCnt`는 최초 범위에서 지원하지 않는다. 합계가 필요하면 공식 메타데이터에서 확인한 정확한 합계 코드를 명시 선택해야 한다.
- `startPrdDe=endPrdDe`로 선택 시점을 고정하고 `smblChk=Y`를 명시한다. json만 읽고 JSONP/HTML/script를 실행하지 않는다. 임의 outputFields를 받아 신원/단위 필드를 제거하지 않는다.
- 이 단위는 typed target을 처리하는 내부 서비스다. 검색 후보 JSON 자체가 서버 발급 선택 증거나 허가된 표 목록이라는 뜻은 아니다. 이후 사용자 선택 연결에서는 서버가 검증한 공개 후보·메타데이터와 정확한 선택을 결합하고 오래된/변조된 선택을 거절해야 한다.

### 반환과 전송

- 선택된 org/table/item/각 분류/주기/시점을 응답 행과 전부 대조한다. 단일 셀 요청인데 두 행 이상·중복·다른 ID·예상하지 않은 추가 분류가 오면 첫 행만 고르지 않고 거절한다.
- 빈 배열과 일치한 값 1건을 구분한다. DT는 문자열 그대로 보존하고 '0'·빈 문자열·부호·결측 표시를 서로 바꾸지 않는다. Number/parseFloat·단위 환산·반올림·합산·성장률 계산을 하지 않는다.
- 표/항목/분류 명칭·단위 ID/명칭·기간·행 수정일·조회 시각을 구분한다. 누락되거나 뜻이 불분명한 단위/날짜는 미확인으로 남기며 다른 메타데이터의 첫 값을 끼워 넣지 않는다.
- 요청 URI는 서버가 고정 HTTPS endpoint와 허용 매개변수만 구성한다. 리디렉션·사용자 헤더/쿠키·브라우저 키 전달·자동 재시도·페이지 분할/백그라운드 수집을 넣지 않는다.
- 20초·512KiB·합계 동시 1개와 취소를 유지한다. 단일 응답 0~1행, 내부 명령 최대 8KiB를 앱의 추가 한도로 둔다. 모든 초과는 실패이며 자르지 않는다. 실제 코드의 한도 적용 위치와 검사 순서를 시험한다.
- 순수 decoder에 supplied fixture를 넣은 결과와 서버가 지정 endpoint에서 읽은 결과를 구분한다. 숫자/출처 의미 검증·회사 해당 여부·사람 확인·원고 채택/전송 승인으로 승격하지 않는다.
- 결과는 아직 DB/자료/원고로 저장하지 않는다. 추후 보관 시에도 별도 검토·정확한 선택/응답 시점·출처를 보존하고 기존 수동 source를 자동으로 신뢰된 구조화 근거로 바꾸지 않는다.

### 의미 있는 합성 검증

정확한 셀·분류 1~8개·Y/M/Q/S 경계/잘못된 기간, 코드/추가 필드/구분자 주입, 원문 수치 부호/긴 명칭·단위 보존, 다른 표/기간·중복/빈/누락·초과 응답, UTF-8/비JSON/오류 객체, 키 미설정·키 노출 금지, timeout/취소/동시 검색과 수치 읽기·redirect/stream 초과를 검증한다. 실제 네트워크·AI·DB writer는 합성 시험에서 금지한다.

제품 코드를 바꾸면 필요한 회귀 → lint → typecheck → 격리 build:local 순서로 각 종료코드를 확인한다. 내부 서비스만 바뀌면 사용자 UI 시험을 성공했다고 주장하지 않는다. 키 없는 합성 성공과 실제 KOSIS 운영 0/1을 계속 구분한다.
