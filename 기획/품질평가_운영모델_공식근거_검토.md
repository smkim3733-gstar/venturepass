# 품질평가 운영 모델 공식 근거 검토

작성·열람일: 2026-09-27 KST. 공식 문서 확인 구간: 2026-09-26 23:51–23:54 UTC.

## 1. 제안의 상태

검토 후보는 **`gpt-5.4-2026-03-05` 한 개**다. 정확한 스냅샷과 Structured Outputs 지원을 공식 문서에서 확인했고, Responses를 쓰는 기존 v2 고정 요청의 텍스트·출력 상한 조건에 부합하여 생성·별도 검토 평가 후보로 제안한다. 실제 요청 수락이나 한국어 사업계획서 품질, 사용자 계정 이용 가능성을 검증한 결과는 아니다. [공식 모델 페이지](https://developers.openai.com/api/docs/models/gpt-5.4)

이 문서는 OpenAI Docs 절차에 따른 **읽기 전용 제안 근거**다. 실제 API 호출, 키·환경설정·사용자 DB 열람, 운영 모델 채택, 예산 설정, 외부 전송 승인, 원장 예약을 하지 않았다. 최신·최고 모델이라는 주장도 하지 않는다. 기존 요청 본문과 과거 승인·보관 해시는 변경하지 않는다.

## 2. 로컬 계약 확인

로컬 설치본은 `openai 7.20.0`이다. `web/node_modules/openai/src/resources/responses/responses.ts`의 `ResponseUsage`, `InputTokensDetails`, `OutputTokensDetails`, `ResponseCreateParams`를 읽었다. 입력·출력·총량, `cached_tokens`, **`cache_write_tokens`**, `reasoning_tokens`, 실제 응답의 `service_tier`가 정의되어 있다. SDK의 필드 존재는 특정 모델의 과금 방식이나 모든 응답의 필드 수신을 보장하지 않는다.

현재 v2 본문 조건은 `service_tier:default`, `truncation:disabled`, `store:false`, `background:false`, `stream:false`, 도구 없음, `max_output_tokens:16000`이다. 생성·검토는 별도 요청 최대 2회이며 자동 재시도는 없다. `previous_response_id`·conversation·compaction을 사용하지 않는 기존 계약을 전제로 검토했다.

| 일반 구간: 입력 / 캐시 읽기 / 출력 | $2.50 / $0.25 / $15.00, 각 1M tokens 기준 | 공식 모델 페이지 |

모델·한도·가격 근거: [GPT-5.4](https://developers.openai.com/api/docs/models/gpt-5.4). 문맥은 입력·출력·추론이 함께 쓰는 공간이다. `C` 전부를 입력 예약에 쓰고 `O`를 더하는 앱 계산은 의도적인 금융 과대예약이며, 입력이 실제로 들어간다는 검증은 아니다. [문맥 관리](https://developers.openai.com/api/docs/guides/conversation-state)

**산술 해석:** 장문 일반 입력은 $5.00, 출력은 $22.50/1M이다. 장문 캐시 읽기 $0.50은 공식 입력 배율을 $0.25에 적용한 계산값이다. 이번에 읽은 페이지에서 $0.50을 별도 숫자 행으로 확인하지는 않았으므로, 직접 인용 가격과 구분해 저장한다. 요청별 장문 가격 적용과 지역·처리 방식에 따른 가산은 별도 조건이다. 이 제안은 기본 Global endpoint와 Standard만 대상으로 한다. [장문 가격 안내](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.4)

### 캐시 쓰기 해석

공식 캐싱 문서의 모델 비교표는 GPT-5.6 이전 모델에 **추가 캐시 쓰기 요금이 없음**을 명시한다. 이는 캐시가 쓰이지 않거나 쓰기 토큰이 항상 0이라는 뜻이 아니다. GPT-5.4에서는 캐시 읽기 외 입력을 일반 입력 요율로 계산하는 정책을 제안한다. 별도 쓰기 과금 구간은 `not-applicable`로 표현할 수 있지만, 원래 `cache_write_tokens`가 도착하면 그대로 보존한다. [캐싱 모델별 차이](https://developers.openai.com/api/docs/guides/prompt-caching#summary-of-model-differences)

이 해석은 GPT-5.4에만 묶는다. 모델을 바꿀 때 재사용하지 않는다. 공식 문서는 새로운 모델의 캐시 쓰기 요율을 일반 입력에 더하는 부가요금이 아닌 대체 요율로 설명한다. 이 사실 때문에 SDK에 필드가 있다는 이유만으로 다른 세대의 배율을 GPT-5.4에 적용해서는 안 된다. [캐시 요율 설명](https://developers.openai.com/api/docs/guides/prompt-caching)

## 4. Responses 사용량 정책 후보

| 정책 항목 | 읽기 전용 제안 |
|---|---|
| 모델 범위 | 요청 모델과 허용 응답 모델을 우선 고정 스냅샷 ID 하나로 제한. 별칭 응답을 임의 허용하지 않음 |
| 처리 등급 | 요청·응답 모두 `default` 기대. 누락·다른 값은 미확인 비용 처리 |
| 입력 총량 | `usage.input_tokens` |
| 캐시 읽기 | `usage.input_tokens_details.cached_tokens` |
| 비캐시 입력 | 입력 총량 − 캐시 읽기. 별도 쓰기 과금 없음이라는 모델별 정책에 따른 정규화 |
| 별도 캐시 쓰기 과금 | `not-applicable`; 물리적 쓰기 횟수·토큰 0 주장 금지 |
| 출력 과금 | `usage.output_tokens` 전체. reasoning을 다시 더하지 않음 |
| 추론 내역 | `usage.output_tokens_details.reasoning_tokens` 원문 보존 |
| 장문 구간 | `input-threshold`, threshold `272000`, 초과일 때 장문 요율 |
| 누락·모순 | 필요한 수치 누락, 음수·비정수, 캐시량>입력량, 합계 모순, 모델·tier 불일치면 `unknown` 및 예약 유지 |

입력 세부 캐시 수치는 입력 총량의 분해다. 공식 캐시 비용 예시는 총입력에서 캐시 읽기·쓰기 범주를 빼고 각 범주 요율로 계산한다. 위 표는 이를 GPT-5.4의 별도 쓰기 과금 없음에 맞춘 **내부 정규화 제안**이다. 실제 응답 관측이나 공급자 청구서 대조 결과는 아니다. [캐시 사용량·비용 계산](https://developers.openai.com/api/docs/guides/prompt-caching#monitor-cache-performance)

`service_tier:default`는 Standard 처리 요청이며, 실제 응답의 tier 값은 요청과 다를 수 있다. 이를 요청값으로 덮어쓰면 안 된다. `max_output_tokens`에는 보이는 출력과 추론 토큰이 포함된다. [Responses 생성 명세](https://developers.openai.com/api/reference/cli/resources/responses/methods/create)

추론 토큰은 출력 요율로 과금된다. 출력 한도에 도달하면 보이는 원고가 없더라도 비용이 생길 수 있으므로, 원고 검증 실패와 비용 미발생을 동일시하지 않는다. [추론·출력 비용](https://developers.openai.com/api/docs/guides/reasoning#controlling-costs)

## 5. 조건부 예약 계산 예시

아래는 로컬 v2 예약 공식에 문서 수치를 대입한 산술 검토다. 예상 평균 청구액이나 운영 예산 채택이 아니다. 계산 단위는 USD의 백만분의 1(`unitScale:6`)로 제안한다.

- 최고 입력 요율: $5.00/1M → `units:"5000000", perTokens:1000000`.
- 최고 출력 요율: $22.50/1M → `units:"22500000", perTokens:1000000`.
- 1회 예약: `ceil(1,050,000 × 5,000,000 / 1,000,000) + ceil(16,000 × 22,500,000 / 1,000,000)` = 5,610,000 units = **$5.61**.
- 생성 1회 + 검토 1회: **11,220,000 units = $11.22**.

입력·출력 각 항목을 요청별로 올림하는 기존 규칙을 따른다. 캐시 할인은 예약을 줄이는 근거로 쓰지 않는다. 이 금액은 기술적으로 부적합한 요청, 공급자 오류, 미수신 응답 등 모든 실패의 청구 상한을 공급자가 보증했다는 의미가 아니다. 실제 토큰 수, 문맥 적합성, 이용 권한, 운영 총예산은 미확인 상태로 둔다.

초기 한 후보 시험의 **누적 예산을 USD 15로 제안**한다. `unitScale:6`이면 `capUnits:"15000000"`이고, 기존 사용량·미정산 예약이 모두 0이라는 조건에서 최초 $11.22 예약 뒤 잔여 가용액은 $3.78이다. 누적 인정 비용과 미정산 예약을 계속 합산하므로, 재실행 때 $15가 다시 생기지 않는다. 이 제안은 설정·예산 채택·승인·호출 허가가 아니며, 기존 비용이나 다른 실행이 있으면 그만큼 가용액을 먼저 줄여야 한다.

## 6. `store:false`와 보관 안내

`store:false`는 응답 객체를 나중에 조회하는 기본 저장을 끄는 조건이다. 모든 데이터의 즉시 삭제나 ZDR 승인을 뜻하지 않는다. [응답 저장](https://developers.openai.com/api/docs/guides/conversation-state#data-retention-for-model-responses)

공식 데이터 문서는 기본 악용 방지 로그에 입력·응답이 포함될 수 있고 통상 최대 30일, 법률·안전상 예외에서는 더 길게 남을 수 있다고 설명한다. ZDR/MAM은 별도 사전 승인과 조직·프로젝트 설정이 필요하다. 현재 계정 상태는 확인하지 않았다. [데이터 보관 통제](https://developers.openai.com/api/docs/guides/your-data#data-retention-controls-for-abuse-monitoring)

확인한 현재 문서는 ZDR 미설정 조직에서 지원 모델의 확장 프롬프트 캐시가 사용될 수 있고, 암호화된 KV 데이터가 GPU 로컬 저장소에 최대 24시간 남을 수 있음을 명시한다. GPT-5.4는 확장 캐시 지원 목록에 있다. 따라서 현 본문에 `store:false`가 있다는 이유로 ‘메모리만 사용’, ‘보관 없음’, ‘요청 종료 즉시 모두 삭제’를 표시하지 않는다. [Responses 보관 예외](https://developers.openai.com/api/docs/guides/your-data#v1responses), [캐시 수명·기본값](https://developers.openai.com/api/docs/guides/prompt-caching#cache-lifetime)

사용자 안내 후보: “외부 AI 응답의 재조회용 저장은 끕니다. 공급자의 악용 방지 로그와 프롬프트 캐시 보관은 별도 정책이 적용됩니다. 현재 계정의 특별 보관 승인은 확인하지 않았습니다.” 이 문구의 운영 채택은 이번 작업에서 하지 않았다.

## 7. 출처 기록과 남은 조건

공식 도메인을 검색한 뒤 해당 페이지를 실제로 열어 확인했다. 웹 도구가 제공한 가독화 본문을 검토했으며 **원래 HTTP body 바이트를 보존하지 않았다**. 따라서 `bodySha256:null`로 두고 공식 원문 SHA를 만들어 넣지 않는다. 후속 소스팩의 `digestKind:"curated-record"`와 `recordDigest`는 URL·확인 시각·짧은 검토문을 묶은 자체 기록의 해시다. 웹페이지 원본 해시와 구분한다. 이 Markdown 파일의 SHA도 검토 문서 자체의 해시에 불과하다.

조회 기준일은 위에 고정했다. 문서에는 공급자가 보장한 미래 가격 유효기간이 없다. 후속 `validUntil`은 다시 확인하기 위한 내부 기한으로 정하고, 공급자 가격 고정 약속으로 표시하지 않는다.

아직 필요한 조건은 다음과 같다.

1. 모델·문맥·요율·캐시 정규화·보관 안내의 운영 채택 기록. 긴 캐시 읽기 요율의 산술 해석도 함께 드러낸다.
2. 실제 프로젝트의 해당 스냅샷 접근 권한·Global 처리 조건·결제 조건 확인. 이번에 키나 계정 API를 조회하지 않았다.
3. 운영 총예산과 한 건 한도, 기존 사용량·미정산 예약을 포함한 예산 정책. $11.22 계산이 이를 대신하지 않는다.
4. 정확한 요청/응답 범위에 대한 별도 전송 승인. 이 검토 문서나 후보 선택으로 승인·예약·실행권한을 생성하지 않는다.
5. 고정 합성 후보를 이용한 실제 품질평가와 독립 검토. Structured Outputs 지원만으로 사업계획서의 사실성·완결성·설명 가능성을 통과 처리하지 않는다.

이번 산출물은 이 문서 한 개이며, 제품 설정·실제 전송 어댑터·기존 저장소·과거 기록은 변경하지 않았다.
