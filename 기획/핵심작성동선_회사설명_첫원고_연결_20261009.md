# 회사 설명만으로 첫 원고를 준비하는 연속 흐름

회사명만 있는 한 합성 회사에서 첨부0개·원고0개로 시작해 설명 저장 → 자료0개 범위 확인 → 별도 전송 동의 → 신청 주제와 이유 직접 선택 → 첫 원고 v1 표시까지 같은 화면 세션으로 확인했다. 중간에 회사를 다시 열거나 완료 상태로 갈아 끼우지 않았다. 처음 주제 선택 전에는 원고가 없고, 설명을 인용한 v1에는 확인 필요10개·검토 의견1개·전체 confirmedAt:null이 남는다. 원래 run/동의/빈 sourceIds·회사 설명·선택 기록·v1 planId가 이어졌다. v1 Word 링크의 대상만 대조했으며 이번 다운로드 실행0이다.

정상 연결 확인 뒤 설명 저장의 구체적 응답 검사가 빠진 것을 발견해 수정했다. 공통 studioMutationResponse는 같은 revision 응답을 허용하므로 설명 저장 호출자가 제출한 profile을 별도로 대조해야 한다. 이제 같은 회사·증가 revision·제출한 전체 profile이 정확히 일치할 때만 설명 폼을 닫고 준비로 이동한다. 응답 없음/옛 revision/다른 설명·profile이면 입력을 유지하고 다음 준비를 막는다. 기존 trim 처리·공통 mutation/writer·다른 저장 경로·동의/검토/기관 상태는 바꾸지 않았다. 이 보완은 서버 영수증/영속 저장을 새로 구현하거나 보증하지 않는다.

제품2개(guided-description-save.ts/guided-workspace.tsx), 시험·합성자료·검증기3개를 변경했다. 신규9+기존 같은 화면13=22/22, 격리 실제 앱의 새 연속 흐름1/1(단계 대조5개)이 통과했다. 잘못된 설명 응답에서 입력을 유지한 뒤 명시 저장으로 정상 흐름을 이어 갔다. 최종 합성 명령5개(profile2/start1/select-candidate1/continue1)와 범위 읽기 POST4개다. 같은 revision7의 읽기2회는 실행 재시도가 아니며 start/continue 각1회다. 개발/프로덕션·수정 전 연결 확인·실패 후 재실행을 별도 고유 흐름으로 합산하지 않는다.

초기 검증기2회는 기존 자동 범위 읽기를 명령/고정 횟수로 잘못 예상해 실패했다. 읽기/실행 집계를 분리하고 같은 현재 revision의 읽기 중복을 구분했다. 첫 비동기 route 단언 실패가 finally를 지나지 않아 처리기에서 오류를 상위 검사로 전달하도록 보완했다. 첫 폴더 y1warA는 unused-data 부재·해당 경로 node/Edge 잔존 프로세스0을 별도 확인했으나 완료 로그가 없어 최종 성공으로 세지 않는다. 뒤 5GswPK 실패·수정 전 yVY9ul 성공과 개발 uOuOTn/최종 J5c3Yg는 보존했다. 최종 업무 route·SQL 생성/읽기/쓰기·외부·SDK client/API·고객DB·유료AI·pageerror0, unused-data 부재·자기 child 종료다. 원래 과거 Word 시험의 임시 DB2건도 별도 보존했다.

## 검증한 경로와 한계

- 시작 상태는 이미 등록된 합성 회사의 빈 설명·자료0·원고0이다. 이번 회사 생성 UI 자체는 관측하지 않았다.
- 사용자 입력 설명은 “소규모 제조사의 설비 상태를 센서로 확인하는 기술을 구상하고 있습니다. 고객 계약과 외부 시험은 아직 없습니다.”다. 실제 회사나 고객 정보가 아니다.
- 첫 profile 응답은 schema가 유효하지만 옛 revision/빈 설명인 합성 응답이다. 폼·입력이 남고 선택 미리보기/AI 명령은 발생하지 않았다. 다시 누른 명시 저장만 다음으로 이어졌다.
- 실제 UI가 만든 범위 입력과 동의·주제 선택·continue 명령을 기존 순수 helper로 대조해 메모리 응답을 구성했다. 생성된 분석/원고/검토 의견은 고정 합성이며 의미 품질을 측정하지 않았다.
- 완료 화면의 v1·확인 필요·미확인 검토·정확한 Word 링크·모바일390px 가로 넘침 없음까지 관측했다. Word 생성/다운로드는 이번 범위가 아니다.
- 후속 읽기 preview4개는 revision1/3/7/7이며 모두 sourceIds:[]이다. 기존 현재 범위 재확인 동작을 바꾸지 않았다.
- 판단/보완/Word 이후 흐름은 기존68efcbd 등 기록을 이용하고 이번에 재실행하지 않았다.
