## 변경한 동작

4H20에서 관측한 코드30 오류에도 기존 화면은 후보를 다시 검색·조회하라는 안내만 했다. 이번에는 CMMT의 지원하는 오류 형식에만 고정 안내를 붙였다. 실제 응답을 다시 조회하거나 과거 원문을 추정하지 않았다.

제품4개 파일을 변경/추가했다. 공유 transport는 기존 한도 안에서 strict UTF-8/JSON 파싱을 마친 뒤 CMMT getMeta 응답에만 제한된 판정 함수를 적용한다. 반환 body는 그대로이고 내부 boolean만 metadata 서비스가 읽는다. raw JSON/errMsg는 브라우저 응답이나 로그에 추가하지 않는다.

지원 형식은 최상위 객체의 err가 정확한 문자열30이고, 그 외 속성이 없거나 errMsg 문자열 하나만 있는 경우다. errMsg의 내용은 사용하지 않는다. 원래 JSON에서 문자열·이스케이프·중첩을 구분해 최상위 속성 수를 센 후 파싱된 키 수와 비교한다. 같은 err/errMsg가 반복되거나 이스케이프된 이름이 중복돼도 특수 안내로 승격하지 않는다. 숫자30·공백·다른 코드·별칭/충돌·추가 필드·잘못된 errMsg 타입은 기존 미확인 실패다. 이 지원 범위는 앱 정책이며 KOSIS 전체 오류 규격 보증이 아니다. 임시 진단기나 공개 코드 전체를 제품에 복사하지 않았다.

서비스는 전체 후보 재검색 대조가 성공한 뒤에만 PUBLIC_COMMENT_NO_RESULTS/HTTP502를 반환한다. 고정 문구는 다음과 같다.

> KOSIS가 이번 주석 요청에 조회결과 없음 오류를 반환했습니다. 주석 원문은 읽지 못했으며, 표 전체에 주석이 없다는 뜻은 아닙니다. 필요하면 통계표 원문에서 확인해 주세요.

오류/미수락을 유지하며 결과·주석 이관 버튼은 생기지 않는다. 정상 빈 배열은 기존 empty 응답과 별도 안내를 유지한다. TBL/PRD/SOURCE나 선행 검색의 코드30 객체에는 이 안내를 붙이지 않는다. 후보 불일치·취소·시간/용량·잘못된 UTF8/JSON은 기존 처리다.
