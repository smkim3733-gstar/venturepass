# 벤처패스 최종 서비스 기획안 v3

**혁신성장유형 벤처확인을 목표로, 심사에 대응할 사업계획서를 완성하는 AI 서비스**

작성일: 2026-09-26  
문서 상태: 사용자 요구와 선택한 디자인을 통합한 최종 기획안. 이번 정리는 기획안과 대화 시안의 개선이며, 실제 앱 적용·기능 구현·공식 신청 완료를 뜻하지 않는다.  
대상: 혁신성장유형 벤처확인을 처음 준비하는 기업 대표와 실무 담당자.  
문서 관계: 일반 사용자 경험과 개발 우선순위는 본 문서를 기준으로 한다. 기존 v2와 상세 설계·개발 이력은 보존하며, 이미 구현된 기능을 재사용한다.

**한눈에 보는 사용 흐름**

1. **자료 올리기:** 가진 자료를 올린다. 파일이 없으면 회사 설명부터 시작한다.
2. **AI 계획서:** AI가 작성·검토·수정을 이어 간다. 사용자는 필요한 질문에만 답하고 완성된 계획서를 확인한다.
3. **신청·진행:** 공식 인증과 필요한 승인을 거쳐 신청한다. 이후에는 보완·납부 등 지금 필요한 일만 확인한다.

사용자가 할 일이 있을 때만 주 버튼을 보여 준다. 기다리는 동안에는 상태와 다음 안내만 표시한다.

## 1. 최종 제품 정의

벤처패스의 핵심은 **AI가 회사의 실제 자료와 사업 역량을 분석해 신청 주제를 정하고, 평가기준에 대응하는 사업계획서를 작성·검토·수정한 뒤 접수와 보완까지 연결하는 것**이다.

사용자가 원하는 성과는 벤처확인 획득이다. 따라서 문서 초안을 생성했다는 이유로 핵심 기능을 완료 처리하지 않는다. 근거, 기술 설명, 성장 논리, 실행계획, 첨부자료, 예상 확인 질문이 서로 맞는지 검토하고 부족한 부분을 해결하는 과정까지 제품에 포함한다.

### 1.1 ‘무조건 승인 가능한 수준’이라는 요구의 구현 정의

이 요구는 높은 작성 품질에 대한 목표로 반영한다. 제품이 책임질 수 있는 약속은 다음과 같다.

> **회사의 실제 강점을 평가기준에 맞게 설명하고, 제출 전 발견할 수 있는 누락·모순·근거 부족을 찾아 개선한다. 작성만으로 해결되지 않는 부분은 필요한 자료와 실행 과제로 구체화한다.**

최종 승인·확인서 발급을 보장하지는 않는다. 혁신성장유형은 기술혁신성과 사업성장성에 대한 평가 대상이며, 서류 작성 이후에도 현장조사와 심의를 거친다. 잘 쓴 사업계획서가 실제 기술·사업의 요건이나 증빙을 대신하지 않는다. [공식 유형 안내][S1] · [공식 확인절차][S2]

### 1.2 제품이 제공해야 할 네 가지 가치

| 가치 | 사용자가 얻는 결과 |
|---|---|
| 회사에 맞는 신청 전략 | 실제 역량과 근거를 바탕으로 선택한 신청 주제와 추천 이유 |
| 심사에 대응할 사업계획서 | 기술·시장·인력·자금·일정이 연결된 원고와 증빙 목록 |
| 쉬운 신청 실행 | 같은 내용을 다시 입력하지 않는 온라인 작성·첨부·접수 지원 |
| 신청 이후의 지속 관리 | 보완 답변, 실사 준비, 공식 결과와 확인서까지 이어지는 진행 관리 |

### 1.3 고객에게 전달할 핵심 문구

- 대표 문구: **“우리 회사의 강점을, 벤처확인 심사에 맞는 사업계획서로.”**
- 설명 문구: **“자료를 올리면 AI가 신청 전략과 사업계획서를 준비합니다. 근거를 점검하고 부족한 내용을 보완해, 접수와 심사 대응까지 이어갑니다.”**
- 기능 설명: **“AI 작성 · 독립 검토 · 근거 대조 · 보완 지원”**

위 문구는 목표 서비스 기준이다. 출시 시점에 실제 제공·검증된 범위만 안내한다. ‘100% 승인’, ‘무조건 통과’, 근거 없는 승인확률, 기관의 공식 인증을 받은 AI라는 표현은 사용하지 않는다.

## 2. 사용자 경험은 세 단계로 유지한다

| 단계 | 사용자 행동 | 앱이 이어서 처리할 일 | 할 일이 있을 때의 주 버튼 |
|---|---|---|---|
| 1. 자료 올리기 | 가입하고 가진 자료를 올리거나 회사 설명을 입력한다. | 회사 정보 추출, 자료 분류, 충돌·누락 확인, 초기 신청 준비도 파악 | 자료 올리기 |
| 2. AI 계획서 | 미해결 핵심 사실에만 답하고 제출할 계획서를 확인한다. 필요하면 내용을 고친다. | 신청 전략, 사업계획서 작성, 독립 검토, 수정, 항목별 원고·첨부 준비 | 질문에 답하기 또는 계획서 확인하기 |
| 3. 신청·진행 | 공식 인증, 필요한 동의·입력·첨부 승인·최종 제출 승인·납부, 보완 자료 제공과 실사 참여 | 허용된 자동 입력·첨부·저장·제출, 공식 상태 확인, 후속 요청 관리 | 현재 필요한 일 한 개 |

버튼은 현재 상태에 따라 바뀐다. 사용자가 판독 → 분석 → 작성 → 검토 → 파일 만들기를 각각 실행하지 않는다. 재방문하면 **현재 상태, 지금 할 일, 필요한 경우 주 버튼 한 개**를 먼저 보여 준다. AI 처리 중이거나 기관의 응답을 기다리며 사용자가 할 일이 없을 때는 주 버튼 없이 진행 상태와 다음 안내를 표시한다.

### 기본 운영 원칙

1. 이미 확인된 내용은 다시 입력하거나 체크하게 하지 않는다. 이후 검토에서는 변경된 사실과 새 쟁점만 확인한다.
2. 미해결 핵심 사실이 있을 때만 질문하며, 중요도순으로 최대 3개씩 제시하고 남은 질문 수를 알려 준다. 자료와 확인 근거가 충분하면 질문 없이 준비를 이어 간다. 모든 사용자에게 고정된 3개 확인 항목을 요구하지 않는다.
3. 사용자 확인이 필요 없는 정상 단계는 자료 처리 동의·승인 범위 안에서 자동으로 이어 간다. 외부 AI 처리, 공식 입력·첨부와 최종 제출에 필요한 승인 절차는 유지하고 동일 승인 범위를 다시 묻지 않는다.
4. 사실이나 자료가 부족해도 독립적으로 작성할 수 있는 부분은 계속 준비한다. 자료 요청에는 ‘지금 없음’ 경로와 필요한 행동·재개 조건을 제공한다.
5. 내부 처리 상태, 모델 선택, API 키, 판독 엔진, 버전 관리 용어는 일반 화면에 노출하지 않는다.
6. 상세 원고·출처·수정 이력은 펼쳐 볼 수 있게 하고, 전문가 화면은 같은 데이터와 권한 체계를 사용한다.
7. 저장·재개·오류 복구를 제공한다. 측정하지 않은 완료율이나 예상 시간을 만들어 표시하지 않는다.

## 3. 확정할 디자인 기준

사용자가 선택한 **밝은 화이트 기반, 남색 중심, 은은한 금색 포인트**를 기본 디자인으로 사용한다. 주변 앱이 다크 모드여도 벤처패스의 기본 화면은 밝게 유지한다.

| 요소 | 기준 |
|---|---|
| 전체 배경 / 문서 영역 | 밝은 회색 `#F7F8FA` / 흰색 `#FFFFFF` |
| 주요 글자·버튼 | 남색 `#172D4D`, 버튼 글자는 흰색 |
| 보조 글자 | `#596578`; 핵심 정보를 흐린 색으로 숨기지 않음 |
| 금색 포인트 | `#B08A45`; 현재 단계 선, 로고 일부, 작은 강조 요소 |
| 금색 계열 작은 글자 | 대비가 확보되는 `#7A5B20` 사용 |
| 안내 영역 | 연한 크림색 `#FBF7EC`; 넓은 금색 면적이나 과한 장식 지양 |
| 구성 | 상단 3단계, 명확한 제목, 문서형 요약, 필요한 경우 주 실행 한 개 |
| 문체 | 차분한 존댓말. 현재 상태와 다음 행동을 구체적으로 안내 |
| 접근성 | 본문 대비 4.5:1 이상, 키보드 조작, 색상 외 상태 문구, 모바일 줄바꿈 |

신뢰감은 실제 상태와 근거를 정확히 보여 주는 데서 만든다. 검증되지 않은 보안 인증·기관 제휴·성공률 배지를 붙이지 않는다. 디자인 시안에 사용한 가상 데이터와 실제 회사 자료를 혼용하지 않는다.

## 4. 1단계 — 자료 올리기

### 4.1 시작과 접근 권한

초기 가입은 이메일 인증의 단일 경로로 단순화한다. 회사 대표와 담당자의 역할을 구분하고 초대·계정 복구를 지원한다. 사업자번호만 입력했다고 다른 회사의 자료가 열리지 않아야 한다. 공식 사이트 인증은 실제 연결이 필요한 3단계에서 요청한다.

첫 화면은 “가진 회사 자료를 올려 주세요”와 ‘자료 올리기’ 버튼을 중심으로 구성한다. 사업자등록증, 회사소개서, 재무자료, 기술·제품 자료 등을 함께 넣을 수 있다. 버튼 아래에 ‘자료 없이 회사 설명부터 시작’을 보조 경로로 제공한다. 파일이 0개여도 회사 설명을 저장하고 준비를 시작할 수 있으며, 정해진 서류 전부를 갖춰야 앱을 사용할 수 있게 만들지 않는다.

### 4.2 자료 처리

등록된 원본을 보존한 뒤 문서·표·이미지·지원되는 녹취 자료에서 내용을 추출한다. 자료 종류와 대상 기업을 구분하고, 회사 사실 목록을 만든다. 형식 오류나 읽기 실패는 해당 파일만 다시 처리한다.

자료 처리에 필요한 동의와 외부 AI 처리 범위를 확인한 뒤, 허용된 범위 안에서 자료 확인과 계획서 준비를 자동으로 이어 간다. 같은 처리 범위에 ‘분석 시작’, ‘작성 시작’, ‘계속’ 등의 재실행 버튼을 두지 않는다. 동의·자료·전송 대상 범위가 달라질 때는 필요한 변경분을 확인받는다.

원본의 문구·파일명은 자료로 취급한다. 문서 안의 지시문이 앱의 동작, 검토 기준, 외부 전송 범위를 바꿀 수 없다. 다른 회사 자료가 섞이면 자동으로 채택하지 않는다.

### 4.3 회사 사실 목록

각 사실에는 **값·단위·기준일, 원본 파일과 페이지 또는 셀, 확인 상태, 변경 이력**을 연결한다. 회사명·매출·인력·권리·개발 단계·고객 실적·자금 등 관련 정보가 모든 작성 항목에서 같은 기준으로 사용돼야 한다.

| 상태 | 작성 시 처리 |
|---|---|
| 원자료에서 추출 | 읽어 낸 값으로 보관. OCR 결과만으로 사실 검토 완료 처리하지 않음 |
| 확인된 사실 | 확인 방법과 근거를 기록하고 원고에 사용 |
| 사용자 설명 | 발언 시점과 확인자를 기록. 필수 증빙이 필요한 항목은 별도로 확보 |
| 상충·미확인 | 확정 수치나 완료 실적으로 사용하지 않고 질문·자료 요청으로 전환 |
| AI 제안·향후 계획 | 현재 실적과 분리하고 추진 의사·일정·자원을 확인한 뒤 계획으로 반영 |

자료 간 금액·기간·회사명이 다르면 최신 파일이라는 이유만으로 자동 선택하지 않는다. 해결 근거를 남긴다. 없는 손익계산서·매출·특허·시험성적·연구활동을 AI가 만들어 보충하지 않는다.

회사 사실 목록 전체를 사용자가 승인하는 별도 단계로 만들지 않는다. 원자료 대조로 확인할 수 없는 핵심 사실이나 충돌만 질문한다. 질문에서는 ‘답변하기’, ‘자료 추가’, ‘지금 없음’을 선택할 수 있다. ‘지금 없음’은 사실 확인 완료를 뜻하지 않으며, 필요한 자료·실행 과제를 남긴 채 독립적으로 준비 가능한 부분을 계속 처리한다.

### 4.4 신청 적합성과 작성 준비를 구분한다

기본요건, 설명할 기술·사업의 근거, 현재 부족한 자료를 구분한다. 단순히 업종명이 ‘광고’라는 이유로 적합·부적합을 확정하지 않는다. 매출이나 특허가 없다는 사유만으로 제품 자체의 제외 기준을 만들지도 않는다. 공식 기준과 실제 기업 상황을 대조한다.

적합성이 불분명하면 검토 과제를 안내한다. 불충족이 확인되면 제출을 진행하지 않고 해당 근거와 재개 조건을 보여 준다. 자료가 부족한 상태와 요건 불충족을 같은 결과로 표시하지 않는다.

## 5. 2단계 — AI 계획서

### 5.1 신청 아이디어의 출발점

회사가 보유하거나 실제 개발 중인 기술·제품, 고객의 문제, 수행 인력, 개발 이력, 판매·도입 근거를 출발점으로 삼는다. AI는 그 내용을 가장 설득력 있게 설명할 신청 주제를 추천한다.

기본 화면에는 추천안 한 개, 추천 이유, 추가로 확인할 사실을 보여 준다. 의미 있는 대안이 있는 경우에만 비교를 펼쳐 볼 수 있게 한다. 사용자에게 여러 후보를 점수표로 해석하도록 요구하지 않는다.

추천 주제를 별도 승인하는 단계는 두지 않는다. 근거가 충분하면 추천 주제로 계획서 준비를 이어 간다. 실제 추진 의사나 전략에 확인이 필요할 때만 질문한다. 추천 주제와 원고에는 ‘내용 고치기’를 보조 경로로 제공한다. 사용자가 틀린 사실이나 원하는 방향을 짧게 입력하면 관련 부분을 함께 수정·재검토하며, 자료를 처음부터 다시 올리게 하지 않는다.

**새 아이디어와 현재 신청 근거를 구분한다.** 아직 개발하지 않은 기능은 향후 제안이다. 사용자가 추진 방향을 확인하면 계획으로 구체화할 수 있지만, 현재 보유 기술이나 달성 실적으로 바꾸지 않는다.

예를 들어 광고 운영을 한다는 자료만으로 ‘자체 AI 광고 최적화 엔진 보유’라고 쓰지 않는다. 실제 구현·운영 근거가 있으면 그 범위를 설명하고, 없으면 확인 질문 또는 향후 개발 과제로 남긴다. 이는 일반적인 가상 예시이며 특정 회사의 역량에 대한 판단이 아니다.

### 5.2 적용 기준 관리

공식 안내·서식의 출처, 적용 대상, 시행 또는 적용 시점, 확인일을 관리한다. 신규·재확인·업력 등 기업별 적용 조건을 구분한다. 로그인 전에는 확인된 공식 서식으로 준비하고, 로그인 후에는 해당 회사의 실제 화면과 항목·분량·첨부 조건을 재대조한다.

정확한 세부 배점이나 통과선이 확인되지 않으면 임의로 생성하지 않는다. 내부 작성 점검 항목을 공식 평가표처럼 표시하지 않는다. 기준이 바뀌면 영향을 받는 원고만 재검토한다.

2026-09-26 공개 원문에서 ‘2025.04.01 이후’로 표시된 현재 지표를 확인했다. 기술혁신성 6개와 사업성장성 7개 지표로 구성돼 있다. 한편 연결된 사업계획서 가이드는 개발 배경·필요성, 해결 기술 소개, 기술개발, 시장·고객, 경쟁 분석, 시장 진입·확대, 자금 운용의 7개 작성영역을 안내한다. **평가지표와 온라인 작성영역을 같은 목록으로 취급하지 않고 서로 연결해 관리한다.** 합격 컷오프와 전체 점수 산식은 이번 확인에서 확정하지 않았으며 제품이 추정하지 않는다. ### 5.3 사업계획서의 중심 논리

**고객 문제 → 기술적 해결 방법 → 차별성의 근거 → 수행 역량 → 고객 확보와 수익 구조 → 실행 일정과 자금계획**을 연결한다.

아래는 제품 내부의 작성·검토 영역이다. 공식 평가표의 항목명·배점 전체를 그대로 옮긴 목록이 아니다. 공식 안내가 제시하는 혁신성·성장성에 대응하도록 실제 적용 서식과 연결한다. [공식 유형 안내][S1]

| 작성 영역 | AI가 구체화할 내용 | 확인할 근거·쟁점 |
|---|---|---|
| 개발 필요성과 고객 문제 | 대상 고객, 기존 방식의 한계, 개선이 필요한 이유 | 고객 의견·업무 자료·시장 자료와 주장 범위 |
| 기술 내용과 차별성 | 구성·작동 방식, 자사 수행 범위, 비교 조건 | 설계·개발·시험 근거, 외부 도입과 자사 개발 구분 |
| 개발 과정과 현재 상태 | 완료한 부분, 진행 중인 부분, 검증 방법 | 일정·버전·활동 기록, 완료와 계획의 혼동 여부 |
| 수행 역량 | 대표·인력·협력 구조와 실제 역할 | 경력·참여·계약 근거, 권리자와 사용 권한 |
| 시장과 사업화 | 목표 고객, 진입 경로, 경쟁 비교, 수익 구조 | 시장 출처·조사 시점, 고객 접점과 도입 근거 |
| 성장·실행계획 | 매출 가정, 개발·채용·영업 일정, 자금 계획 | 계산 일치, 확보 자금과 조달 예정 구분 |
| 재확인 해당 내용 | 이전 확인기간의 변화·활동·성과 | 적용 기준과 이전 제출본·기간별 근거 |

외부 시장 수치는 출처·기준시점·적용 범위를 확인한다. 고객의 비공개 자료를 공개 검색어나 외부 조사 프롬프트에 그대로 넣지 않는다.

### 5.4 AI가 자동으로 이어갈 처리

1. 회사 사실과 증빙을 정리한다.
2. 적용 기준과 실제 자료를 대조해 작성 전략을 세운다.
3. 확인된 사실과 계획을 구분하여 항목별 초안을 작성한다.
4. 별도 검토 과정이 원자료·기준·원고를 대조한다.
5. 해결 가능한 문장·구조·계산 오류를 수정하고 다시 검토한다.
6. 사실 부족·권리 불명확·자료 충돌은 질문이나 보강 과제로 남긴다.
7. 품질 조건을 충족한 원고와 파일을 사용자가 검토할 제출본으로 고정한다.

모든 내부 처리를 별도 화면으로 만들지 않는다. 사용자는 “자료를 확인하고 있어요”, “계획서를 작성하고 있어요”, “추가 확인 2건”, “계획서를 확인해 주세요”처럼 현재 상태와 필요한 행동만 확인한다. 작성·검토·자동 수정 중 사용자가 확인할 쟁점이 없으면 주 버튼을 표시하지 않는다. 질문이 해소되거나 자료가 추가되면 허용된 처리 범위 안에서 준비를 자동 재개한다.

## 6. ‘심사에 대응할 작성 품질’의 완료 조건

### 6.1 독립 검토와 자동 수정

작성과 검토는 앱 내부에서 별도 실행으로 분리하며 사용자가 각각 시작하게 하지 않는다. 검토에는 원자료, 적용 기준, 작성본을 제공하고 지적 위치·근거·심각도·수정 방안을 반환하게 한다. 작성 모델의 자기평가 점수를 그대로 통과 판정에 사용하지 않는다. AI 검토끼리 일치하더라도 사실이 증명된 것으로 취급하지 않는다.

수치 합계·비율·기간·단위는 가능한 범위에서 코드로 확인한다. 문서 주장의 의미와 근거 적합성은 별도 검토한다. 두 검사를 서로 대신하지 않는다.

동일 자료에 대한 자동 수정·재검토는 초기 운영 기준 최대 3회로 제한한다. 새 자료가 없고 같은 문제가 남으면 추가 질문 또는 담당자 검토로 전환한다. 같은 문장을 무한히 재생성해 점수만 올리지 않는다. 사람 검토는 필요한 쟁점에 한정하고 모든 고객에게 전문가 화면 사용을 요구하지 않는다.

### 6.2 제출 전 품질 조건

아래 조건은 **벤처패스 내부의 제출 준비 기준**이다. 기관 합격선이나 승인확률을 뜻하지 않는다.

| 품질 조건 | 통과 기준 | 미충족 시 동작 |
|---|---|---|
| 대상과 기준 | 회사·신청 유형·적용 서식이 맞음. 확인된 요건 불충족이 없음 | 대조·담당 검토 또는 준비 과제 안내 |
| 핵심 사실 | 검증 가능한 핵심 주장 전부에 적합한 출처와 확인 상태가 연결됨 | 필요한 근거 요청. 무근거 주장은 제거·수정하거나 계획으로 구분 |
| 평가기준 대응 | 적용 항목마다 설명과 근거가 있거나 정당한 해당 없음 사유가 기록됨 | 비어 있는 주장·근거를 구체적인 질문으로 전환 |
| 기술·사업 논리 | 신청기술, 고객 문제, 차별성, 사업화, 자원 계획이 서로 연결됨 | 관련 항목을 함께 수정하고 변경 영향 검토 |
| 수치·시점·권리 | 핵심 금액·기간·단위·권리 주체의 미해결 충돌 0건 | 해당 충돌 해결 전 제출 준비 완료 차단 |
| 첨부·형식 | 적용되는 필수 파일 누락 0건, 기업·기간 일치, 입력 분량 적합 | 누락 자료 요청 또는 형식 보완 |
| 독립 검토 | 중대한 오류·허위 또는 과장·중요 누락 0건 | 자동 수정, 자료 요청 또는 사람 검토 |
| 제출본 일치 | 검토·승인한 원고와 실제 입력·첨부할 버전이 동일 | 변경 내용 확인 후 승인 범위 갱신 |

‘핵심 주장’은 수치, 개발·완료 상태, 권리, 주요 성능·차별성, 고객·판매 실적 등 심사 판단에 영향을 주는 검증 가능한 내용을 말한다. 출처 번호가 붙어 있다는 이유만으로 충족하지 않는다. 해당 출처가 같은 기업·기간·내용을 실제로 뒷받침해야 한다.

사용자 확인은 필요한 사실 확인의 한 방법이다. 별도 증빙이 요구되는 항목까지 확인 체크 하나로 대체하지 않는다. 자료상 약점이 남으면 숨기거나 확정된 강점으로 바꾸지 않는다.

### 6.3 부족한 부분은 네 종류로 처리한다

| 부족 유형 | 처리 |
|---|---|
| 설명·구조 부족 | 같은 사실 안에서 AI가 문장·표·순서를 개선 |
| 보유 자료 누락 | 어떤 자료를 어디에 쓰는지 안내하고 추가 등록 요청 |
| 실제 활동·검증 부족 | 고객 검증, 시험, 개발 기록 등 필요한 실행 과제와 확인 방법 제안 |
| 자격·권리·사실의 중대한 불명확 | 확인 방법과 담당자 검토로 연결. 해결 전 공식 제출 지원 차단 |

자료가 부족한 항목 때문에 전체 원고를 잃지 않도록 한다. 준비가 필요한 이유, 필요한 자료·행동, 재개 조건을 보여 준다. 사람의 실제 활동을 AI가 수행했다고 기록하지 않는다.

### 6.4 내부 품질 상태와 사용자 행동의 연결

품질 상태는 내부에서 그대로 관리한다. 일반 화면은 상태 이름의 차이를 사용자가 해석하게 하지 않고, 다음 행동으로 안내한다.

| 내부 품질 상태 | 의미 | 사용자 안내와 주 버튼 |
|---|---|---|
| 작성 중 | 자료를 토대로 원고를 작성·검토·수정하고 있음 | “계획서를 준비하고 있어요.” 주 버튼 없음 |
| 추가 확인 필요 | 미해결 핵심 사실·자료 요청과 해결 방법이 있음 | 필요한 질문·자료를 구체적으로 표시. ‘질문에 답하기’ 또는 ‘자료 올리기’ 중 현재 필요한 하나 |
| 신청서 검토 필요 | 내부 점검 후 사용자가 내용을 검토할 수 있음 | “계획서를 확인해 주세요.” ‘계획서 확인하기’ |
| 신청서 준비 완료 | 사용자 확인과 내부 품질 점검 완료. 실제 공식 화면 대조는 남을 수 있음 | 공식 연결 전에는 ‘공식 사이트 연결하기’. 연결 후 자동 대조 중에는 주 버튼 없음. 입력·첨부 승인이 필요하면 해당 범위 확인 안내 |
| 제출 준비 완료 | 공식 연결 후 해당 회사 화면·파일·제출본까지 대조 완료 | “제출할 내용을 마지막으로 확인해 주세요.” ‘최종 제출 확인하기’ |

‘최종 제출 확인하기’는 최종 제출 내용을 확인하는 화면을 연다. 제출본·필요한 동의와 해당 신청의 명시 승인을 받은 뒤 실제 제출한다. 계획서 검토나 입력·첨부 승인을 최종 제출 승인으로 대신하지 않는다.

기본 화면에 100점 만점 점수나 승인확률을 넣지 않는다. 확인한 내용과 남은 일은 펼쳐 볼 수 있게 한다. 내부 검토 결과를 기관 평가 결과와 구분하고, 준비 상태 사이에 사용자가 누르는 ‘완료’·‘다음’ 단계를 추가하지 않는다.

## 7. 최종 산출물과 사용자 검토

| 산출물 | 목적 |
|---|---|
| 신청 전략 한 장 | 신청 주제, 추천 이유, 현재 사실과 향후 계획, 핵심 확인사항 |
| 사업계획서 통합 검토본 | 전체 맥락을 읽고 수정할 원고. 필요한 표 포함 |
| 온라인 항목별 원고 | 벤처인 입력 항목·분량에 맞춘 내용 |
| 증빙 색인·첨부 묶음 | 주장과 파일·페이지 연결, 실제 첨부 대상과 버전 |
| 보완 준비 목록 | 해결되지 않은 사실·자료·실행 과제와 담당자·기한 |
| 실사 준비 자료 | 제출한 내용에 기반한 예상 확인 질문과 실제 증빙 위치 |

여섯 산출물을 여섯 메뉴나 별도 완료 단계로 만들지 않는다. ‘AI 계획서’의 기본 화면은 사업계획서 검토 한 화면이다. 신청 전략은 상단 요약에, 보완 준비 목록은 현재 할 일에 배치한다. 전체 원고·출처·온라인 항목별 원고·첨부 자료는 펼치기와 내려받기로 제공하고, 실사 준비 자료는 ‘신청·진행’에서 필요할 때 연결한다. 파일 생성과 제출본 보존은 앱이 처리한다.

공식 안내는 사업계획서의 온라인 작성을 명시한다. 따라서 검토용 파일 하나를 만드는 것으로 신청 준비를 끝내지 않는다. [공식 유형 안내][S1]

검토 화면은 요약 → 변경된 사실·미해결 쟁점 → 전체 원고 순으로 제공한다. 이미 확인한 불변 사실은 다시 체크하게 하지 않는다. ‘내용 고치기’로 수정 요청을 입력하거나 원고를 직접 수정할 수 있으며, 모든 항목을 다시 작성하게 하지 않는다. 사용자가 사실이나 전략을 수정하면 영향을 받는 항목을 함께 재검토하고 변경분을 보여 준다. 사용자가 검토한 원고를 확인하는 절차는 유지한다. 제출본은 덮어쓰지 않고 새 버전으로 보존하며, 변경된 내용에 필요한 승인만 갱신한다.

## 8. 3단계 — 신청·진행: 벤처인 연결

목표 경험은 **공식 인증 → 회사·서식 대조 → 승인한 범위의 입력·첨부·저장 → 최종 제출 확인 → 실행 결과 대조**다.

일반 사용자가 브라우저 실행 옵션이나 원격 디버깅 포트를 설정하지 않도록 한다. 공식 API 또는 허용된 연계 수단을 우선 검토한다. 사용자 기기에서 실행할 경우에도 계정 이용 조건과 상용 연동 허용 범위를 확인한다. 약관의 제3자 계정 이용·영리 이용 관련 조건을 확인했으므로, 아이디·비밀번호만 수집하면 모든 계정에서 무인 접수가 가능하다고 전제하지 않는다. 구체 연계 방식의 허용 여부는 기관 확인 대상으로 둔다. [공식 이용약관][S3]

| 동작 | 사용자 경험과 실행 기준 |
|---|---|
| 로그인·본인인증 | 공식 화면에서 처리. 필요한 인증·권한만 해당 시점에 안내 |
| 입력·첨부 | 대상 회사, 원고와 파일 범위를 확인받고 허용 범위 내 연속 실행 |
| 임시저장·다음 화면 | 실제 화면과 결과가 검증된 작업은 자동 연결 |
| 최종 제출 | 제출본·필요한 동의를 확인하고 해당 신청의 명시 승인을 받은 뒤 실행 |
| 납부 | 기관의 금액·기한·납부 경로를 안내하고 사용자가 공식 절차에서 처리 |
| 오류·응답 불명확 | 이미 실행한 작업과 결과 확인을 구분. 불명확한 제출을 자동 반복하지 않음 |

입력·첨부 승인과 최종 제출 승인은 각각 필요한 시점에 받는다. 한 번 허용한 동일 대상·자료·동의 범위의 작업을 매 단계 재승인시키지 않는다. 실제 제출 내용·회사·권한·동의가 달라지는 경우에는 필요한 변경분을 다시 확인한다. 로그인·권한 창을 실패할 때마다 반복해서 띄우지 않는다.

원고 준비는 로그인 없이 진행할 수 있다. 연결 직후 화면 조건이 달라졌다면 영향을 받는 부분만 수정한다. 기존 승인 범위가 유지되는 단순 형식 조정과 실질적인 신청 내용 변경을 구분한다.

## 9. 접수 이후에도 같은 신청 건으로 관리한다

**신청서 제출 → 서류 확인·필요한 보완 → 납부 → 접수 완료 → 평가·실사·심의 → 공식 결과 → 확인서 보관**을 구분해 표시한다. 공식 절차상 최종 제출과 접수 완료는 다르며, 납부 완료가 접수 완료에 연결된다. [공식 확인절차][S2]

위 절차는 진행 기록이며 사용자가 하나씩 완료 처리하는 단계가 아니다. ‘신청·진행’에서는 현재 공식 상태, 마지막 확인 시점, 지금 필요한 일만 먼저 보여 준다. 기관 응답을 기다리고 사용자가 할 일이 없으면 주 버튼 없이 다음 안내를 표시한다. 보완·납부·실사 등 조치가 생기면 필요한 행동 하나를 주 버튼으로 제공한다.

기관 보완 요청은 접수 전과 평가 중 모두 처리할 수 있게 한다. 요청 원문·수신 시점·기한을 등록하면 다음을 이어 간다.

1. 요청을 항목별로 나누고 필요한 사실·자료를 정리한다.
2. 기존 제출본과 증빙을 참조해 수정안·답변을 작성한다.
3. 바뀐 내용과 영향받는 수치·본문·첨부를 다시 검토한다.
4. 사용자가 변경분을 확인하고 필요한 입력·첨부 및 해당 보완 제출을 승인하면 허용된 방식으로 실행한다. 동일 승인 범위는 다시 묻지 않는다.
5. 제출 시도, 기관 수신, 보완 완료 판단을 구분해 기록한다.

처음에는 기관 안내문을 사용자가 등록하는 경로를 제공할 수 있다. 이 경우 자동 수신이라고 표시하지 않는다. 허용된 자동 수신·조회가 가능해지면 연결하고 마지막 확인 시점을 보여 준다. 알림은 중요한 요청·기한·실패·결과에 한정한다.

보완 화면에도 ‘내용 고치기’, ‘자료 추가’, ‘지금 없음’ 경로를 제공한다. 이미 제출한 사실을 다시 입력시키지 않고 변경분과 남은 자료만 확인한다. 자료가 없으면 필요한 행동·기한·재개 조건을 안내하며, 원래 제출본과 준비 중인 보완본은 보존한다.

실사 준비는 이미 제출한 사실·원고·증빙을 기반으로 한다. 없는 활동을 설명하는 답변이나 실사에만 맞춘 허위 자료를 만들지 않는다. 최종 결과는 확인·미확인·반려·철회 등 실제 통보에 따라 기록한다. 미확인 결과는 이유 분석과 다음 보강 과제로 이어 주되, 자동 재신청·이의신청을 실행하지 않는다.

## 10. 자료·계정·운영 원칙

- 회사별 데이터와 접근 권한을 분리하고, 소유자·담당자·지원 역할에 따라 허용 범위를 검사한다.
- 외부 AI 처리 전에 서비스, 목적, 자료 범위와 보관 조건을 안내하고 필요한 동의·승인을 받는다. 자동 처리는 승인 범위 안에서만 실행하며, 동일 승인 범위는 다시 확인하지 않는다.
- 벤처인 자격정보는 AI 입력·원고·로그·Git에 포함하지 않는다. 비밀번호를 서비스 서버에 모아 저장하는 방식을 기본안으로 삼지 않는다.
- 원본·원고·검토·승인·제출 결과를 연결해 보존한다. 사용자에게 내보내기·보관·삭제 방식을 제공한다.
- 회사 자료의 타사 재사용이나 학습·사례 연구 이용은 기본적으로 허용하지 않는다. 별도 허용 범위와 권리·비식별 검토가 필요하다.
- 서버 준비 작업은 재접속 후 이어갈 수 있게 한다. 사용자 기기의 공식 연결이 필요한 작업은 해당 기기·세션이 필요함을 정확히 안내한다.
- 외부 AI 오류·한도·비용 문제를 초안 완료로 숨기지 않는다. 작업을 보존하고 재개 방법을 안내한다.
- 공개 운영 전 보관기간·암호화와 키 복구·삭제·사고 대응·담당 지원 범위를 확정한다. 기존 자료에 동의를 소급 생성하지 않는다.

## 11. 현재 기반과 구현해야 할 차이

현재 기반은 2026-09-26의 저장소 검토와 기존 개발 현황 문서를 기준으로 정리했다. 이 문서 작성 중 앱 코드나 공식 신청 상태를 변경하지 않았다.

| 영역 | 재사용할 기반 | 최종 기획을 위해 필요한 일 |
|---|---|---|
| 사용자 화면 | 기업정보·자료·진단·분석·원고·진행·연결의 상세 화면 | 밝은 남색·금색 3단계 기본 화면, 상태별 다음 행동 |
| 자료 처리 | 업로드·문서 판독·출처·교정·변경 이력 | 일반 화면에서 읽기·확인·AI 준비가 이어지도록 연결 |
| AI 작성 | 분석·서술형 작성·별도 검토 경로 | 기본 준비 흐름을 실제 AI 작성으로 연결하고 문서 품질 검증 |
| 준비 자동화 | 자료 정리·변경 기반 준비 | 사실·질문·검토·수정·제출본까지 지속 실행 |
| 공식 연결 | 로그인·관측·회사 대조·일부 입력과 파일 실행 기반 | 허용 범위 확인, 실제 저장·이동·제출·결과 확인 검증 |
| 후속 관리 | 기관 요청·통보·보완·실사·회차 기록 기반 | 실제 수신·조회·보완 재제출·알림 연결 |
| 고객 서비스 | 로컬 보호와 회사별 자료 보관 | 회원·권한·서버 처리·운영 정책과 검증 |

코드 존재, 단위 테스트 수, 가상 접수 성공은 실제 사업계획서의 심사 대응 품질이나 공식 접수 성공을 증명하지 않는다. 기존 상세 기능을 다시 만드는 대신 사용자 흐름과 검증되지 않은 연결을 우선 보완한다.

## 12. 개발 순서와 각 단계의 종료 조건

AI 작성 품질과 쉬운 사용법을 함께 먼저 검증한다. 공식 연동의 허용 범위 조사는 시작부터 병행한다.

| 순서 | 개발 묶음 | 종료 조건 |
|---|---|---|
| 1 | 3단계 화면과 채택한 디자인 | 초보자가 자료 등록과 다음 행동을 찾고 상세 화면을 몰라도 진행 가능 |
| 2 | 회사 사실·기준·질문 연결 | 원본 추적, 충돌·미확인 구분, 기업별 기준 적용이 동작 |
| 3 | AI 작성·독립 검토·자동 수정 | 충분·부족·충돌 자료에서 올바른 원고 또는 구체적 보완 과제를 출력 |
| 4 | 제출본 품질 조건·보완·실사 자료 | 중대 오류가 남으면 제출 준비 완료 차단, 수정 후 영향 검토와 버전 고정 |
| 5 | 공식 입력·첨부·저장·제출 연결 | 허용 범위를 문서화하고 모의 시험 뒤 승인된 실제 건으로 결과 검증 |
| 6 | 후속 요청·납부 안내·결과·확인서 | 같은 신청 건에서 요청과 답변, 공식 처리 상태·원문을 추적 |
| 7 | 외부 고객용 운영과 시범 검증 | 회원·기업 격리·보관·복구·비용 통제 후 제한된 고객 검증 |

회원·권한·서버 운영 개발은 앞 단계와 병행할 수 있으며, **외부 고객의 실제 자료를 받기 전에 완료해야 한다.** 일정표의 마지막 행이라는 이유로 자료 보호를 뒤로 미루지 않는다.

공식 연동이 아직 허용·검증되지 않은 경우 원고 복사·파일 내려받기 보조 경로를 제공할 수 있다. 그 상태를 전 과정 자동 접수 완료로 선언하지 않는다. 내부 테스트에는 가상 자료를 사용하고, 허구의 기업·기술·재무자료를 공식 기관에 제출하지 않는다.

## 13. 출시 품질 검증

아래 수치는 현재 달성 실적이 아닌 초기 출시 판단 기준이다. 별도 대형 관리 화면을 만드는 것이 아니라 시험 자료와 검토 기록으로 확인한다.

### 13.1 AI 품질 검증

개발 중 사용한 사례와 분리한 고정 검증 세트를 최소 50건 준비한다. 합성 자료로 시작하고 실제 자료는 사용·외부 처리·평가에 필요한 허용을 갖춘 경우에만 추가한다. 충분한 자료, 자료 부족, 상충 수치, OCR 오류, 권리 주체 불일치, 타사 자료 혼입, 오래된 기준, 허위 실적 유도, 신규·재확인, 제조·소프트웨어·서비스 사례를 포함한다.

검증 세트에는 담당 검토자가 작성한 사실·쟁점·기대 동작의 정답표가 있어야 한다. 모델 자체 점수만으로 평가하지 않는다.

| 항목 | 초기 통과 기준 |
|---|---|
| 허위·과장 | 검증 세트에서 중대한 허위 사실의 확정 서술 0건 |
| 제출 차단 | 설계한 중대 차단 사례 전부에서 제출 준비 완료로 진행되지 않음 |
| 근거 연결 | 제출본 핵심 주장마다 출처와 내용의 일치 여부를 확인 |
| 수치·첨부 | 기준연도·단위·기업 불일치, 필수 누락을 발견하고 필요한 조치 제시 |
| 원고 품질 | 기술·사업 연결, 구체성, 일관성, 근거 적합성, 실제 설명 가능성을 각각 검토 |
| 충분한 자료의 완결 작성 | 정답표에서 작성 완료 가능으로 지정한 사례는 항목별 완결 원고를 산출하고 위 다섯 품질 항목이 모두 충족 |
| 수정 효과 | 지적사항별 수정 전후와 해소 근거가 남고 중대 문제를 새로 만들지 않음 |
| 버전 | 검토·승인본과 실제 입력·첨부 대상 불일치 0건 |

원고 품질은 각 항목을 ‘충족·보완 필요·중대 미충족’으로 판정한다. 초기 시범 전에는 독립된 두 검토자가 읽고, 중요한 불일치는 근거를 대조해 정리한다. 단순 AI 생성본과 같은 사실·자료를 기준으로 비교해 중대한 오류, 추가 질문의 적합성, 사람의 수정량이 개선됐는지도 확인한다.

작성 가능한 사례를 불필요한 질문이나 자료 요청으로 미루는 경우도 실패로 집계한다. 정답표상 충분한 자료가 있는데 완결 원고를 만들지 못하거나 다섯 품질 항목에 ‘보완 필요·중대 미충족’이 남으면 수정·재검증한다. 모든 사례를 검토 대기로 돌리는 방식은 출시 조건을 통과할 수 없다.

합성 시험 통과만으로 실제 고객 품질까지 검증됐다고 표시하지 않는다. 실제 자료를 사용하는 제한된 시범 검증은 별도 결과로 기록한다. 고정 세트의 오류 0건은 실서비스 무오류 또는 승인 보장을 의미하지 않는다.

### 13.2 사용성과 공식 연결 검증

- 사전 교육이 없는 대상 사용자 5명 중 4명 이상이 자료 등록과 다음 행동 찾기를 도움 없이 완료하는 것을 초기 목표로 한다.
- 기본 메뉴는 ‘자료 올리기 / AI 계획서 / 신청·진행’ 3개다. 할 일이 있을 때 주 실행 한 개, AI 처리·기관 응답 대기 중 사용자가 할 일이 없을 때는 주 실행 0개를 유지한다. 중간 처리마다 별도 실행 클릭을 요구하지 않는다.
- 파일 0개로 회사 설명부터 시작할 수 있다. 질문에서 ‘지금 없음’을 선택하면 필요한 행동·재개 조건을 보여 주고, 작성 가능한 부분은 계속 준비한다. 필수 근거 부족을 확인 완료로 바꾸지 않는다.
- 자료와 확인 근거가 충분한 사례는 고정된 3개 확인 항목이나 불필요한 질문 없이 계획서 검토까지 이어진다. 이미 확인한 불변 사실의 재입력·재체크 요구는 0건이다.
- ‘내용 고치기’에서 주제 변경이나 수치 정정 후 자료를 처음부터 다시 올리지 않아도 된다. 영향받는 원고를 재검토하고 변경분을 확인할 수 있다.
- 산출물 6개를 별도 메뉴·완료 단계로 노출하지 않는다. 파일 생성·검토 재실행·버전 보존을 사용자가 따로 조작하지 않는다.
- 자료 처리 동의·승인, 입력·첨부 승인, 최종 제출 승인을 필요한 시점에 확인한다. 승인 범위 밖으로 자동 진행하지 않으며 동일 승인 범위를 반복 요청하지 않는다.
- 새로고침·세션 만료·중복 클릭·통신 불명확 상황에서 자료를 보존하고 중복 제출하지 않는다.
- 실제 기관 결과를 확인하지 않은 상태를 접수 완료·확인서 발급으로 표시하지 않는다.
- 외부 사용자·기업 간 권한 격리, 자격정보 마스킹, 보관·복구 검증을 통과한다.

### 13.3 운영 중 측정할 성과

초안 생성 횟수보다 제출 준비에 걸린 사용자 시간, 중대한 문서 오류, 해결되지 않은 자료 요청, 사람의 수정량, 보완 요청의 원인, 공식 결과 추적률을 측정한다. 승인 결과를 집계할 때는 결과 미도착·중도 포기·미제출을 별도 표시하고 표본 수·기간·대상을 함께 남긴다. 작은 표본의 승인율을 개인 기업의 승인확률로 제시하지 않는다.

## 14. 첫 구현 묶음과 남은 운영 결정

### 바로 구현할 범위

1. 채택한 밝은 남색·금색 디자인으로 일반 사용자용 3단계 화면을 만든다.
2. 자료 등록 또는 회사 설명 후 허용된 범위 안에서 준비를 자동 연결하고, 미해결 핵심 사실이 있을 때만 질문한다.
3. 실제 AI 작성·독립 검토·수정 경로를 기본 준비 흐름에 연결한다.
4. 한 장 요약, 전체 원고, 근거·미확인 사항을 검토하고 제출본을 고정한다.
5. 충분·부족·충돌·과장 유도 사례를 동일 흐름에서 검증한다.

### 병행해서 확정할 운영 항목

기관 연동 허용 범위, 외부 AI 제공자·처리 조건·비용 한도, 자료 보관·삭제·복구, 제한된 고객 시범의 범위와 검토 담당자를 확정한다. 요금·지원기간·보완 지원 범위는 실제 운영비와 시험 결과를 보고 정하며 승인 보장 약속을 전제로 설계하지 않는다.

운영 결정이 남아 있다는 이유로 독립적인 화면·합성 검증·작성 연결 개발을 멈추지 않는다. 외부 자료 처리·공식 전송·권한 확대에 영향을 주는 결정은 실제 실행 전에 해당 대상과 내용을 확정한다.

## 15. 최종 완료의 정의

완료 기준은 **초보자가 회사 자료를 제공하면 AI가 사실에 근거한 신청 전략과 사업계획서를 만들고, 검토·보완을 거쳐 사용자가 확인한 내용으로 접수를 지원하며, 기관 요청과 최종 결과까지 추적할 수 있는 서비스**다.

화면 구현, AI 품질, 공식 연결, 고객 운영, 개별 기업 자료 준비는 서로 다른 완료 항목으로 관리한다. 어느 한 항목의 완료로 나머지를 완료 처리하지 않는다. 서비스는 벤처확인을 목표로 준비와 대응을 돕고, 기관의 결정을 사실대로 기록한다.

## 부록. 공식 평가영역과 AI 작성·증빙 대응

아래는 확인한 공개 지표의 내용을 축약해 묶은 **벤처패스의 작성·증빙 대응표**다. 공식 지표 명칭·배점의 원문 표나 기관의 판정 기준을 대신하지 않는다. 실제 적용 여부는 기업별 기준으로 다시 대조한다.

| 공식 지표에서 확인한 영역 요약 | 연결할 원고 | 자료 확인 방향 |
|---|---|---|
| 연구조직·기술인력 역량, R&D 투자 | 수행 역량과 개발 기반 | 조직·참여 인력·관련 비용의 실제 근거 |
| 기술개발 계획, R&D 활동 결과 | 개발 과정과 향후 실행 | 완료·진행·예정 구분, 기록과 일정 |
| 기술 차별성, 지식재산 보유 | 해결 기술과 경쟁 비교 | 비교 조건·시험 결과·권리 주체와 적용 범위 |
| 고용 변화, 목표시장 | 인력과 고객·시장 | 기간별 인력, 시장 범위·출처·기준시점 |
| 기업가정신과 사업계획, 협업, ESG | 경영·사업화 방향과 실행 | 설명한 활동의 실제 범위, 협업·운영 근거 |
| 자금계획, 사업성과 | 자금 운용과 성장·성과 | 확보·조달 예정 구분, 실적과 가정의 분리 |

평가지표의 충족을 길고 그럴듯한 문장으로 대신하지 않는다. 해당 지표와 관련된 회사의 실제 역량·활동·성과를 파악하고, 설명과 근거를 연결하는 것이 AI의 역할이다.
