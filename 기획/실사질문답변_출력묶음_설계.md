# 22. 제출본 기준 질문·답변·증빙 출력 묶음

상태: 구현·전체 회귀·독립 검토·격리 API/UI 검증 완료. 90파일 2,840개 테스트·타입·린트·격리 빌드와 선택 ZIP의 실제 바이트·과거 버전·회사 불변성을 확인했다. 잔여 R09를 기존 제출 준비 ZIP·실사 답변 이력 위에서 완성한다. 새 답변 입력기나 발표자료 자동 작성을 추가하지 않는다.

## 사용자 흐름

저장 원고 또는 수동 제출 기록을 명시 선택 → 해당 정확한 원고 버전의 질문과 저장 답변 버전을 직접 선택 → 포함할 원본을 직접 선택 → 질문·역할·답변·인용 위치·미확인 사항·선택 원본의 로컬 ZIP 다운로드. 실제 제출 또는 기관 수신을 뜻하지 않는다.

수동 제출 기록을 선택하면 그 기록에 고정된 원고·신청 회차·기록 당시 메타데이터를 기준으로 한다. 최신 원고나 최신 답변으로 임의 교체하지 않는다. 제출 기록의 공식 확인 상태는 그대로 표시한다. 초안 기준 모드에는 DRAFT를 명확하게 표기한다. 현재 회사정보와 과거 제출 기록은 구분하며 연락처 이력을 자동 포함하지 않는다.

## 정확한 선택과 저장 경계

읽기 전용 POST 요청은 회사 revision, mode(draft 또는 recorded-submission), 정확한 planId, submissionRecordId(null 또는 정확 ID), 선택 answerVersionIds(최대 20개), sourceIds(최대 10개)를 strict로 받는다. submission 모드는 같은 회사의 실제 저장 submission 이벤트와 plan ID·version·content SHA가 일치해야 한다. 답변은 해당 원고의 정확한 질문 인덱스·질문 텍스트·질문 SHA에 묶인 저장 버전만 허용한다.

답변 버전을 골랐다는 사실은 내부 검토나 사실 확인이 아니다. 다른 신청 제출 기록에 연결된 답변을 자동으로 옮기지 않는다. 별도 제출 기록에 귀속하지 않은 답변을 사용할 때는 ‘제출 기록 미연결’ 상태를 표시하고 현재 선택으로 소급 귀속하지 않는다. 같은 답변 root의 복수 버전을 동시에 선택할 수 있는지 UI에서 명확히 하며 기본은 한 root의 명시한 한 버전으로 제한한다.

출력은 저장 당시 답변·역할·인용·원본/원고 SHA·내부 판단·미확인 경고를 포함한다. 현재 자료 연결 상태는 별도 점검 결과로 구분한다. 저장된 답변의 원본 바이트가 현재 파일과 달라졌다면 해당 원본을 과거 증빙으로 포함할 수 없다. 원본 미선택 시 저장 메타데이터와 ‘원본 미포함’ 안내만 출력할 수 있다. 과거 자료 본문을 현재 본문으로 바꾸지 않는다.

기존 ZIP의 원본 안전 reader·개수/바이트/메타데이터/ZIP 한도·스냅샷 CAS·최종 해시 재확인을 재사용한다. 압축 경로는 서버가 UUID 기반으로 만들며 로컬 경로나 사용자 파일명을 경로에 쓰지 않는다. 생성 중 회사·원고·원본이 바뀌면 전체 결과를 보내기 전에 실패한다. 요청·다운로드는 회사 자료·진행 단계·제출 기록을 변경하지 않는다.

## 결과와 검증

묶음에는 안내, 선택 원고, 질문별 답변/담당 역할/근거 위치, 미응답·미검토·자료 부족 목록, 저장 당시 참조 목록, 선택 원본과 SHA manifest를 둔다. 모든 미선택 자료·다른 답변·연락 메모·자격정보는 제외한다. HTML/문서 실행을 요구하지 않는 Markdown·JSON·선택 원본으로 한정한다.

합성 API/ZIP 내용 검사는 다른 회사/원고/질문/제출 기록·중복/오래된 입력 거부, 과거 제출본 보존, 정확한 선택 버전, 변경 원본·경합·한도·경로 안전, 미검토/DRAFT 표시, 연락처/미선택 본문 제외를 확인한다. UI에서는 선택 초기화·동시 편집 차단·다운로드 성공/실패 후 상태 보존을 검증한다.
