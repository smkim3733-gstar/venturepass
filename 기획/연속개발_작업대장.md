- 현재 작업에 연결한 `벤처패스 끝까지 연속 개발` 자동 재개(automation-3)는 2026-09-25 사용자의 제품 연속 개발 재개 지시에 따라 ACTIVE로 변경했다. 5분 간격을 보존하고 개별 회사의 자료 대기와 제품 개발을 분리하도록 지시문을 보완했다. [제품 완성 개발 로드맵](./제품완성_개발로드맵.md)의 미완료 기능을 이어간다.

- 자료나 승인을 기다리는 동안에는 독립적인 개발을 계속한다. 반복 로그인이나 이미 불확실한 전송을 재시도하지 않는다.
- 종료는 자료 준비, 아이템·계획서, 승인 후 입력·첨부, 공식 처리 결과 확인·기록, 보완·실사·결과·확인서 관리까지 필요한 구현을 검증하고 실제 신청의 미확인 사항·사용자 할 일을 구체적으로 정리한 상태다. 기관의 심사 결과나 확인서 발급을 개발 테스트로 대체하지 않는다.

## 현재 검증된 기반

- DPAPI 계정 보관·로그인, 공식 화면 읽기·기업 대조, 항목·원본 연결, 2분 단회 승인, 텍스트·파일 실행, 파일 SHA256 재확인과 화면별 12개 이력.
- 최종 고정 소스: 전체 32개 파일 1,303개 테스트(Windows DPAPI 포함, 건너뜀 없음), lint·TypeScript·격리 배포 빌드 성공. 선택 항목 준비 분리, 미추출 원본 보관, 읽기 전용 현재값 대조, 텍스트 부분 실행의 새 승인 복구, 단계 이력, 기관 요청·답변·통보 5분류·원본 증빙과 안전 다운로드, 최초 입력 문맥 및 최종 완료 대조를 포함한다. 실제 회사의 공식 입력·업로드·동의·제출·납부는 미실행.
- 실제 회사에는 최신 재무 확정·주업종·자료의 현재성·공식 기업 일치·검토 완료 작성본 등 보완사항이 남아 있다. 실제 식별정보·자료 본문은 이 문서에 기록하지 않는다.

## 진행 순서

1. **완료 — 선택 항목 입력 준비와 전체 제출 준비 분리.** 일부 profile 입력도 전체 계획서·동의 오류 때문에 막히던 구조를 개선했다. 전체 제출 판정은 그대로 보존하며 기업 일치·세션·대응표·버전·선택한 모든 값·원본 검증을 유지한다. 관련 없는 계획서·미선택 항목은 남은 제출 과제로 표시한다. 불명확한 오류는 차단한다. 전체 846개 검사에 포함해 검증했다.
2. **현존 자료 점검 완료·외부 자료 필요 — 실제 회사 자료 재점검.** 최신 재무 확정·현재 주업종을 확정할 추가 증빙은 찾지 못했다. 기술자료는 설계·명세서 초안으로 실제 구현·고객·권리 확보의 증명이 아니다. 원본 변경·외부 AI 전송 없이 출처·기간·미확인 사항을 로컬에 정리했다. 신규 자료가 제공되면 이어간다.
3. **로컬 검토 원고 v2 준비 완료·사실 및 증빙 보완 필요 — 자료함 등록과 근거 있는 원고 준비.** 원본 5개와 확인 메모 1개를 등록했다. 스캔 2개는 원본 보관 상태로 분석에서 제외한다. 기업정보 4개 서술 항목과 자료 기반 아이템, 보강 업무 3개를 유지한다. 기존 v1의 27개 인용을 동일 회사의 등록 본문·기업정보와 문자 단위로 대조한 뒤 v2를 새 버전으로 저장했다. 항목별 설명 순서와 담당자 입력·문서 기재·현재 사실 미확인·향후 계획의 구분을 보강했으며 기존 v1·출처·업무·단계·기관 기록을 보존했다. 확인 필요 10개 항목을 유지했고 제출용 서술 완성본이나 내부 검토 완료로 표시하지 않았다. 별도 로컬 검토안에 최신 재무·주업종·구현 실적·고객·인력·자금·권리 증빙과 공식 실행 전 확인 사항을 모았다. 원문은 로컬 코드에서만 대조했으며 외부 AI 작성은 실행하지 않았다.
4. **대기 — 실제 공식 신청 문맥 확인.** 로그인 기업과 신청 기업의 공식 증거를 확보하고 페이지 간 문맥을 검증한다. 사전확인 화면에 기업번호가 없다는 이유로 로컬 기업명만으로 일치 처리하지 않는다. 화면이 필요한 시점에만 로그인한다.
5. **텍스트 전용 새 승인 복구 완료·첨부 및 세션 만료 복구 제한 유지 — 부분 실행 복구.** 현재 연결안과 화면을 읽기 전용으로 대조하고, 새 실행부터 전체 대상·값의 해시·기업/계정/세션/화면과 누적 시도 이력을 불변 근거로 보관한다. 동일 문맥의 텍스트 전용 중단 실행에서 일치 항목은 지속 보호하고 한 번도 시도하지 않은 빈 항목만 별도 2분 단회 승인 대상으로 제시한다. 회사·인증·전체 메타데이터·보호값을 쓰기 직전 같은 동기 평가에서 확인하며, 이번에 새로 쓴 값도 이후 입력에서 보호한다. 첨부가 포함된 최초 실행·legacy·진행 중·결과 미확인·시도했던 빈칸·상충·연결 변경은 거부한다. 이전 승인 재사용·값 덮어쓰기·불확실한 전송 재시도는 하지 않는다. 최초 시도 포함 10회에서 추가 실행을 거부하고 기존 이력을 보존한다. 이번 실제 입력만 완료 목록에 기록하며 읽기 일치를 새 전송으로 세지 않는다. 전체 1,083개 검사와 격리 빌드·독립 검토 통과. 실제 기관 동작과 브라우저의 실환경 부분 실행은 미검증이다. 첨부 복구는 빈 파일 선택란을 미전송 근거로 사용할 수 없어 자동 구현하지 않는다.
6. **대기 — 공식 저장·이동·제출 결과 연결.** 실제 관측한 화면과 동작을 바탕으로 단계별 정확한 전송 검토안, 명시 승인, 중복 방지와 결과 확인을 구현한다. 공식 동작을 관측하지 못했다면 버튼·성공 신호를 추측해서 구현하지 않는다. 승인 전까지 구체적인 로컬 검토안을 완성한다.
7. **로컬 기록 구현 완료·실제 기관 결과 대기 — 접수 이후 이력.** 단계 변경 이력과 담당자 기록을 보존한다. 기관 요청 원문·직접 확인한 날짜/기한/근거·요청 정정·답변 초안/수동 발송 기록을 회사별 추가 전용 저널에 저장한다. 요청과 답변은 각각 버전을 올리고 답변이 참조한 요청 버전을 고정한다. 납부·접수·실사·결과·확인서 통보에는 별도 최초 통보 ID와 정정 이력을 적용했다. 분류 정정 시 과거 분류·본문·증빙을 보존하며 통보는 답변 대상으로 쓰지 않는다. 금액·기한·번호·일자·일정·장소·결과·유효기간의 빈 값은 미확인으로 남기고 자동 계산·진위 판정·단계 변경은 수행하지 않는다. 같은 회사 원본을 서버가 안전하게 읽어 이름/형식/크기/SHA256/캡처시각을 보관하며 참조 원본 삭제와 변경된 원본의 같은 ID 재연결을 차단한다. 중복 저장 nonce·CAS·실행 잠금·기록 200개/텍스트 20만자/한 기록 10개 파일·합계 24MiB 제한은 새 상세 문자열에도 적용한다. 현재 원본 대조와 안전 다운로드, 이전 기업 호환을 유지했다. 실제 UI의 5분류·빈 확인서 값·편집 취소 후 0건 보존을 확인했다. 기관의 실제 송수신·접수·납부·발급은 별도 확인이 필요하다.
