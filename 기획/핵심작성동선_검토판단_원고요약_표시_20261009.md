## 표시와 검증 범위

기록 없는 의견과 저장한 ‘확인 필요’는 서로 다르게 보인다. 최신 기록이 보류→담당자 해결 판단으로 바뀌면 요약만 갱신한다. 이전 판단 이력·원고 버전·경고는 유지한다. ‘저장 기준 유지’는 원래 수동 판단의 근거 연결 상태이며 사실 확인 완료가 아니다. 이유 전문은 기존 의견 버튼으로 연 폼의 이력에서 확인하므로 요약에 자르거나 재작성하지 않았다.

신규13개: 미기록1·상태3·기록순서1·다른원고/버전/index/의견4·숨긴info/같은문구1·non-stale1·재검토사유/문자escape1·현재회사props/무요청1이다. 기존13개는 같은 GuidedWorkspace의 상태별 렌더링 영향 회귀다. 수동 판단 입력/저장 writer 자체는 수정하지 않았다.

앱3개는 기존 검증기의 summary 인자로 구분했다. 이전 link 모드는 실행하지 않았다. 보류와 해결 판단 두 번을 실제 폼에서 저장하되 응답은 합성 메모리이며, 뒤의 새 v3는 공급한 합성 GET 상태다. 새 버전을 실제 backend가 저장하거나 회사 전환을 관측한 시험으로 부풀리지 않는다. 모바일390px에서는 재검토 사유가 줄바꿈되고 가로 넘침0이었다.

이번 경로는 내보내기를 사용하지 않으므로 proxy는 모든 업무 API를 차단했다. Playwright 가로채기를 벗어난 업무 요청은 실제 Next에 도달하지 않는다. dev의 /_next/hmr만 자기 child로 전달한다. 과거 다운로드의 SQL 생성 실패를 이번 결과와 섞지 않는다.

## 다음 작업 완료 기준

- 현재 원고가 없는 첨부0개 합성 회사의 실제 간단 화면에서 시작한다. 회사 설명이 없는 상태와 설명을 저장한 상태를 혼동하지 않는다.
- 기존 자료 범위·명시 선택·전송 동의·원래 요청/응답 binding을 그대로 사용한다. 자동 동의·전체 파일 자동 전송·새 백엔드를 만들지 않는다.
- 실제 UI의 첫 원고 표시까지 같은 회사·현재 revision/선택을 이어 받는지 확인한다. 응답은 순수 합성으로만 구성하며 AI 품질/실제 저장 성공으로 세지 않는다.
- 기존 자료 준비/선택 개별 시험을 이유 없이 반복하지 않는다. 옛 실제 route 통과 검증기/운영 원장·SQL·SDK/유료AI를 실행하지 않는다.
- 단절이 없으면 제품을 임의로 변경하지 않는다. 제품 변경 시에만 관련 회귀→합성 앱→lint→typecheck→격리 build를 순차 확인한다.
