| 대상 | 경계 |

Content-Length는 안전한 정수/한도만 조기 검사한다. 실제 노출 bytes를 EOF까지 누적하며 길이 header와 압축 해제 본문의 같음을 요구하지 않는다. Content-Type은 application/json 또는 UTF-8 charset만 허용한다. native Response 접근자로 body/status/header/redirect/사용 상태를 검사하고 가짜 DTO를 응답으로 cast하지 않는다.

단일 reader로 수집한 뒤 EOF/releaseLock 성공 후에만 fatal UTF-8와 JSON을 각1회 해독한다. response.json/text/arrayBuffer/clone은 사용하지 않는다. 큰 단일 청크는 복사 전 거절한다. 한도는 노출 본문의 보관량 경계이며 헤더/TLS/압축wire/이미 할당된 청크·전체 heap 상한이 아니다.

모든 read 전후·마지막 해독 뒤에도 취소/deadline을 재검사한다. 타이머가 아직 실행되지 않았어도 시작 전 단조 기한이 지났으면 start0으로 실패한다. 동기 SQL/JSON/schema를 선점 중단하지 않으며 기한을 지난 결과를 폐기한다.

취소 시 자기 AbortController만 중단한다. 원래 start promise의 resolve/reject observer를 즉시 설치하며 늦은 Response도 자기 body cancel 대상으로 보관한다. 원래 read 또는 cancel이 끝나지 않으면 completion pending이다. cancel은 최대1회, throw/reject·release 실패는 cleanupFailed다. 실패를 정리 성공으로 바꾸거나 시간/PID/창 닫기로 서버 책임을 해제하지 않는다.
