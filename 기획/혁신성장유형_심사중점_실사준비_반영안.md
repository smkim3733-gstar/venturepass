# 혁신성장유형 심사 중점과 현장실제조사 준비 반영안

작성·확인일: 2026-09-23. 대상: 혁신성장유형 전용 앱. 아래에서 공식 기준, 실무 준비 제안, 실제 구현 범위를 구분한다.

## 1. 핵심 결론과 공식 근거

사업계획서는 신청기술의 차별성, 회사의 지속적인 개발 역량, 해당 기술을 활용한 시장확대 계획을 객관적 자료와 연결해야 한다. 실사 준비도 같은 사실·자료를 이용해 현재 상태를 설명하고 확인할 수 있게 구성한다. 문장을 다듬는 것으로 실제 개발·검증·고객 확보를 대신할 수 없다.

2026 공식 가이드북 인쇄 p36의 심의 중점은 유사기술·제품과의 비교, 기술·지식재산의 객관적 근거, 혁신활동을 지속할 인력·인프라, 시장확대 전략, 신청기술과 사업계획의 연관성이다. 추상적 우수성, 감정적 호소, 약한 경쟁 비교, 일반적인 마케팅 나열은 피하도록 안내한다. 아래 여섯 관점은 이 내용을 제품에서 사용하기 쉽게 묶은 것이며 공식 평가항목의 명칭이나 배점을 대체하지 않는다.

공식 절차는 신청서 제출 → 신청서류 확인·보완 → 수수료 납부와 접수완료 → 전문평가·현장실제조사 → 위원회 심의다. 사무국의 서류 확인, 현장평가, 위원회 최종 판단을 서로 다른 상태로 관리한다. 서류 접수나 실사 완료를 최종 확인으로 표시하지 않는다.

## 2. 심사 관점과 사업계획서·증빙·실사의 연결

| 준비 관점 | 사업계획서가 답해야 할 질문 | 증빙 예시 | 실사에서 준비할 확인 |
|---|---|---|---|
| 고객 문제와 신청기술의 연결 | 어떤 고객의 무슨 문제를 어떤 기술로 해결하는가? | 고객 상담, 현장 문제 기록, 제품·기술 구성 설명 | 문제 → 작동 방식 → 고객 가치가 같은 제품·서비스를 가리키는지 설명 |
| 객관적인 기술 차별성 | 기존 기술·제품과 무엇이 다른가? 비교 조건이 적절한가? | 비교표, 도면, 측정 조건·원자료, 개발·고객 검증 기록 | 수치의 비교 대상·기간·조건·측정방법, 입증 범위와 한계 |
| 자사 개발 범위와 지속 개발 역량 | 직접 개발하는 부분과 외주·외부 기술 범위는? 누가 계속 개선하는가? | 인력 경력·참여 기록, 개발환경, 해당 계약·사용권 근거 | 기술 담당자의 실제 역할, 외부 의존 범위, 사용 가능한 환경 |
| 현재 개발 단계와 향후 계획 | 지금 구현·검증한 부분과 앞으로 만들 부분은? | 개발 이력, 버전·시제품·시험 기록, 단계별 계획 | 현재 가능한 기능과 한계, 완료일과 기록의 일치 |
| 기술에 연결된 시장확대 전략 | 누가 왜 구매하며 최초 고객에서 어떻게 확대하는가? | 수요조사, 구매 검토, 계약·납품·협업 자료, 출처가 있는 시장자료 | 협의·계약·납품·매출·목표를 구분하고 실제 도입 경로 설명 |
| 인력·자금·일정의 실행 가능성 | 계획한 개발·사업화에 인원·비용·조달 시기가 맞는가? | 투입계획, 자금 소요·조달 근거, 기간별 재무·실적 | 숫자 산정 근거, 확보 자금과 조달 예정 자금, 가정·민감요인 |

위 자료는 주장에 따라 선택하는 예시다. 특허·공인 연구조직·공인 시험성적서·매출을 모든 기업의 동일한 필수조건으로 설정하지 않는다. 특허가 있더라도 신청기술과 관련성, 출원·등록·권리자·사용 가능 범위를 확인해야 한다. 구체적인 인정은 기관의 평가에 따른다.

## 3. 팩트체크와 증빙 확보를 작성 과정에 넣기

자료 입력 → 신청기술 선택 → 핵심 주장 추출 → 주장별 증빙·현재 상태 대조 → 누락·모순 보강 → 사업계획서 작성·검토 → 실제 제출본 확정 → 같은 내용으로 실사 준비의 흐름으로 개발한다.

예를 들어 `기존 방식 대비 불량률을 30% 낮췄다`는 문장을 쓰려면 비교 대상, 불량률 정의, 측정 기간·대상 수, 전후 조건, 계산 방식, 원자료를 확인해야 한다. 고객의 기대나 대표의 희망 수치라면 검증된 실적으로 쓰지 않는다. 향후 목표로 기재하려면 그 목표의 가정·검증 계획을 별도로 표시한다.

상담 녹취는 회사의 설명을 수집하는 자료다. 녹취에 나온 말이 자동으로 실적 증빙이 되지는 않는다. 계약서에 기재된 금액도 바로 매출로 치환하지 않고, 해당 문장이 주장하는 계약·납품·회계 인식 기간을 확인한다. AI가 생성한 연구노트나 보고서를 과거에 실제 수행한 활동의 원본 증거로 만들지 않는다.

후속 개발의 주장별 기록: 주장 ID, 관련 평가 관점, 실적/계획/가정 구분, 자료 ID·버전·페이지 또는 확보된 위치·인용, 기업·기간·단위, 원본 대조 여부, 외부 확인 여부, 불일치, 보강 행동, 담당자, 기한, 마지막 확인일. 자료가 바뀌면 연결된 주장과 실사 답변을 다시 확인해야 한다.

확인 방식은 문서 원문 일치, 숫자·기간·단위 대조, 출처·권리 등의 외부 확인, 기업 담당자 사실 확인으로 구분한다. AI끼리 답변이 일치하거나 원문 인용이 존재한다는 이유만으로 사실 검증 완료로 처리하지 않는다. 증빙이 없는 경우 필요한 시험·고객 검증·권리 확인을 실제 업무로 안내한다.

## 4. 실사 준비 운영안

### 실사 일정 확정 후

1. 기관 연락, 일정, 장소, 참석·요청자료를 확인한다. 본사와 실사 장소가 다르면 벤처인 사업장 정보와 신청 장소를 확인한다. 이전 예정이면 배정 기관에 문의한다.
2. 기관에 실제 제출한 사업계획서·첨부자료·보완본을 한 벌로 정리한다. 앱의 최신 초안과 실제 제출본을 혼동하지 않는다. 이후 변경된 인원·주소·개발 상태·계약은 변경일과 자료를 함께 정리한다.
3. 사업·기술·재무 설명 담당자를 정하고 핵심 주장마다 `답변 요점 → 원본 자료 → 현재 확인할 대상`을 연결한다. 참석자와 발표 형식은 기관 안내에 따른다.
4. 적용 가능한 제품·서비스·개발환경을 확인한다. 시연을 준비하는 경우 동작 범위·환경·접속·장비를 점검하고 구현하지 않은 기능을 완성 기능으로 설명하지 않는다.
5. 인력·외주·라이선스·협업의 실제 범위를 대조한다. 외부 개발을 모두 자사 독자개발로 표현하지 않는다.
6. 기술 비교 수치, 매출·계약·고용·개발비의 기준기간과 계산 근거를 대조한다. 재확인은 이전 확인기간의 개선 내용과 성과를 따로 준비한다.
7. 실제 제출본과 근거를 보면서 모의 질의응답을 진행한다. 답변 자체보다 설명과 원자료·현장 상태의 일치 여부를 점검한다.

### 실사 당일과 이후

- 실제 제출본을 기준으로 현재 기술·사업을 설명하고 질문에 맞는 자료를 제시한다. 확인하지 못한 내용은 추측하지 않고 확인할 담당자·자료를 기록한다.
- 현장에서 추가 요청을 받으면 요청 내용·담당자·안내기한·대상 자료를 남긴다. 실사 완료와 최종 승인 상태는 별개로 관리한다.
- 후속 제출은 요청사항별 답변·근거·변경 내용을 연결해 준비하고 제출 증빙을 보관한다. 모든 현장 보완에 공통 15일 기한을 가정하지 않는다.

### 기업 형태별 준비 예시

| 기업 형태 | 현장에서 설명할 대상 예시 |
|---|---|
| 제조·장비 | 제품·시제품, 설계·공정의 차이, 적절한 시험 조건과 결과, 생산·외주 범위 |
| 소프트웨어 | 현재 실행 가능한 기능, 구조·개발 이력, 자사 코드·외부 솔루션 범위, 측정 환경과 이용·도입 근거 |
| 기술 기반 서비스 | 기술이 작동하는 업무 과정, 실제 서비스 결과·운영 기록, 검증된 고객 효과와 확인 한계 |

시연·소스코드·특정 장비·PPT를 모두에게 동일한 필수항목으로 만들지 않는다. 회사 상황과 기관의 개별 요청을 우선한다.

## 5. 2026년 7월 시행 규칙의 범위

- **기업 신청 단계의 접수 전 신청 보완·수수료 납부 요청** 이후 15일간 미진행하면 취소 또는 제출완료 이전 상태로 변경될 수 있다. 추가 신청 보완요청 시 가장 최근 요청일을 기준으로 확인한다.
- 현장평가 중 추가자료 요청에 위 15일을 자동 적용하지 않는다. 기관에서 실제 안내한 기한을 보존한다.
- 신청기업의 부득이한 사유로 전문평가기관 평가기간 28일에 최대 14일 추가 연장이 가능하다. 그 기간에도 평가할 수 없어 반려·취소되는 경우의 수수료 전액 환불 안내가 있다. 모든 취소에 같은 환불 규칙을 적용하지 않는다.
- 혁신성장유형 전체 처리기간 45일과 부득이한 경우 최대 20일 연장, 전문평가기간 28일과 최대 14일 연장은 서로 다른 기준이다. 두 기간을 더하지 않는다.
- 후속 자동 기한 관리에는 요청 주체·절차 단계·요청 종류·최신 요청일·안내기한·연장 여부·완료 증빙·공식 상태를 분리해서 저장한다. 현재 구현은 안내문과 수동 기한 기록이다.

## 6. 앱에 반영한 범위와 후속 개발

2026-09-23 코드 반영:

- 아이템 분석 화면: 여섯 심사 준비 관점과 증빙 예시, 공식 근거 링크 안내.
- 분석·자동작성·별도 AI 검토: 신청기술 연관성, 객관적인 비교 조건, 자체·외부 개발 범위, 완료·계획 구분, 인력·일정·자금 정합성을 프롬프트에 반영.
- 자료 기반 정리본: 입력된 회사 자료·아이템에 연결한 준비 질문 생성. 기관의 실제 질문으로 표시하지 않음.
- 진행 관리: 실사 준비목록 8개, 선택한 작성본의 심사 관점별 본문·기존 인용, 예상 질문 확인. 선택한 준비사항이나 질문을 실사 업무 편집기에 채우고 담당자 메모·기한·결과를 저장할 수 있음.
- 진행 단계가 제출·납부일 때 접수 전 15일 규칙과 공식 공지 표시.

현재 인용 연결은 작성 항목 단위이며 모든 문장에 대한 증명이나 외부 사실 확인이 아니다. 작성본이 실제 기관 제출본인지 자동 확인하지 않는다. 기존 작성본은 보존하며 새 프롬프트는 이후 새로 분석·작성하는 결과에 적용된다. 실제 AI 응답 품질은 API 키를 설정한 후 별도 검증이 필요하다.

후속 개발:

1. 신청요건·심사준비도 사전진단과 기업별 부족 자료 안내를 첫 화면 흐름으로 통합.
2. 문장별 주장·증빙 상태, 적용 기준 버전, 자료 변경에 따른 재검토 표시.
3. 실제 제출본 보관·버전 확정과 질문별 답변·증빙 위치를 연결한 실사 준비자료 출력.
4. 모의 질의응답 답변 입력·녹취 분석 및 불일치·추가 확인 목록. 자동 합격점수는 표시하지 않음.
5. 기관 요청·안내기한·제출 증빙의 구조화 및 공식 연결이 가능한 범위에서 일정 알림.

회원가입·권한, 외부 통지 연동, 벤처인 자동 제출은 이번 변경으로 구현된 기능이 아니다.
