## 최신 인계 — 간단 화면의 파일 판독·교정·채택 연결 완료 (2026-10-10)

사용자가 마지막 개발 기회를 주며 실제 결과를 요구했다. 기존 변경 확인만 반복하던 후속을 이번 구체적 제품 작업으로 전환했다. 파일 본문 확인을 위해 상세 자료함으로 갔다가 간단 화면으로 돌아와야 하던 전환을 없앴다. 업로드 완료·본문 준비 안내·미채택 자료 카드의 세 진입점이 같은 간단 화면의 기존 SourceIntakesPanel을 연다. 중복 신규 업로드 폼은 숨기고 자료 선택 복귀를 제공한다. 업로드 구성요소는 숨겨진 채 유지하며 기존 선택과 복구 상태를 새로 만들지 않는다.

판독/채택 처리 중에도 폼이 유지된다. 열린 교정·외부 전송 검토·미확인 요청·실행 항목·선택 파일이 있으면 복귀를 막는다. 접수 미확인 상태를 상위 화면에 전달하여 상세 전환·회사 변경으로 우회하지 않게 한다. 교정 닫기 취소는 본문을 유지한다. 기존 명령/응답·원본/결과/회사 revision 대조와 별도 채택/전송 동의는 그대로 재사용했다. 새 writer/AI/자동 판독·자동 채택은 없다.

## 변경과 검증 범위

- 제품: guided-workspace.tsx, source-intakes-panel.tsx.
- 시험: source-intakes-panel.test.ts에 간단/상세 표시 경계 2개 추가.
- 격리 앱: guided-file-draft-validation.mjs를 새 간단 화면과 지연 판독·교정 취소·잘못된 채택 응답/정확한 GET 복구에 맞춰 갱신했다.
- 기존 준비/원래 명령/해시/영수증 helper와 합성 fixture를 재사용했다.
- 교정 폼의 수동 확인과 AI 전송 동의는 별개다. 본문 채택은 원고 사실 확인/전체 confirmedAt/기관 준비를 승격하지 않는다.
- 완성본의 항목 확인 필요10·검토 의견1·confirmedAt:null, 정확한 sourceId·원래 run·v1 planId를 대조했다.
- 기존 동일 원고 재진입/공개통계/기관 조회/Word 내려받기 시험을 재실행하지 않았다.

## 한계

현재 흐름은 실제 브라우저 화면에서 합성 응답으로 검증했다. 실제 원본 저장소/판독기/AI/SQL의 신규 성공으로 세지 않는다. 회사 변경은 상위 미확인 상태 전달과 기존 회사별 key 수명을 소스로 확인한 것이며 이번 회사 전환 앱 시험으로 주장하지 않는다. 숨겨진 업로드 구성요소의 보존은 구현을 유지했지만 이번 흐름은 업로드 선택 목록을 닫은 뒤 본문 확인으로 진입했다.
