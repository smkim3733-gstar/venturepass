# 자료 종류 변경 설계

작성일: 2026-10-24. 상태: 구현.

## 문제

간단 화면 업로드는 기본값 "기타 서류"로 보관된다. AI 없이 하는 정리는 기술·특허 분류 자료나 회사 설명이 있어야 후보를 만들므로, 잘못 분류한 자료는 다시 올리는 것 말고는 고칠 방법이 사실상 없었다. 상세 도구의 "추출 내용·분류 수정"은 자료 전체를 덮어쓰는 `source` 변경이라 다음 문제가 있다.

- 저장하면 추출 방식이 항상 `manual`(직접 입력)로 바뀐다. 자료 정리에서 문서 추출 자료는 `documented`, 직접 입력은 `reported`로 기록되므로 종류만 바꿔도 근거 등급이 내려간다.
- 본문이 필요해서 원본만 보관한(`pending`) 자료의 종류는 바꿀 수 없다.

## 결정

종류만 바꾸는 별도 변경 `set-source-kind`를 둔다.

- 입력: `revision`, `sourceId`, `kind`. 기업 revision CAS를 그대로 사용한다.
- 본문·제목·추출 방식·경고·원본 파일 정보·생성 시각은 그대로 둔다. `kind`와 `updatedAt`(기존 단조 증가 규칙 `nextSourceTimestamp`)만 바꾼다.
- 같은 종류로 바꾸는 요청은 새 revision을 만들지 않도록 409 `SOURCE_KIND_UNCHANGED`로 거절한다. 없는 자료는 404.
- 종류는 분석 근거 선택에 쓰이므로 본문 수정과 같게 `invalidateEvidence`를 적용한다(분석·선택 해제, 원고 확인 해제, 진단·준비 기록 stale). 과거 원고 버전·제출 기록·접수 이력·절차 스냅샷은 바꾸지 않는다.
- `updatedAt`이 바뀌므로 기존 "자료 변경 영향" 목록과 "자료 변경 후 로컬 준비 연결"(종류를 `sourceMeaning`에 포함)이 변경을 그대로 감지한다.
- 원본만 보관한 자료도 종류를 바꿀 수 있다. 본문을 확인하기 전에는 여전히 분석 근거에서 제외된다.
- 별도 종류 변경 이력 표는 만들지 않는다. 변경 사실은 자료 수정 시각과 기존 영향·자동 준비 이벤트로 추적한다.

## 화면

- 간단 화면 "올려 둔 자료" 목록의 각 파일에 종류 선택을 둔다. 바꾸기 전에 이전 정리본·분석을 다시 준비해야 할 수 있음을 확인받는다.
- 상세 도구 자료 편집에서 제목·본문이 그대로이고 종류만 바뀌었으면 `set-source-kind`를 사용해 추출 방식을 보존한다.

## 남은 일

- 종류 변경을 이유와 함께 별도 이력으로 남길지 여부는 실제 사용 후 판단한다.
