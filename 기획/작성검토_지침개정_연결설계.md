## 연결 방식

1. v1 지침과 wire schema를 현재 바이트 그대로 보존한다. 우선 지침/계약 선택을 순수한 버전 모듈로 분리하고 기존 getter·builder는 계속 v1을 반환하게 한다. 추출 과정에서 원문 공백, 줄바꿈, JSON 삽입 순서, 후보 classification 보정 차이를 유지한다.
2. 새 지침은 `plan-observation-v2`로 명시한다. 생성·검토 단계별 system/instruction/schema digest와 호출·토큰·재시도 제한을 계약에 포함한다. 버전별 상수는 외부에서 변경하지 못하게 하고 반환하는 요청·계약은 서로 독립된 객체로 만든다. 알 수 없는 버전은 기본값으로 바꾸지 않고 거절한다.
3. 4C2b에서는 **순수 v1/v2 지침 선택과 요청/검토 template 준비까지만** 구현한다. 공급자 SDK, 파일/DB, 키/환경 읽기, 실행 owner, 예산/승인 생성, 공개 HTTP/UI 연결은 추가하지 않는다. 기존 운영 경로는 v1로 남긴다.
4. 4C2c에서 서버가 새 실행에 선택할 버전을 하나의 명시적 경로로 연결한다. 클라이언트가 임의 prompt/contract/version을 보내 운영 선택을 바꾸지 못하게 한다. 실행 시작 때 버전을 고정하고 generation → validated generation → derived review → finalization 전체가 그 버전을 사용하게 한다. 중간 서버 기본값 변경으로 계약이 섞이면 전송을 차단한다.
5. 운영 준비·토큰 계산·정책 검토·채택·예약·전송 승인이 새 정확한 요청에 다시 결합되는지 모의 경로로 검증한다. 옛 승인은 새 지침의 승인이 될 수 없다. 버전 변경은 예산 범위/고정 원장 경로 변경 사유가 아니다.
6. 과거 결과 읽기/내보내기/백업·복구 검증은 저장된 버전/바이트와 해당 검증기를 사용한다. 과거 v1 자료 조회만으로 새 정책이나 예산을 만들지 않는다. 이미 완료된 실제 run을 재실행하지 않는다.

## v2 작성 지침의 구체적 변경

- 독자에게 보이는 제목·요약·본문·과제·질문은 자연스러운 한국어를 사용한다. 구조화 enum과 evidence quote/sourceId/locator는 원문과 계약대로 유지한다. documented/reported/planned/unverified를 각각 문서 기재/담당자 설명/향후 계획/근거 미확인으로 설명하되 확인 완료로 의미를 높이지 않는다.
- 자금 메모·잔액·자기자금 배정은 자료에 기재된 범위로만 설명한다. 메모 하나로 현재 가용 현금, 목적 제한 없음, 집행 가능, 외부 조달 불필요, 조달 확정 또는 투자 적정성을 단정하지 않는다. 기준일, 사용 가능성, 다른 집행 의무와 미확인 조건을 필요한 확인 질문으로 남긴다.
- 회사 자료에 없는 심사 빈도, 기관 선호, 심사에 유리함, 일률적 실사 필수요건을 만들지 않는다. 원문에 없는 현장 상태와 준비 질문은 제안/확인 항목으로 표현한다. 실제 기관 질문이라고 표시하지 않는다.
- 인용의 문자 그대로 일치, 원문 지시 무시, 사실·계획 구분, 불확실성, 확인 필요 flag, 10개 섹션 순서와 기존 출력 schema는 유지한다.

## v2 검토 지침의 구체적 변경

- 지적 전에 해당 본문 전체와 이미 있는 제한·확인 질문을 함께 읽는다. 본문이 제한을 이미 정확히 밝혔다는 이유만으로 같은 위험을 다시 오류로 만들지 않는다. 다만 다른 문장이 그 제한과 충돌하거나 과도하게 확정하면 그 문장과 원문을 특정해 지적한다.
- 같은 section/주장/근거/원인/수정 행동의 단순 재서술은 하나의 지적으로 정리한다. 근거, 주장 또는 필요한 행동이 다르면 유지한다. 개수 채우기를 요구하지 않고 문제가 없으면 빈 배열을 허용한다.
- message에는 문제되는 본문 주장과 원문이 허용하는 범위의 차이를 구체적으로 쓴다. action은 이미 수행한 조치를 반복 요구하지 않고 실제로 남은 수정 또는 확인을 지정한다. 불확실한 판단은 확인 의견으로 유지한다.
- 자금 확정성 확대와 실사/기관 일반화도 확인한다. 실제 자료에서 확인할 수 없는 단어 목록 일치만으로 위반을 단정하지 않는다.
- 저장된 과거 review 배열/ID/원본 번호/사람 판단을 삭제하거나 의미상 중복으로 다시 쓰지 않는다. 새 검토 생성 지침과 기존 의견의 표시 기능을 구분한다.
