## 4E3 한글 경로 백업 결함과 복구

실제 합성 앱 자료를 백업할 때 정상 한글 경로가 `UNSAFE_PATH`로 거절됐다. Node는 stdin을 UTF-8로 보내지만 Windows PowerShell의 경로 검사는 시스템 콘솔 문자 인코딩으로 읽고 있었다. `local-data-files.mjs`의 고정 검사 명령에 UTF-8 입력을 명시했다. 경로 내용은 계속 JSON stdin으로만 전달하며 명령으로 해석하지 않는다.

링크·재분석 지점, Git·동기화 폴더, 기존 목적지, 원본/목적지 겹침, 파일·DB 손상 거절은 유지했다. 현재 D: 소스 루트에도 `.git`이 있으므로 그 하위 백업은 기존 정책대로 `DESTINATION_REPOSITORY`로 거절된다. 이를 완화하지 않고 안내의 일반 백업 위치를 `%LOCALAPPDATA%/VenturePass/backups`로 정했다.

관련 로컬 데이터 회귀3파일 **74개(신규2개 포함)**가 153.96초에 통과했다. 한글·공백·악센트·이모지·따옴표·명령처럼 보이는 문자 경로, 없는 파일, 한글 junction 상위 경로 거절을 확인했다. 기존 WAL 온라인/정상 종료 DB의 백업·검증·복원 시험도 한글 목적지로 실행했다. 기존 DB·원본·과거 준비 ZIP 보존, 손상·덮어쓰기·중단 거절을 유지한다.

4E2에서 만든 실제 합성 앱 자료의 백업→검증→새 경로 복원→검증도 기존 CLI로 통과했다. Git 경로 금지 때문에 승인된 시스템 임시 폴더 `venture-local-recovery-cFtI7i`를 사용했다. 원래·복원 경로를 각각 별도 앱으로 열어 회사 전체 응답, 원고3개, 원본 파일, Markdown이 일치하고 원래 백업 파일이 바뀌지 않음을 확인했다. 운영 설정을 전환하지 않았다. 시험 서버 잔존0을 확인했다.

임시 복원 대조 도우미는 처음에 저장 DB 본문과 API가 붙이는 읽기 전용 `applicationCriteriaContexts` 필드를 혼동했다. DB 본문끼리, 전체 API 응답끼리 대조하도록 바로잡았다. 이미 종료한 서버를 다시 기다린 정리 오류도 고친 뒤 최종 실행은 종료코드0이다. 백업4단계는 이미 통과했으므로 반복하지 않았고, 대조 재실행을 별도 성공 건수로 합산하지 않았다.
