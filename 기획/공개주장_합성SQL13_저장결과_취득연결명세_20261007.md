## 4. 이번 선택: SQL13 합성 저장에서 내보낸 사본

지금 가능한 연결은 **격리 SQL13 저장·감사 → 검증된 historical wire → 현재 실제 앱의 명시 읽기·표시**다. 현재 테스트가 이미 session/guard/service를 보관하며 기존 reader를 사용할 수 있으므로 새 서버 registry나 운영 DB 취득 없이 구현 가능하다.

직접 SQL을 Next route에 연결하려면 별도의 신뢰한 서버 보관 경로와 SDK 없는 runtime 의존성 분리가 먼저 필요하다. 이 점검에서 그런 경로가 이미 있다고 가정하거나 동작하지 않는 factory를 추가하지 않는다. 다음 범위의 결과도 실시간 SQL service 설치로 기록하지 않는다.

후속 산출은 현재 고정 JSON을 **실제로 저장된 합성 SQL13에서 읽은 사본**으로 교체하고 그 생성 출처를 검증 가능하게 남긴다. source/authority/원래 result bytes는 그대로이며 별도 manifest가 필요하면 kind/schemaVersion13/witnessVersion3/원래 run·dispatch/wireSha256 등 최소 메타데이터만 둔다. 파일 경로·DB handle·capability·control/lock·원래 전체 명령·SDK 응답 원문을 앱에 배포하지 않는다. 출처 manifest도 실행 권한/사람 동의/사실 확인 증인이 아니다.

현재 화면의 합성 안내에 시점 고정 사본임을 분명히 표시한다. 기존 메뉴/명시 시작/POST/현재 frame/표시 비우기/종료 흐름은 재사용한다. 사용자에게 새 서버 선택·DB 경로·SDK 설정을 요구하는 UI를 만들지 않는다.
