## 구현

기존 SDK 형태 경로에 단일 body 수집기를 연결했다. helper는 SDK import/fetch/환경을 포함하지 않으며 fresh dispatch COMMIT·정확한 ack 이후 같은 실행 엔진의 sdk 호출에서만 생성된다. 공개 결과로 owner를 만들지 않고 SQL13/증인3·private writer/decoder/산술과 원래 nonce/bytes를 유지한다.

정상 HTTP 본문은4MiB, 오류 본문은64KiB를 적용한다. reader가 노출하는 바이트를 고정 크기 buffer에 경계 검사 후 복사한다. Content-Length는 엄격한 조기 거절에만 사용하며 작거나 누락된 값을 상한 증거로 삼지 않는다. JSON/text/arrayBuffer·clone/tee로 원래 본문을 먼저 읽지 않는다. raw Response의 native accessor로 status/body/header를 읽고 SDK에 주는 buffered view는 동일 bytes/status/content-type/request-id를 보존하며 content-encoding을 제거하고 실제 길이를 기록한다. 압축 wire·socket/TLS·전체 heap 상한을 보장하지 않는다.

SDK 준비 직전 한 번의120000ms 단조 deadline과 AbortController를 만들고 별도 request 옵션{signal}만 전달한다. 비교 요청v1/requestedTier:null·네 옵션 생략과 원래 rawBody/headers는 그대로다. 최종 quality→studio guard에서 확인한 wire signal은 시작 함수에 그대로 전달한다. 네트워크 시작과 즉시 거절 handler 설치는 잠금 안에서 동기 수행하고 body read/await는 잠금 밖이다.

빠른 전달 promise와 원래 fetch/read/cancel의 종료를 분리했다. timeout·SDK 종료 뒤에도 pending fetch가 Response를 주면 body 취소 책임을 새로 관측하며 두 번째 전달·새 SDK/전송을 하지 않는다. 한 번의 cancel이 pending/거절/throw하거나 reader 해제가 실패하면 cleanup 책임을 남긴다. SDK 진입 등록이 닫히고 원래 pump/cancel이 종료되어야 private I/O 완료가 된다. 순간적인 pending0·abort/release 호출은 완료가 아니다.

기존 engine의 finish/execute/recover에 I/O 완료 조건을 연결했다. 공개 ioSettled는 관측치이며 입력 권한이 아니다. capture가 없으면 모든 promise가 끝나도 recovery-required와 DB hold가 남는다. HTTP 오류 JSON은 성공처럼 생겨도 capture로 인정하지 않는다. EOF 뒤 이미 살아 있는 SDK promise의 늦은 첫 JSON은 기존 synchronous capture로 먼저 보관하며 현재 회사 삭제/가격·기한 만료 때문에 버리지 않는다. capture 영속과 모든 I/O·SDK/driver·SQL/lease 종료가 함께 확인되어야 메모리 수명을 닫는다.

기존 legacy JSON-start 경로는 유지한다. SDK형 경로는 원래 Response 객체 대신 제한된 buffered view를 사용하며, 기존 시험 두 곳은 그 객체 신원과 빠른 network 거절/원래 I/O 미종료의 구분을 반영했다. 기존 명령·요청·원장 bytes/승인·금액·보관 한도는 바꾸지 않았다.

실제 SDK 모듈 import/생성/실행·global fetch·키/환경/공식 가격 설정·고객/운영 DB/control/lock·route/UI/production 설치·외부 전송은0이다. source synthetic-comparison-execution·공개 owner:null·runtimeObserved:false·authority:false를 유지한다. 합성 수신 제한/SQL COMMIT 관측을 실제 SDK 호환·사람 동의/공식 가격·AI 의미 품질로 승격하지 않는다.
