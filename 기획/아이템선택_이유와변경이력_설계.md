# 17. 아이템 선택 이유와 변경 이력

상태: 설계안. 14–16번 제품 검증과 소스 고정이 끝난 뒤 구현한다. 이 문서는 현재 제공 기능이나 기관 판단을 뜻하지 않는다.

## 기존 요구와 현재 누락

- `아이템도출_사업계획서자동작성_상세기획.md` 4.3은 다른 후보를 선택할 때 이유와 변경 이력을 기록하고 전체 원고를 해당 주제로 다시 검토하도록 요구한다. 4.2의 자동 추천 이유와 사용자가 선택한 이유는 서로 다른 기록이다.
- `혁신성장유형_서비스기획_v1.md`의 데이터 항목 표는 신청 아이템·전략에 후보, 비교 근거와 선정 이유를 포함한다.
- 현재 `web/src/components/studio/analysis-panel.tsx`는 후보 카드에서 `select-candidate`와 후보 ID만 전송한다. `studio-storage.ts`의 해당 분기는 `selectedCandidateId`를 덮어쓰고 다른 후보 원고의 `confirmedAt`을 해제한다. 사용자 이유·선택 당시 후보·전후 선택 이력은 남지 않는다.
- `StudioStore.beginPreparation()`의 `continue`도 후보 ID를 직접 변경한다. 분석 화면만 바꾸면 이 경로에서 이유 없는 선택이 가능하다. 새 분석과 자료 변경은 선택을 해제하므로, 현재 분석이 교체된 뒤에도 과거 선택 내용을 따로 보존해야 한다.

## 최소 완결 흐름

후보의 추천 설명·부족 자료 확인 → 후보 선택 또는 기존 선택 이유 기록 → 사용자가 이유 입력 → 정확한 현재 분석·후보를 서버에서 확인하여 선택과 이력을 함께 저장 → 과거 선택과 이유 조회 → 선택한 주제의 원고 생성·기존 버전 재검토로 이동한다.

자동 추천 설명을 사용자 이유로 채우거나, 순위·점수로 후보를 자동 선택하지 않는다. 선택은 전략 기록이며 사실·기관 적합성·원고 검토 완료를 의미하지 않는다. 원고 자동 재생성, 공식 전송, 외부 AI 호출은 이 저장 동작에 포함하지 않는다.

## 입력·저장 계약 제안

기존 PATCH `select-candidate`를 strict 요청으로 확장한다. 필수 입력은 `revision`, `clientRequestId: UUID`, `candidateId: 1..300자`, `analysisGeneratedAt`, `analysisSourceRevision`, `expectedSelectedCandidateId: string|null`, `reason: trim 후 1..2000자`다. 기록자 이름은 이 최소 범위에 추가하지 않는다. 후보 ID는 기존 분석에서 UUID가 아닌 값도 허용하므로 UUID로 제한하지 않는다.

서버는 같은 회사의 현재 분석을 확인하고, 요청한 생성 시각·근거 revision·현재 선택 ID가 모두 일치하며 후보 ID가 정확히 한 개일 때만 저장한다. 회사 revision의 CAS가 기본 경계이고, 분석·후보 digest는 서버가 계산한다. 클라이언트가 후보 스냅샷·시각·검토 결과를 임의 저장하지 못하게 한다. 선택 이유 없는 구형 쓰기 요청은 명확한 오류로 거부하고, 기존 저장 데이터의 읽기는 유지한다.

`StudioCase.candidateSelections`는 기본값 `[]`인 추가 전용 배열이다. 기록에는 다음 값을 둔다.

- 서버 `id`, `clientRequestId`, 정규화 요청의 `inputDigest`, `recordedAt`, `origin:'manual'`.
- `event:'selection'|'reason-recorded'`: 실제 후보 변경/최초 선택과 이미 선택된 후보의 이유 추가·정정을 구분한다. 같은 후보라도 새로운 이유를 기록할 수 있으며 과거 이유는 덮어쓰지 않는다.
- `reason`, 선택 전 후보 ID 또는 null, 선택 후 후보 ID.
- 분석 당시 `generatedAt`, `sourceRevision`, `mode`, 전체 분석 digest와 선택 후보 digest.
- 선택 후보 스냅샷 및 같은 분석에서 유일하게 해석되는 이전 후보 스냅샷. 제목·설명·추천 이유·부족 자료·연결 근거는 해당 후보에 한해 보관한다. 이전 ID가 현재 분석에 없거나 중복이면 스냅샷을 추정하지 않고 `previousContext:'unavailable'`로 기록한다.
- 직전 보존 기록 ID 또는 null. 이 연결은 저장 순서이며, 이전 분석에서 현재까지 선택이 계속 유지됐다는 증명이 아니다.

전체 분석의 다른 후보·회사 자료 본문·계정·파일 경로는 이력에 복제하지 않는다. 후보 스냅샷도 현재 후보 스키마를 그대로 신뢰해 무한 보관하지 않고, 기록 수 100개·기업별 이력 문자열 합계 20만 자·요청 본문 16KiB 한도를 제안한다. 한도 초과는 기존 이력 삭제나 내용 잘라내기 없이 거부한다. 과거 후보의 근거 인용은 ‘선택 당시 연결 표기’이며 원본 진위나 현재 근거 검증으로 표시하지 않는다.

기존 회사의 현재 선택에 기록이 없으면 ‘기존 선택 · 선택 이유 기록 없음’으로 보여 준다. 이유·시각을 소급 생성하지 않는다. 사용자가 현재 후보를 다시 확인해 이유를 남기는 별도 동작은 허용한다.

## 원고 및 연속 준비 연결

- 후보가 실제로 바뀌면 기존 원고의 내용·버전·연결 근거·개별 검토 판단 이력은 보존하고 내부 전체 검토 표시를 해제한다. 기존 내용의 `needsConfirmation`을 변경하여 과거 원고 해시를 깨뜨리지 않는다. 화면에는 후보 변경 후 전체 원고 재검토가 필요함을 표시한다.
- 같은 후보의 이유 추가·정정만으로 내용 재작성이나 사실 확인을 수행하지 않는다. 이 기록을 자동으로 원고 본문, ZIP, AI 입력에 넣지 않는다.
- `beginPreparation(continue)`는 후보를 별도로 선택하는 경로가 아니라 현재 분석에서 이유와 함께 저장된 선택을 이어가는 경로로 바꾼다. 회사의 현재 선택 ID, 서버 계산 분석·후보 digest, 현재 분석에 대응하는 선택 기록이 모두 맞아야 한다. 이유 저장 후 새 회사 revision으로 이어간다. 일치하지 않으면 아이템 분석 화면에서 명시적으로 선택·이유 저장을 먼저 하도록 안내한다.
- `start`도 구형 이유 없는 선택을 자동 승인하지 않는다. 기존 분석과 원고는 보존하되 선택 이유 확인 단계에서 대기한다. 현재 분석의 유효한 선택 기록이 있으면 재사용한다. `resume`은 기존 체크포인트를 보존하며 새 선택이나 이유를 만들지 않는다.
- 자료 변경·재분석에 따른 선택 해제는 사용자 후보 변경으로 꾸미지 않는다. 과거 이력은 그대로 남고, 현재 선택과 과거 기록이 다른 분석에 속함을 표시한다.

## 화면과 상태 보호

`AnalysisPanel`의 후보 버튼은 선택 이유 편집기를 연다. 추천 이유와 사용자 입력을 따로 보여 주고 이유 입력은 빈 값으로 시작한다. 이미 선택된 구형 후보에는 ‘선택 이유 기록’, 현재 이유가 있는 후보에는 ‘이유 추가·정정 기록’을 제공한다. 과거 목록은 저장 시각·전후 후보 제목·분석 시점·사용자 이유·당시 추천 설명을 접어서 표시하며 현재 분석과 다른 기록에는 과거 표기를 붙인다.

편집 중 자료 재분석·다른 후보 선택·원고 생성·로컬 준비 진행을 막고, 기존 상위 dirty/busy 보호에 합산한다. 회사 ID·revision 변경 시 기존 편집기 응답을 폐기한다. 실패하면 입력 이유와 동일 nonce를 유지한다. 수정된 payload에 이전 nonce를 재사용하지 않으며, 응답이 불확실한 동안 자동 재요청하지 않는다. ACK는 회사·정확 nonce·후보·분석 binding·이유를 확인한다.

## 파일과 검사 범위

새 `studio-candidate-selection-types.ts`에 pure DTO·schema·현재 선택 기록 판별을, `studio-candidate-selection.ts`에 서버 digest·추가 전용 저장 준비를 둔다. `studio-schema.ts`, `studio-storage.ts`, case PATCH의 strict action/본문 한도, `studio-preparation.ts` 및 관련 저장 경계에 연결한다. UI는 새 `candidate-selection.tsx`와 `analysis-panel.tsx`의 최소 변경, 상위 dirty 연결 및 `preparation-panel.tsx`의 선택 대기 안내로 제한한다. 공통 타입의 역참조는 type-only로 순환 의존을 피한다.

합성 자료·임시 SQLite로 최초 선택, 변경, 동일 후보 이유 정정, 기존 회사, 새 분석·동일 ID 내용 변경, 중복 후보 ID, 다른 회사, 오래된 CAS, 예상 전후 ID 불일치, 같은 nonce 재전송·변경 payload 충돌, 저장 실패 원상복구, 이력 한도와 과거 원고 보존을 검사한다. 로컬 준비 start/continue/resume에서 이유 없는 선택을 만들지 못하는 회귀가 필수다. UI는 빈 이유 차단·추천 이유 자동 복사 없음·미저장 편집 보호·불확실 응답 유지·HTML escaping·다른 분석의 과거 스냅샷 표시를 확인한다. 외부 AI·공식 runner 호출과 기관 단계 변경은 0회여야 한다.
