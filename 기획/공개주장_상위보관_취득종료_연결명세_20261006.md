## 3. 명시 종료와 표시 해제의 최소 입력/순서

상위 종료는 이미 보관한 동일 screen/retainer, 현재 화면의 token/등록, 현재 frame 또는 실제 자식 해제 수단, 원래 I/O 참조를 계속 보관할 호출자를 전제로 한다. 회사 원문·결과·원장을 새로 복제하는 종료 입력은 없다.

1. 명시 종료 의도를 같은 screen에 전달해 새 attach/prepare/start를 닫는다. ordinary cleanup/StrictMode probe는 여기로 연결하지 않는다.
2. 현재 frame의 `open:false`가 React에 commit되거나 실제 자식/root가 unmount돼 이전 표시가 비워지는 책임을 별도로 둔다. setState 호출만으로 commit 완료를 주장하지 않는다.
3. 구독 해제·표시 무효화·요청 취소는 원래 I/O 객체 폐기가 아니다. 호출자는 closed인 원래 두 객체를 강하게 보관한다.
4. 같은 entry의 원래 aggregate completion과 fresh `canForget:true`가 확인된 경우에만 기존 retainer가 I/O entry를 해제한다. 캐시된 React snapshot은 fresh 해제 증거가 아니다.
5. 서버 SQL/guard/lease·pending ack/불명 명령/cleanupRequired의 복구는 원래 같은 service 책임이다. close/release로 retire/session close/recover/ack·INSERT·정산/hold 해제를 호출하지 않는다.

현재 `screen.close:173`은 subscriber를 먼저 지운다. `publish:47`의 queue는 실행 시 현재 subscriber를 읽으며 없으면 listener를 호출하지 않는다. `selectDisplay:114`는 이후 렌더에서 null이지만 useSyncExternalStore에 변경 통지가 오지 않으면 기존 DOM이 바로 갱신된다는 보장이 없다. 이것은 소스에서 확인한 한계이며 이번 브라우저 재현/수정은 없다.

4I46의 `review-react.test.ts:167`은 오류 표시→parentClose 뒤 retained.closed/occupied/canForget를 대조한다. close 뒤 DOM display가 비었는지는 단언하지 않았다. `comparison-review-react-browser.tsx:146`의 parentClose는 close만 호출하며 props 갱신이나 render를 호출하지 않는다. 과거68/68 통과를 이 미검증 범위에 확대하지 않는다.
