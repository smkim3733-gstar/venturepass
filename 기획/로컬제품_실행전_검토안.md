# 로컬 제품의 실행 전 검토안

작성일: 2026-09-26. 로컬 제품의 구현 범위와 실제 신청·운영에 필요한 다음 결정을 정리한다. 회사 자료의 값·자격정보는 이 문서에 복사하지 않는다. 기능별 최종 검사 상태는 `제품완성_개발로드맵.md`와 `../web/VALIDATION.md`를 기준으로 확인한다.

로컬 개발 1~29 및 R01~R11의 독립 구현·검증은 완료했다. 최종 3,712개 테스트·타입·lint·격리 빌드·합성 API와 실제 UI를 통과했다. 실제 기관 신청이나 공유 서비스 운영 완료를 뜻하지 않는다.

## 1. 사용 흐름

1. 로컬 앱의 기업 작업공간에서 기업정보와 자료를 확인한다. 복수 파일은 파일별 접수 결과를 확인하고, 미검토 판독문은 원본과 대조한 뒤 본문으로 채택한다.
2. 필요한 경우 해당 기업의 **자료 변경 후 로컬 준비 연결**을 켠다. 켜기 이후의 저장 변경만 모으며, 해당 기업 화면이 보이고 편집·다른 작업이 없을 때 준비를 이어간다. 화면을 닫아도 이미 시작한 작업이 취소되는 것은 아니므로 저장 상태에서 확인한다.
3. 사전진단과 후보를 확인하고 신청 아이템 및 선택 이유를 기록한다. 준비된 원고의 미확인 문장·수치·근거를 담당자가 검토한다. 제품의 규칙 검사 통과와 사실 확인은 구분한다.
4. 기관 요청을 수동 등록하면 정확한 요청 버전에 답변 준비·근거·담당 업무를 연결한다. 답변 제안은 선택한 등록 본문에서 인용을 고르는 보조 기능이며, 명시적으로 편집기에 반영하고 별도 저장한다.
5. 검토한 원고·원본·근거 목록을 제출 준비 묶음으로 보관한다. 신청 회차에 기준·서류 조건의 정확한 버전을 고정하고, 수동 기한·연장·진행 이력과 제출본을 보존한다.
6. 실제 벤처인 입력은 현재 공식 화면과 계정의 기업 일치를 다시 확인한 뒤 진행한다. 정확한 값·원본·대상을 검토한 승인 범위에서만 실행하며, 공식 접수 결과를 보기 전에는 접수 성공으로 기록하지 않는다.

외부 AI 문서 판독·음성 전사·답변 인용 제안은 각각 선택한 대상·전송 내용·목적지·모델을 검토하는 별도 실행이다. 로컬 준비 연결을 켜는 동작에는 이 외부 실행 권한이 포함되지 않는다. 외부 결과가 불명확하면 자동 재전송하지 않는다.
