## 1. 같은 실행을 보관하는 경계

기존 createIsolatedPublicComparisonExecution은 같은 private factory가 만든 execution을 반환한다. 새 createIsolatedPublicComparisonService는 그 factory의 execution과 비공개 canRelease closure를 같은 지역 수명에 보관한다. 기존 엔진의 SQL13·증인3·owner/lease·private writer·전체 감사·decoder/금액 산술은 그대로 사용한다. 새 표/원장/승인 owner·전역 등록부/설치·production-server import는 없다.

서비스 생성 시 원래 session/회사 guard와 합성 driver를 고정한다. 명령에서 이를 대체하거나 새 SDK/options/키를 받을 수 없다. constructor는 current·시계·환경·driver 인증/SDK 준비를 실행하지 않는다. execute는 원래 command/current를 그대로 기존 엔진에 넘겨 nonce/전체 명령 감사 우선 순서를 유지한다. 새 dispatch COMMIT·회사 읽기 종료·재감사와 정확한 ack를 직접 관측한 같은 내부 호출만 전송 capability를 보유한다.

ready는 retirement 전이라는 표시일 뿐 새 실행 허가가 아니다. 서비스는 한 execution만 갖고 replace/reset API가 없다. 별도로 만든 객체가 같은 session에서 실행을 시도해도 기존 lease가 새 시작을 거절한다. 그 객체를 만들었다는 사실이 원래 서비스의 책임을 폐기하지 않는다. 프로세스 재시작/HMR 보관이나 자동 설치를 추가한 것은 아니다.

## 2. 공개 포트와 비공개 해제 판단

| 포트 | 동작 |
|---|---|
| execute(command,current) | 원래 엔진의 safe view promise를 반환. 동시 원래 nonce 관측은 새 전송 없이 반환. pending Set은 원래 대기 promise를 중복 관측 promise로 덮어쓰지 않음 |
| recover(selection) | 원래 runId/dispatchCommandDigest만 기존 엔진에 전달. 원래 capture/nonce/bytes의 조회·정확한 ack 복구이며 새 current/driver/SDK 준비 없음 |
| inspect() | synthetic-comparison-service·ready/draining/closed·activeCalls·원래 safe execution view만 반환 |
| retire() | 단조 retirement. 새 execute를 닫고 원래 callback/명시 recover를 유지. 자동 취소·DB hold 해제 아님 |

canRelease는 모듈 외부로 내보내지 않으며 공개 boolean/view/token을 입력으로 받지 않는다. lease 비활성·실행/회사 읽기 없음·pending/dispatch 불명 없음·private owner 없음·원래 network/SDK/I/O 종료·body cleanup 실패 없음·driver 종료 또는 확정된 미사용 상태를 함께 확인한다. 공개 phase/activeCalls/retainedCaptureCount/promiseSettled 중 하나만으로 판단하지 않는다.

retire 후 서비스의 pending 호출까지 없어지고 엔진의 비공개 조건이 충족되어야 execution 참조를 해제한다. retire 전에는 성공 뒤에도 원래 객체를 보관한다. 초기 미사용/확정된 dispatch 이전 거절은 해제할 수 있고, dispatch 이후 unknown·COMMIT/ack 불명·정리 실패는 캡처0/활성0이어도 보존한다. SQL/lease가 정리되기 전 다른 실행으로 교체하지 않는다.

## 3. 응답·중단 수명

기존 성공4MiB/오류64KiB·준비부터 한 번의120초, 단일 reader/EOF 뒤 bounded Response와 SDK 첫 JSON의 동기 capture를 유지한다. 상한은 앱에 노출된 body bytes이며 압축 wire/TLS/헤더/전체 heap 보장이 아니다.

합성 SDK가 private request.signal을 별도 wire signal로 조합하는 native any 형태와 수동 listener 형태를 다룬다. 두 signal의 객체 동일성을 요구하지 않고 최종 guard가 확인한 wire signal을 실제 합성 시작에 그대로 전달한다. 앱 deadline과 SDK controller abort 양쪽에서 원래 fetch/read/cancel 종료를 따로 관측한다.

원래 살아 있는 SDK promise의 늦은 첫 JSON은 retire/기한 이후에도 기존 capture에 보관한다. SDK형 Promise.race가 먼저 거절한 뒤 숨겨진 parser가 끝나도 밖으로 전달하지 않은 JSON은 재해독/asResponse/조회/재전송으로 만들지 않는다. 오류 body·parse 실패·중단·미전달 JSON은 unknown/hold를 남긴다.
