## 구현과 호출 경계

제품 변경은 기존 capability/회사 guard/비활성 서비스 및 읽기 사본 한도 모듈이다. writer/decoder/산술·SQL13/증인3 helper를 복제하지 않았다. 회사 guard의 readCall은 기존 registry 안에서 이 읽기 호출의 정리 책임을 구별하는 표시다. 전송 owner나 외부 입력의 권한 boolean이 아니다.

| 선택 | runId·dispatchCommandDigest·comparisonEventDigest·responseArtifactSha256·validatedArtifactSha256, strict/data-only/8KiB |
| 과거 읽기 | 저장 event와 receipt/원래 capture/context/validated artifact 전체 감사 후 원래 준비 문맥·비교 의견의 사본 |

전체 감사는 저장 event가 실제 존재하는지와 원래 response/validated bytes의 동일성을 먼저 확인한다. JSON 하나만 독립 신뢰하지 않는다. 기존 archive/request/decoder로 만든 좁은 투영도 감사된 validated body와 다시 대조한다. preview 성공이나 comparison-ready 자체는 저장 결과의 증거가 아니다. 나중 close가 원래 result 신원을 바꾸지 않는다.

## 수명과 실패 처리

| 경계 | 처리 |
|---|---|
| 원래 실행 I/O/driver/lease·unknown 미종료 | private canRelease와 원래 pending 호출로 인계 거절 |
| 불명 저장 명령/ack | retained 명령을 유지하고 원래 명시 recoverPostcapture만 허용. 읽기는 수선하지 않음 |
| 회사 획득 전 busy | unavailable 또는 인계 거절, 다른 호출의 거래 정리0 |

| 호출 표시가 다른 reader로 바뀜 | 자기 scope의 finish 거절. 새 reader를 종료하지 않음 |
| 회사/quality SQL/lease 정리 실패 | 정상 DTO 반환 금지, 서비스 draining/cleanup 책임 보존 |
| 명시 재조회 | 자기 읽기 정리만 마친 뒤 같은 selection을 다시 감사. 새 INSERT/SDK0 |
| 공개 투영 유실 | 이미 끝난 읽기를 저장/전송으로 다시 실행하지 않음. 원래 결과 명시 재조회 가능 |
| 파일/binding/증인 불일치·손상/부분행/중복 | 전체 읽기 거절. 현재 unavailable로 감추지 않음 |
| 현재 행/형식/지원 여부 미확인 | allowlist 이유의 unavailable. 별도 안전한 과거 읽기는 유지 |

quality와 studio는 하나의 일반 원자적 DB 거래가 아니다. 같은 호출의 quality 읽기 구간과 기존 일시 lease를 유지한 상태에서 studio SELECT guard를 읽고 역순으로 정리한다. 원래 실행/후속 저장/읽기 책임을 공개 phase나 캡처 개수만으로 추정하지 않는다. 일시 lease 파일 획득/반납은 가능하므로 전체 파일 byte 불변을 주장하지 않고 DB 논리 행·증인 내용·회사 revision/body 불변을 검증한다.

exact-original-request는 선택한 원래 원고 버전에서 요청이 일치했다는 관측이다. 다른 최신 원고, 공식 출처 진위, 회사 적용성, 의미적 진실, 수동 판단·원고 채택 권한은 여전히 없다. comparison result의 supplied-response/manual-unverified·currentContextVerified:false를 유지한다.
