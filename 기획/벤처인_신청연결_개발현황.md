## 공식 연결 구현 이력 (2026-09-25 오후)

검토한 텍스트·단일 선택·원본 파일을 1회 입력·첨부하는 실행 단계와 승인 UI를 추가했다. 선택 항목의 입력 준비와 전체 제출 준비를 분리했다. 기업·계정·세션·화면·버전·확인한 연결값·원본 검증은 유지하며, 선택하지 않은 필수 항목·동의·계획서 보완은 남은 제출 과제로 표시한다. 계획서 원고를 선택하면 최신 작성본과 내부 검토가 필요하다. 알 수 없는 오류는 차단한다. 준비한 기업·공식 주소·값·파일명·크기·형식·SHA256을 보고 이번 선택 범위의 전송을 승인한다. 승인 유효기간은 2분이고 변경·만료·실행 시도 후에는 재사용하지 않는다. 실제 기업의 공식 단위·최신 근거·기업 일치 등 보완사항은 미완료로 유지했다.

첨부 실행과 화면 간 연결을 이어 개발했다. 해당 기업의 자료 ID로 보관 원본을 읽어 경로·링크·파일 상태를 검사하고, 준비와 실행 시 해시를 대조한다. 승인한 바이트만 표준 file input에 설정하며 파일만 있는 화면도 지원한다. 입력·첨부 후 전체 값과 파일 해시 및 화면 상태를 다시 확인한다. 최대 10개 파일, 개별 12MiB·합계 24MiB는 앱의 처리 제한이고 기관 제한과 구분한다.

신청 진행 단계 7개와 최근 12개 화면 이력을 표시한다. 공식 화면에서 다음 단계로 이동한 뒤 ‘다음 화면 연결’로 새 화면을 읽으며, 이전 실행 결과를 보존하고 대응표·승인은 새로 준비한다. 이 버튼은 공식 사이트의 다음·저장·동의·제출 버튼을 누르지 않는다. 가상 기업으로 텍스트 화면 실행부터 새 첨부 화면 연결·승인·실행·저장소 재시작 후 이력 복원까지 통합 검증했다.

납입자본금·결산월의 구조화 입력과 공식 항목 대응을 추가했다. 기존 기업 기록에는 빈 기본값을 적용하며 재무 근거 메모를 보존한다. 10:07에 확인된 원자료 값을 앱의 두 개별 항목에 저장했다. 연결안은 원래 값과 단위·재무 근거 메모를 함께 보여 주며 계획서 없는 기업정보 미리보기도 제공한다. 계획서·기업 일치·동의 등 제출 전 검사는 유지하고, 기업정보 변경 시 이전 값의 확인 표시는 무효화한다.

선택 항목 준비·원본 보관·현재값 대조·텍스트 부분 실행 복구·단계 이력·기관 요청/답변/통보 5분류·원본 증빙·최초 쓰기 문맥 및 최종 완료 대조까지 반영한 최종 소스의 전체 32개 파일 1,303개 테스트와 ESLint·TypeScript 검사를 통과했다. Windows DPAPI는 가상 계정으로 시험했고 건너뛴 검사는 없다. 기관 요청과 답변은 진행 관리의 별도 추가 전용 기록으로 보관한다. 요청 원문·기한 근거·정정·답변 버전과 같은 회사 원본의 SHA256을 연결하며 참조 원본 삭제와 바뀐 원본의 재연결을 차단한다. 납부·접수·실사·결과·확인서 통보도 별도 최초 통보 ID와 정정 이력으로 보관한다. 분류를 정정해도 과거 본문·원본을 보존하고 요청/답변 체인에 섞지 않는다. 선택 상세값은 비워두면 미확인이며 날짜·금액·기관 상태·유효기간을 추정하거나 진행 단계를 바꾸지 않는다. 읽기 전용 원본 대조와 안전한 현재 파일 다운로드를 제공한다. 이는 담당자 기록과 파일 동일성 확인이며 기관 발송·접수·납부·확인서 진위의 자동 확인이 아니다.

화면 수집과 연결안은 별도 로컬 테이블에 보관한다. 일반 기업 JSON, AI 작성 입력, 자격정보 저장소와 분리된다. 클라이언트가 공식 화면 스냅샷을 주입하거나 실제 제출 명령을 호출할 수 없다.

일반 준비 공지는 사전 로그인 확인 이력과 정확한 공식 주소·제목·전체 본문을 확인한 경우에만 제한된 안내 영역 안의 `확인`을 한 번 시도한다. 클릭 직전 내용을 다시 검사하며 입력·동의 요소나 추가 동작이 있으면 중단한다. 확인된 사전확인 주소로 이동한 뒤에도 새 화면의 로그인 표시를 다시 확인한다.

유형 카드 클릭 후에는 정확한 공지 표시 또는 공식 사전확인 주소로의 전환을 기다린다. 사전확인에서는 로그아웃 표시 또는 속성을 검증한 모바일 메뉴 준비를 총 15초 이내에서 기다린 뒤 기존 로그인 검사를 수행한다. 문서 전체 로딩 이벤트가 지연되어도 실제 필요한 메뉴를 기준으로 검사할 수 있다. 원본 URL과 연결 상태를 다시 검사하고 준비 신호만으로 로그인 성공을 판정하지 않는다. 카드 재클릭이나 작업시간 연장은 하지 않는다.

필수 여부는 HTML 속성뿐 아니라 연결된 라벨·직접 대응하는 표 제목의 명확한 필수 표시를 반영한다. 부정·조건부·상충 표시와 여러 입력의 공통 표시는 경고로 남기고 다른 필드에 전파하지 않는다. 실제 09:08 조회에서 자본금·결산월의 필수 인식을 확인했다. 이미 공식 origin과 정확한 사전확인 pathname에 있으면 `혁신성장유형 화면 확인`도 기존 현재 화면 읽기로 처리한다. 쿼리·해시를 재작성하거나 탐색에 사용하지 않고 현재 URL을 보존하며, 새 로그인 표시와 읽기 전후 원본 URL 일치를 확인한다.

## 실제 화면에서 확인한 이력

- 10:25 새 로그인 세션에서 사전확인 10개 항목을 다시 읽고 10:27 자본금·결산월의 기업정보 연결안을 로컬에 저장했다. 계획서가 없는 상태에서도 두 값·단위·근거 메모를 저장된 미리보기로 확인했으며, 미확인 대응과 제출 전 보완 상태를 유지했다.
- 09:38 최종 수정 후 유형 선택 화면에서 혁신성장유형 명령 한 번으로 일반 공지 확인과 사전확인 화면 10개 항목 조회·저장을 완료했다. 중간 로그인 상태 재개나 별도 현재 화면 읽기 없이 연결을 유지했다. 자본금·결산월의 필수 표시를 인식했으며, 공식 입력·동의·제출은 실행하지 않았다.
- 공식 로그인 후 모바일 메뉴의 로그아웃 표시를 확인했다.
- 공식 `/venturein/aply/v2`는 유형 선택을 위한 첫 화면이다. 벤처투자유형·연구개발유형·혁신성장유형·예비벤처유형 바로가기가 표시된다. 이 화면에는 연결할 기업번호·원고 입력칸·첨부칸이 없었다.

- 해당 관측 당시에는 기업정보와 작성본이 준비되지 않아 기업 일치나 제출 준비 완료로 처리하지 않았다. 이후 원자료 확인과 로컬 기업정보 저장은 위 09:05 현재 상태에 반영했다.

## 다음 연결 작업

1. 원자료에서 확인한 정보와 미확인인 최신 재무 확정 여부·현재 주업종을 구분하여 요건 화면의 대응표를 준비한다. 자본금·결산월 구조화 입력과 값·단위·근거 미리보기는 구현했으며, 자료의 최신성·공식 단위와 화면의 확인·동의 검토가 남아 있다.
2. 현재 Edge 화면을 다시 읽고 공식 화면의 기업정보와 저장된 사업자등록번호를 정확히 대조한다. 기업명만으로 자동 연결하거나 과거 화면의 확인을 재사용하지 않는다.
3. 실제 기업자료와 검토 완료된 최신 작성본으로 대응표·첨부 목록을 완성한다.
4. 텍스트·단일 선택·파일 첨부 실행기와 구체적인 전송 승인 검토안, 화면 간 연결과 실행 이력을 구현했다. 가상 자료의 검증 이후 실제 회사의 보완사항을 해결하고 공식 화면의 실제 값·파일 처리와 서버 응답을 별도로 검증한다.
5. 약관 동의·최종 제출·납부 등은 별도 승인을 받고 수행하며, 기관의 접수 결과를 확인하기 전 성공으로 기록하지 않는다.

텍스트 입력·첨부 실행 경로를 구현했지만 실제 회사 정보의 공식 입력·업로드는 수행하지 않았다. 별도 업로드 버튼·임시 저장·동의·최종 제출 실행기는 미구현이다. 사이트 자체 동작으로 입력값·파일이 즉시 전송·저장될 수 있으므로 승인 화면에서 안내하며, 실행 완료는 화면 값·선택된 파일 내용의 확인만 의미한다. 로컬 점검 통과나 가상 화면 검증을 기관 제출 성공으로 해석하면 안 된다.
