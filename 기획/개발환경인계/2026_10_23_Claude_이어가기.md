## 실행 환경과 검증

Node **24.x**, pnpm **11.19.0**, 기존 `web/pnpm-lock.yaml`을 유지한다. 새 clone만 정확한 버전으로 설치하고 기존 환경은 이유 없이 재설치하지 않는다.

```powershell
node --version
pnpm --version
Set-Location web
pnpm install --frozen-lockfile
pnpm dev --port 3022
```

pnpm이 없다면 `pnpm@11.19.0`을 별도 도구 폴더에 설치하고 `node <도구폴더>/node_modules/pnpm/bin/pnpm.cjs`로 실행한다. 글로벌 업그레이드나 lockfile 재생성으로 우회하지 않는다. 3022는 예시이므로 사용 여부를 먼저 확인한다. loopback과 새로운 개발 데이터 위치를 사용하며 기존 3021 검토 서버·데이터를 재사용/종료하지 않는다. API 키 없이 로컬 자료·원고 흐름을 사용할 수 있다. 실제 키·유료 호출은 별도 결정이다.

제품 변경은 **정적 의존 → 영향 시험(maxWorkers 1) → 필요한 격리 합성 UI → lint → 격리 typecheck → 격리 build** 순서로 각 종료를 확인한다. 설치된 `node_modules/next/dist/docs/`에서 해당 버전 지침을 읽는다.

- 영향 시험: `pnpm exec vitest run <정확한 시험 파일> --maxWorkers 1`.
- lint: `pnpm lint`.
- typecheck: `scripts/build-local.mjs`의 `prepareLocalBuild()`로 만든 사본에서 `next typegen`, `tsc --noEmit`를 순차 실행한다. 원래 `.next`를 변경하지 않는다.
- build: `node scripts/build-local.mjs`. `TEMP/TMP`는 OneDrive·저장소 밖의 실제 쓰기 가능한 임시 경로를 사용하며 보호 검사를 끄지 않는다.
- 시연: `node --test --test-concurrency=1 examples/scheduling-simulation/engine.test.cjs`, `node examples/scheduling-simulation/build.mjs`.

최근 본체는 관련46개 시험·lint·격리 typecheck/build 종료0이 기록되어 있다. 품질 백업255개·회사 자료 CLI74개도 이미 통과했다. 이는 합성 검증이며 실제 운영 복원·AI 품질·기관 성공 증거가 아니다. 이관만을 이유로 전체 검사를 반복하지 않는다.
