## 다음4I1 구현 명세 — 아직 구현하지 않음

### 입력 준비

- 읽기 전용 내부 함수에 이미 읽은 회사 snapshot과 명시 선택을 전달한다. 저장소/키/SDK/network를 함수 안에서 읽지 않는다.
- strict 선택: 회사 ID/revision, 고유한 저장 claim record ID/version/inputDigest, 공개 근거 source ID 부분집합1~10개. 임의 URL·키·회사 본문·공급 응답/권한 플래그는 선택 입력에 받지 않는다. 요청 선택은8KiB 이내다.
- 원래 claim의 plan ID/version/sectionKey/claimQuote와 현재 원고를 대조한다. 주장 최대1500자, 해당 항목 전체 문맥 최대18000자를 보존한다. 문장의 일부만으로 이미 적힌 제한을 지우지 않는다.
- claim schema와 전체 원래 inputDigest를 기존 claimReviewInputDigest로 대조한다. 원고 contentSha256·선택 자료의 textSha256 및 source snapshot 신원을 다시 계산한다. claimReviewContext는 빠른 현재 표시로 재사용할 수 있지만 단독 신뢰 조건은 아니다.
- 선택된 자료는 원래 claim.references 안에 있어야 하며 각 자료가 고유하고 동일 updatedAt/본문 hash/정확한 인용이어야 한다. 중복 ID/원래 snapshot 누락/모순·같은 revision의 내용 변경은 거절한다. 새 권한을 만들기 위해 기존 수동 기록을 수정하지 않는다.
- 최초 범위는 readManualPublicEvidence로 정확히 읽히는, 원본 첨부가 없는 수동 공개 후보만 지원한다. 원래 reference.quote도 수동 draft.quote 안에서 정확히 찾을 수 있어야 한다. 수치 이관 기록은 편집 가능한 수동 발췌로만 남긴다. JSON 모양의 본문을 검증된 API 관측으로 역변환하지 않는다.
- 선택 공개 발췌는 전체를 복사하고 메타데이터(수동 제목/URL/발행처·발행일/기준 기간/읽은 날짜)와 담당자 관련성·상충 메모를 구분한다. 과거 수동 judgement·외부확인 진술·numeric/plan-review 판단은 모델 정답/독립 검증으로 넣지 않는다.
- 선택하지 않은 원래 reference는 ID 목록으로만 남기고 본문을 보내지 않는다. 그것들이 없다고 전체 주장에 근거가 없다는 결론을 만들지 않는다. 원고의 다른 항목·회사 profile·전체 sources를 자동 포함하지 않는다.
- 준비본은 caller 변경의 영향을 받지 않는 사본이다. 원래 대상/선택/문맥·자료/계약 버전을 digest로 결합한다. 입력 전체24만자 한도는 기존 상수를 재사용하며 초과는 거절한다. 한도 내로 조용히 자르거나 일부 source를 누락하지 않는다.
- 출력은 준비본이며 AI 동의/토큰 적합성/예산/전송 권한을 만들지 않는다. 이후 실제 요청에 쓸 때 system/schema를 포함한 전송 크기는 기존 정확한 preview/builder 경계에서 다시 대조해야 한다.

### 응답 대조

- 4I1은 공급된 합성 응답을 엄격하게 검증하는 순수 경로다. source는 supplied-response로 고정하며 provider-response라는 주장을 caller에게서 받아들이지 않는다.
- 원래 준비본 digest·그대로의 claimQuote, 선택 범위에 대한 overall 관계 의견, source별 관계/정확한 원문 인용·이유/남은 질문을 받는다. 관계는 provided-text-support / provided-text-conflict / insufficient / undetermined의 제한된 enum으로 둔다. 이름은 “제공된 발췌 범위의 비교 의견”임을 표현한다.
- source별 결과는 선택한 모든 source ID를 정확히 한 번씩 포함한다. 각 결과의 인용은 해당 공개 draft.quote 내 문자 대조, 최대1500자·자료당최대3개다. support/conflict 의견에는 적어도1개 인용을 요구한다. 부족/유보는 인용0개를 허용한다. 다른 자료/추가 결과·중복·임의 출처를 거절한다.

### 기존 경로 재사용과 완료 기준

기존 원장·승인/예산/취소·원래 nonce 복구는 다시 만들지 않는다. 오래된 v1/v2 지침·request bytes·완료 run과 일반 findings schema를 바꾸거나 기존 두 호출 권한에 새 비교 호출을 끼워 넣지 않는다. 이후 실제 실행 연결에서 새 계약 digest/정확한 요청과 같은 전송 경로가 결합돼야 한다. 이번 내부 구현에는 새 route/UI/SDK/AI 호출·DB writer·운영 설정 변경이 없다.
