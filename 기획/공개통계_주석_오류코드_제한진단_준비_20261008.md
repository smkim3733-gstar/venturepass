## 공식 근거와 로컬 진단 정책

[공식 KOSIS 공유서비스 개발가이드](https://kosis.kr/openapi/file/openApi_manual_v1.0.pdf)의 16쪽 1.4절을 키 없이 읽고 렌더링해 확인했다. 공식 표는 코드10/11/20/21/30/31/40/41/42/50을 설명한다. 10·11은 인증 관련, 20·21은 요청 입력 관련, 30·31은 조회 결과 관련, 40·41·42는 이용량/이용 제한 관련, 50은 서버 측 오류에 해당한다. 이 표를 현재 응답의 원인이나 모든 API의 완전한 오류 목록으로 확대하지 않는다.

매뉴얼의 형식 예시는 XML의 error/err/errMsg다. JSON 객체의 코드 타입·누락 필드·중복·추가 속성 처리까지 보증하지 않는다. 아래는 공개 코드 표를 이용한 **앱 밖 임시 진단 지원 정책**이며 실제 KOSIS JSON wire 규격 확정이 아니다. 검색엔진에 나온 데이터 API URL/예제키는 열거나 사용하지 않았다. 공식 문서 GET는 실제 데이터 API 호출에 포함하지 않는다.

- 기존 strict UTF-8/JSON.parse를 통과한 최상위 객체만 대상으로 삼는다. 본문을 수정하거나 따옴표를 보정하지 않는다.
- err가 정확한 두 자리 ASCII 문자열이고 허용목록과 일치할 때만 고정 map에서 코드값을 반환한다. 숫자·공백·줄바꿈·자릿수·전각문자 등의 입력은 변환하지 않는다.
- errMsg는 있으면 문자열이어야 한다. 내용은 해석·대조·복사·기록하지 않는다. 없는 errMsg도 코드 진단만 가능한 로컬 정책으로 구분한다.
- err와 code/error가 함께 있거나 code/error가 둘 다 있으면 값이 같아도 충돌 형식으로 분류하고 코드를 기록하지 않는다. code/error만 있으면 미지원 속성이다. 다른 이름으로 코드를 찾아다니거나 중첩 객체를 해석하지 않는다.
- 엄격한 JSON 문법 확인 후 문자열 경계·깊이만 순회해 최상위 중복 속성을 판정한다. escape로 같은 이름을 쓴 경우도 중복이며, 문자열 내용의 가짜 키·중첩 키는 최상위 키로 취급하지 않는다. 이 순회는 JSON 복구/수락기가 아니다.
- main classification은 TOP_LEVEL_NOT_ARRAY, rowCount:null, rowSchemaAccepted:false를 유지한다. providerError의 고정 분류/허용 코드만 추가한다. 오류를 빈 주석 배열/성공으로 만들지 않는다.

| 고정 분류 | 의미와 기록 |
|---|---|
| DOCUMENTED_CODE | 지원 형식에서 공개 코드와 일치; code는 고정10종 중 하나 |
| UNKNOWN_CODE | 두 자리 문자열이지만 공개 허용목록 밖; code:null |
| MALFORMED_CODE / MALFORMED_MESSAGE | 타입·코드 철자 또는 메시지 타입이 로컬 지원 형식 밖; code:null |
| DUPLICATE_FIELDS / CONFLICTING_CODE_FIELDS | 최상위 중복 이름 또는 여러 코드 속성; code:null |
| UNSUPPORTED_CODE_FIELD / UNSUPPORTED_FIELDS | 별칭/추가 속성이 있어 해석하지 않음; code:null |
| MISSING_CODE / NOT_ERROR_OBJECT | 명시 err 부재 또는 객체가 아님; code:null |

공개 코드가30으로 관측되더라도 그 요청에서 반환된 오류 코드라는 뜻만 남긴다. 해당 표의 모든 주석 부재·특정 셀/시점 적용·회사 해당성·공식 진위·사실 확인을 확정하지 않는다. unknown/충돌/형식 실패도 고정 분류 이상으로 자동 추정하지 않는다.
