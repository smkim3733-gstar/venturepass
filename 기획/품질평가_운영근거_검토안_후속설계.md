# 품질평가 운영 근거·한 건 검토안 후속 설계

작성일: 2026-09-27
상태: 설계. 읽기 전용 검토안과 이력 화면 뒤의 다음 구현이며, 운영 설정·승인·실제 AI 전송 완료를 뜻하지 않는다.

## 목적

현재 v2 검토 화면은 운영 모델·요율·문맥·보관·예산이 미설정임을 정확히 알린다. 다음 작업은 새 원장을 만드는 것이 아니라 기존 요청 builder와 금융 예약 계산을 재사용해, 합성 후보 한 건의 정확한 본문·출처·상한을 사용자가 검토할 수 있도록 만드는 것이다. 키 확인과 원격 token counting, 유료 호출 없이 준비한다.

## 1. 서버에서 고정할 운영 근거

`studio-plan-quality-provider-configuration.ts`에 모델 ID, 공식 문맥·요율·usage 해석, 보관 안내의 한 묶음을 둔다. 기본값은 미설정이다. 실제 값을 채우기 전 공식 공급자 원문을 확인하고 URL·확인 시각·인용 범위·원문 SHA·내부 재확인 기한을 기록한다. 내부 기한을 공급자의 가격 보증일로 표현하지 않는다. 확인된 후보 모델 한 개를 제안하고 운영 채택 상태와 계정 권한 확인 상태를 따로 남긴다.

공식 근거 조회는 공개 문서 읽기이며 API 인증·키 접근·유료 호출이 아니다. 기존 로컬 SDK와 요청 계약부터 대조하고 공개 정보가 필요한 부분만 공식 문서로 확인한다. 테스트용 요율·모델을 운영 근거로 채택할 수 없도록 출처 경계를 유지한다. 클라이언트가 model/URL/요율/계정/예산을 주입하는 경로를 만들지 않는다.

## 2. 가짜 예산·준비안 없이 요청을 고정한다

현재 `createProviderPreparation()`은 실제 예산 revision/head를 필요로 한다. 운영 예산이 없다는 이유로 가상의 production budget, run, manifest를 만들지 않는다. `studio-plan-quality-provider-core.ts`의 생성 요청·검토 템플릿 조립 부분만 키와 I/O 없는 공유 함수로 분리하고 기존 바이트·wire digest golden을 보존한다. v1 계약도 그대로 둔다.

그 요청과 서버 고정 근거를 `createProviderContextReservation()`에 전달하여 C+O 보수적 금융 예약액을 계산한다. 이 값은 토큰 실측·문맥 적합성·실제 견적·모든 실패의 청구 상한 보장이 아니다. 아직 생성되지 않은 검토 요청은 같은 실행의 검증된 최초 원고에서 파생하는 규칙과 상한만 제시한다.

## 3. 현재 읽기 화면을 확장한다

기존 `ProviderReviewView`의 configuration-missing 분기는 보존한다. 요청·근거를 검토할 수 있지만 예산 또는 운영 채택이 미완료인 별도 읽기 전용 분기를 추가한다. 정확한 등록 버전·후보 입력·생성 본문 바이트 SHA·wire digest·모델·공식 목적지·생성1/검토1·재시도0·단계별 예약액·보관 조건·미확인 항목을 하나의 조회 JSON에 고정한다.

영속 운영 budget/run이 없는 동안 `preparation`·`transmissionManifest`는 null, 실제 실행 권한은 false다. 금액 제안과 비용 예약을 구분한다. 운영 모델 채택·통화·누적 한도 제안은 구체적 근거와 계산을 마련한 뒤 한 번에 사용자에게 검토받는다. 앱의 기본 메뉴3개는 유지하고 기존 개발 도구의 펼침 영역을 재사용한다.

## 4. 쓰기와 실행 경계

기본 provider store의 production 쓰기 거절, synthetic-only runner, HTTP 실제 전송 폐쇄를 이번 단계에서도 유지한다. 실제 운영 경로는 고정 서버 transport와 별도 승인 계약으로 나중에 연결한다. 정확한 검토안이 완성되면 운영 예산 설정/예약 승인과 특정 run에 결합된 전송 승인을 구분한다. 기존 합성 기록·A 조회본·예약 전용 동의를 전송 승인으로 승격하지 않는다.

## 5. 합성 검증

- 기존 v1/v2 요청·digest·JSON 바이트 불변.
- 미설정·만료·공식 출처 SHA/모델 불일치·범위 누락은 실행 불가.
- 합성 설정과 클라이언트 입력의 운영 승격 거절.
- raw byte SHA와 canonical wire digest를 별도로 대조.
- 예산 없는 검토안에 가짜 run/manifest/승인·예약 기록 생성0.
- 고객 원자료·자격정보·키·외부 AI 접근0. 등록 서버 합성 후보만 사용.
- 다른 후보·버전·늦은 조회 결과 거절, 정확한 조회본 다운로드와 작은 화면 확인.

실제 AI 의미 품질, 사람 정답표와 독립 holdout, 공식 접수·결과 확인, 외부 고객 운영은 여전히 별도 남은 일이다. 이 읽기 연결을 최종 서비스 전체 완료로 취급하지 않는다.
