# 현재 PC의 VenturePass 시작·확인·복구 안내

기준: 2026-10-03. 사용자가 선택한 완료 범위는 **현재 PC에서 내부 업무에 사용하는 로컬 앱**이다.

## 1. PC를 다시 켰을 때

1. 먼저 브라우저에서 <http://127.0.0.1:3000/studio>를 연다. 기존 VenturePass 화면이 열리면 회사 목록과 최근 저장본을 확인하고 사용한다.
2. 열리지 않으면 파일 탐색기에서 `D:\개발\codex_2\벤처확인자동화앱개발_최신`을 열고 **VenturePass-start.cmd**를 한 번 실행한다.
3. 실행 창에 준비 완료가 표시되면 위 주소를 다시 연다. 사용 중에는 실행 창을 유지한다.
4. 사용을 마칠 때 편집 내용을 저장하고 실행 창에서 Ctrl+C로 종료한다. 브라우저만 닫으면 앱 서버는 계속 실행될 수 있다.

시작 파일은 이 PC에 설치된 Node와 전용 pnpm으로 기존 Webpack 실행을 시작한다. Windows 시작 시 자동으로 앱을 켜는 서비스나 다른 PC용 설치 프로그램은 이번 범위에 포함하지 않았다. 기존 소스·의존성·설정을 그대로 사용하므로 매번 설치하거나 빌드할 필요가 없다.

포트가 이미 사용 중이라는 메시지가 나오면 실행 창을 여러 개 열지 않는다. 기존 3000번 화면이 VenturePass인지 먼저 확인한다. 다른 프로그램이면 그 프로그램을 임의 종료하지 않고 충돌 상태를 확인한다. 다른 포트가 표시된 실행 창과 기존 주소를 혼용하지 않는다.

## 2. 자료와 저장 상태 확인

이 PC의 기존 사용자 자료 위치는 `C:\Users\usr\AppData\Local\VenturePass\data`다. 설정 파일은 현재 작업 루트의 `venturepass\web\.env.local`이며, 실제 자료 위치는 그 안의 `VENTURE_DATA_DIR` 값으로 정해진다. 키를 화면 캡처나 대화에 붙여 넣지 않는다.

- 회사 선택 후 회사명·자료 목록·최근 원고 버전과 저장 시점을 확인한다.
- 원고를 수정한 뒤 **수정본 저장**을 누르고 새 버전이 생겼는지 확인한다. 이전 버전은 별도로 남는다.
- 새로고침 후에도 같은 버전과 내용이 보이면 저장된 자료를 다시 읽은 것이다. 입력칸에만 쓰고 저장하지 않은 내용은 재시작 후 남는다고 보장하지 않는다.
- 자료가 비어 보이면 새 회사를 재등록하거나 자료 폴더를 초기화하기 전에 실행 위치와 `VENTURE_DATA_DIR`부터 확인한다.
- 한국어 표현 점검에서 **편집 위치로 이동**을 누르면 해당 입력칸으로 이동한다. 이동만으로 사실 확인이나 문장 수정이 완료되지는 않는다.

편집 예시는 [내부 사용 편집 동선](./내부사용_편집동선_20261003.md)에 있다. 원고 내용의 정확성·근거·제출 적합성은 담당자가 확인한다.

## 3. 백업 만들기

다음은 현재 PC의 자료 설정을 유지하는 PowerShell 예시다. `VENTURE_DATA_DIR`를 다른 곳으로 바꾼 경우 `$vpSource`만 실제 값과 맞춘다. 앱에서 저장을 끝내고 편집을 잠시 멈춘 상태에서 실행한다. 도구는 새 백업 폴더만 만들며 원래 자료와 설정을 덮어쓰지 않는다.

```powershell
$vpRoot = 'D:\개발\codex_2\벤처확인자동화앱개발_최신'
Set-Location -LiteralPath (Join-Path $vpRoot 'venturepass\web')
$vpTool = Join-Path $vpRoot '.venturepass-tools\pnpm.cmd'
$vpSource = Join-Path $env:LOCALAPPDATA 'VenturePass\data'
$vpBackupParent = Join-Path $env:LOCALAPPDATA 'VenturePass\backups'
New-Item -ItemType Directory -Path $vpBackupParent -Force | Out-Null
$vpBackup = Join-Path $vpBackupParent ('backup-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
& $vpTool data:local backup --source $vpSource --destination $vpBackup
if ($LASTEXITCODE -ne 0) { throw '백업 실패. 출력 코드를 확인하고 중단합니다.' }
& $vpTool data:local verify --source $vpBackup
if ($LASTEXITCODE -ne 0) { throw '백업 확인 실패. 복원에 사용하지 마세요.' }
Write-Output $vpBackup
```

두 명령이 모두 `"ok":true`이면 완료된 백업이다. 출력된 폴더 위치를 기록한다. `COMPLETE.json`, `backup-manifest.json`, DB, 원본 파일을 함께 보관한다. 도구가 거절하면 실패한 폴더를 완료 백업으로 취급하지 않는다.

백업 위치는 이 PC의 %LOCALAPPDATA%\VenturePass\backups다. 현재 D: 소스 루트 자체도 Git 저장소이므로 그 아래에는 백업을 만들지 않는다. 백업에는 회사 자료가 포함되므로 공유·Git·OneDrive 폴더로 옮기지 않는다. 이 예시는 같은 PC의 작업 사본 보호용이며 디스크 고장에 대비한 별도 보관 매체 정책은 정하지 않았다. 키와 브라우저 로그인 상태는 백업되지 않는다.

## 4. 새 경로에 복원한 뒤 확인하기

위 작업을 실행한 같은 PowerShell 창에서 다음을 실행한다. 다른 날의 백업을 사용하려면 `$vpBackup`에 **검증 완료된 백업 폴더의 전체 경로**를 넣는다.

```powershell
$vpRestored = Join-Path $vpBackupParent ('restore-candidate-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
& $vpTool data:local verify --source $vpBackup
if ($LASTEXITCODE -ne 0) { throw '백업 확인 실패. 복원을 중단합니다.' }
& $vpTool data:local restore --source $vpBackup --destination $vpRestored
if ($LASTEXITCODE -ne 0) { throw '복원 실패. 기존 자료 경로를 유지합니다.' }
& $vpTool data:local verify --source $vpRestored
if ($LASTEXITCODE -ne 0) { throw '복원 후보 확인 실패. 전환하지 마세요.' }
Write-Output $vpRestored
```

이 단계까지는 복원 후보만 생기며 앱은 기존 자료를 계속 사용한다. 기존 폴더를 덮어쓰거나 삭제하지 않는다.

전환이 필요하면 앱을 종료하고 기존 `VENTURE_DATA_DIR` 값을 별도로 기록한다. `.env.local`에서 **그 값만** 검증된 복원 후보 경로로 바꾸고 앱을 다시 실행한다. 회사·자료·원고 버전·내려받기를 확인한다. 문제가 있으면 앱을 종료하고 원래 값으로 되돌린다. 실제 편집을 시작하면 원래 백업의 해시와 달라지므로 복원 후보 검증은 전환 전에 마친다.

## 5. 문제가 생겼을 때

| 상황 | 다음 행동 |
| --- | --- |
| 화면이 열리지 않음 | 시작 창의 준비 완료·오류·주소를 확인한다. 기존 서버를 무작정 종료하거나 중복 실행하지 않는다. |
| 회사나 원고가 안 보임 | 현재 D: 작업 위치와 자료 경로를 확인한다. 기존 자료를 지우거나 새 빈 자료로 덮어쓰지 않는다. |
| 저장 중 오류 | 같은 원고 버전과 저장 상태를 먼저 확인한다. 저장되지 않은 내용은 별도로 보관한다. |
| `UNSAFE_PATH` | 링크·동기화 폴더·경로 교체 여부를 확인한다. 경로 검사를 해제하지 않는다. 이번 수정은 정상 한글 경로의 문자 인코딩만 바로잡았다. |
| `SOURCE_WAL_NOT_READY` | DB 보조파일을 직접 삭제하지 않는다. 앱의 정상 연결·종료 상태부터 확인한다. |
| `SOURCE_INTAKE_RECOVERY_REQUIRED` | 자료 접수 목록에서 미완료 원본 저장을 확인한다. 파일이나 DB를 직접 지우지 않는다. |
| AI·기관 작업 중 결과 불확실 | 같은 작업을 새 요청으로 반복하지 말고 원래 이력과 상태를 먼저 확인한다. |

고정 운영 평가 자료 `operational-validation-20260928`와 `-control`은 일반 회사 자료와 별도다. 완료한 운영 검증 명령을 앱 복구 목적으로 실행하지 않는다. 이번 백업 안내는 일반 회사 자료용이며 별도 운영 평가 원장·승인·외부 기록을 재작성하지 않는다.

## 확인 범위

실제 앱과 새 합성 자료를 사용해 회사 등록부터 원고 저장·서버 재시작 후 재조회까지 확인했다. 새 경로 복원은 기존 백업 도구를 사용한다. 저장 도중 전원 차단·디스크 손상 전체 상황이나 사람의 원고 내용 인수를 대신 증명하지 않는다.
