## 1. 범위와 수명

기존 studio-public-claim-comparison-database-v11.ts의 createIsolatedPublicComparisonService와 같은 private 실행 엔진을 확장한다. 같은 session/회사 파일 guard, 기존 SQL13/증인3 및 private writer·decoder·사용량 산술을 재사용한다. 새 owner/전역 registry·SQL14·원장·production import/설치·route/UI는 없다.

retire는 새 execute를 닫고 명시 후속 저장/복구를 유지한다. 실행 참조가 해제됐어도 후속 명령/자기 SQL·lease 정리 책임이 남으면 전체 서비스는 draining이다. DB의 comparisonRecorded/costSettled/finalized·금액 hold·진행 run 저장 예약은 메모리 closed와 별도다. missing usage 때문에 DB hold가 남는 상태에서도 안전하게 종료한 메모리 실행은 closed일 수 있다.

## 3. 명시 저장과 원래 명령 복구

result3행과 close8행은 독립 명시 호출이다. 결과 저장 뒤 자동 정산/hold 해제·원고 채택·수동 judgement 수정은 없다. 사전 plan과 실제 writer 모두 기존 전체 감사/원래 nonce 검사를 쓰며, 마지막 저장은 거래 안에서 다시 감사한다. 미리보기의 head/hash를 저장 권한으로 재사용하지 않는다.

새 명령은 검토/정책/head/용량과 current를 기존 planner로 검사한 뒤 전체 명령과 최초 current/내부 nonce를 메모리에 사본으로 고정한다. 원래 nonce replay에서는 새 current를 읽지 않는다. writer의 COMMIT/ack/lease 정리 결과를 구분하고 전부 확인된 경우에만 해당 메모리 보관 책임을 끝낸다.

COMMIT 반환 유실/ack 실패/반환 투영 실패는 정확한 원래 행을 재감사한다. 복구에는 신규 쓰기 분기 자체가 없고 기존 pending 증인의 nonce/command digest가 같은 경우에만 reconcile helper의 ack 파일 복구를 허용한다. 이미 일치하는 증인은 읽기만 하며 과거 결과 명령으로 다른 미완료 정산 ack를 대신 확정하지 않는다. 원래 행 없음·intent-only·부분3/8행·변조/충돌/되돌림은 책임과 hold를 보존한다. 다른 nonce/current로 자동 재삽입하지 않는다.

자기 호출이 획득한 기존 storage session만 비공개로 추적한다. SQL/lease 정리가 실패하면 connection과 원래 명령을 남긴다. 명시 복구에서 자기 미종료 거래의 ROLLBACK 및 기존 end helper의 성공을 확인한 뒤 재조회한다. 경쟁 호출이나 원래 진행 실행의 lease는 정리하지 않는다. 정리 실패가 계속되거나 응답이 불명확하면 해제하지 않는다.

재시작 후 정상 원래 session의 storage-only 서비스는 새 execute/driver/owner 없이 원래 명령/DB 행/증인을 감사한다. 살아 있는 이전 객체는 자신의 복구 책임을 별도 명시 관측해야 닫힌다. 남은 lease나 intent를 시간/PID로 삭제하지 않으며 일반 백업/전원 차단 복구 성공으로 세지 않는다.
