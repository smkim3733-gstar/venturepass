- 로그인은 앱의 안전한 계정 연결/해당 사이트 로그인 화면에서 진행한다. 비밀번호를 채팅·원고·로그·Git·일반 문서에 남기지 않는다. 사이트가 요구하는 본인 인증/인증서/추가 인증은 사용자가 완료하는 동선으로 처리한다.
- 제출할 회사·기관·계획서 버전·첨부를 한 화면에서 확인하고 누르는 “접수 시작”을 최종 실행 지점으로 한다. 같은 범위의 승인을 단계마다 되묻지 않는다. 계정 로그인만으로 다른 회사·다른 신청이나 결제·서명을 실행하지 않는다.
- 접수 도중 응답이 끊기면 원래 신청의 상태를 먼저 확인한다. 신청번호·접수증 등 기관 증거가 없으면 완료로 표시하거나 새 신청을 중복 제출하지 않는다.
- 결과는 접수번호·현재 상태·보완 요청·기한과 다음 행동을 간단히 보고한다. 기관의 보완 요구는 기존 계획서와 연결해 수정안으로 제시하며 제출본과 후속본을 구분한다.
- 이번 반영은 화면/연동 개발 방향이다. 현재 특정 계정·실제 제출본을 접수하거나 신규 유료 AI 호출을 실행한 것이 아니다. 구체 실행은 대상과 제출본이 정해진 제품 흐름에서 처리한다.

## 2026-10-04 사용자 추가 요구 — 현재 자료로 초안 작성 후 보완

사용자는 회사가 완전한 자료를 처음부터 확보하기 어렵다는 실제 사용 경험을 공유했고, “최대한 자료를 먼저 모아서 올린 뒤 자료 기반으로 계획서를 작성하고 부족한 자료를 AI가 찾아 보완”하는 방향을 제안했다. 이어 자료 현황 분석 → 1차 초안 → 우선 질문 → 추가 자료/답변 반영 및 공개 정보 보완 제안에 대해 “이 내용 맞춰서 개발진행에 반영을 해줘”라고 지시했다. 이 절은 기존4F 계획의 추가 개발 요구이며, 아직 구현·실제 품질 검증 완료가 아니다.

### 사용자 흐름과 작성 기준

1. 확보한 자료부터 올린다. 특정 서류가 모두 모였는지로 초안 작성을 일괄 차단하지 않는다. 첨부0개라도 회사가 하는 일·제품/서비스 등 최소 설명이 있으면 그 설명을 바탕으로 시작한다. 설명도 없으면 최소 질문부터 받고 회사 사실을 만들어내지 않는다.
2. AI 분석 전에 저장됨·본문 판독됨·근거로 사용됨을 구분한다. 읽지 못한 파일, 중복/다른 버전, 서로 맞지 않는 수치와 분석에서 빠진 자료를 표시한다. 파일 수 자체를 근거 충실도나 품질 점수로 취급하지 않는다.
3. 현재 자료로 1차 초안을 만든다. 근거가 없는 수치·계약·고객 수·매출·개발/보유 실적은 확정 문장으로 채우지 않는다. 부족한 항목에는 확인할 내용과 필요한 근거를 제시하고, 작성 가능한 다른 항목은 진행한다.
4. 초안 옆에 중요 보완 질문3~5개와 질문의 이유·연결되는 계획서 항목·도움이 되는 자료 예시를 제시한다. 전체 부족 목록은 따로 열어볼 수 있게 한다. 짧은 답변·메모도 입력으로 받으며 해당 회사의 사용자 진술로 구분한다.
5. 자료/답변이 추가되면 영향받는 항목의 수정안을 제시한다. 기존 원고와 근거, 질문/답변, 사용자 수정 이력을 보존하고 전후 차이를 확인한 뒤 새 버전에 반영한다. 자동 갱신으로 사실 확인 완료나 사람 인수를 대신하지 않는다.
6. 초안 작성 가능 여부와 최종 사용 전 확인할 사항을 분리한다. 부족한 자료 때문에 초안을 일괄 막지 않되, 전송 동의·보관 무결성·입력 한도·예산 등 기존 실행 조건을 완화하지 않는다.

### 근거와 확인 상태 표시

| 표시 | 저장하고 보여줄 내용 |
| --- | --- |
| 자료 근거 있음 | 파일/사용자 답변의 신원, 버전, 해당 위치·인용. 업로드 내용이나 사용자 진술을 독립 검증된 사실로 승격하지 않는다. |
| 공개 자료로 보완 | 실제 확인한 출처 URL·발행처·발행/기준 시점·확인일과 뒷받침하는 주장. 업계 일반 정보를 해당 회사 실적으로 사용하지 않는다. |
| AI 제안 | 설명·전략·추정/가정의 제안과 전제. 검증된 실적과 구분하며 사용자가 채택해도 자동으로 사실 확인이 되지 않는다. |
| 회사 확인 필요 | 미확인 사실·충돌·읽지 못한 근거, 연결 질문과 필요한 확인 주체/자료. |

문단 또는 주장에 여러 근거와 확인 상태가 공존할 수 있다. 단일 배지로 확인되지 않은 부분을 숨기지 않는다. 인용이 맞다는 검사와 내용의 사실성·사람의 확인은 별개다.

### 자료가 많을 때와 외부 보완의 경계

- 원본0~100개를 보존하고 항목별 관련 근거를 선택한다. 선택된 자료/사용 위치와 제외 이유·미판독 자료·입력량을 보여준다. 전체 장문을 자동 전송하거나 한도에 맞춰 조용히 자르지 않는다.
- 부족한 내용의 탐지는 단어 목록만으로 확정하지 않는다. 이미 설명된 한계, 계획과 실적, 내부 메모와 확정 자료를 구분한다.
- 공개 조사는 공개된 일반 주제와 확인 가능한 출처부터 다룬다. 고객 원문·식별정보를 검색어/외부 요청으로 전송하지 않는다. 출처를 찾지 못하면 검색 미확인으로 남기고 URL·통계·인용을 만들지 않는다.
- 과거 승인된 실행/보관 계약과 원문을 바꾸지 않는다. 새 생성 지침·입력/출력 계약이 필요하면 별도 버전과 저장/읽기 호환성을 구현한다. 원래 동의·요청 고정·사용량/예산·복구 경계를 재사용한다.
- 이번 지시는 기능 개발 반영이며 추가 실제 유료 호출, 고객 자료 외부 전송, 기관 제출, 사람 내용 인수를 승인한 것으로 확대하지 않는다.

### 완료 검증 기준

- 첨부0개+회사 설명, 일부 서류만 있음, 회사 설명도 없음의 흐름을 각각 확인한다. 작성 가능한 항목과 질문이 구분돼야 한다.
- 스캔/본문 미판독·상충 자료·중복/구버전·100개 장문에서 누락을 숨기거나 없는 근거를 인용하지 않아야 한다.
- 매출/고객 수/계약 등 미확인 회사 사실을 지어내지 않고, 기존에 밝힌 시험 한계를 무시한 과장 보완을 하지 않아야 한다.
- 질문은 중요도와 연결 항목이 있어야 하며 먼저3~5개를 보여준다. 답변/파일 추가 후 관련 항목 수정안과 사용자 편집·이전 버전이 보존돼야 한다.
- 공개 출처 미확인·시점 불일치·회사 정보와 충돌할 때 미확인 상태를 유지한다. 자료 근거/공개 정보/AI 제안/회사 확인 상태가 화면과 내보내기에서 일치해야 한다.
- 새 AI 실행 기능은 합성/모의로 검증하고 실제 모델 품질 개선이나 사람 인수 완료로 보고하지 않는다. 구현 변경마다 필요한 관련 회귀와 화면/저장 검증을 수행한다. 문서만 변경한 이번 반영에는 과거 앱 검사를 반복하지 않는다.

## 진행 및 중단 기준

기존 15분 자동 후속 venturepass를 같은 채팅에서 ACTIVE로 재개했다. 중요한 완료/실패/필수 결정만 알리고 완료한 검사를 반복하지 않는다. 각 완결 단위는 관련 회귀·lint·typecheck·격리 빌드를 마친 뒤 관련 파일만 로컬 commit한다. 출처가 다른 편집기 미커밋 변경 및 보호 파일은 보존한다. 완료 범위와 남은 범위를 인계하고, 전체 승인 범위를 마치거나 필수 외부 결정이 있을 때 자동 후속을 PAUSED로 전환한다.

4F 개발·검증에서 새 유료 AI 호출이나 실제 고객 자료 외부 전송·기관 제출을 실행하지 않는다. 후속4G 자동 접수 기능은 위 추가 지시로 개발 목표에 포함됐으며 벤처인 기준으로 계정·제출본과 연동 가능 범위를 확인한 뒤 구현/실행을 구체화한다. 실제 사용·내용 인수는 담당자가 한다.
