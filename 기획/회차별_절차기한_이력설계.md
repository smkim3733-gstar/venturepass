# 회차별 절차·안내기한·연장 기록

상태: R10 최소 범위 구현·전체 검사·격리 API/UI 검증 완료(2026-09-26 00:06). 현재 신청 회차, 기관 요청/통보, 업무 상태를 재사용하고 회사 전체 단계와 구분한다. 담당자 기록의 구현 검증이며 실제 기관 상태 확인은 아니다.

고정 전체 3,296개·lint·타입·격리 빌드가 통과했다. 실제 합성 화면에서 날짜 정정의 확인 해제, 회차·기관 원문 재선택, v1/v2 보존과 v3 저장, 다른 편집·준비와의 상호 차단을 확인했다. 원본/귀속/동일 ID 변조·CAS·nonce·회사 잠금은 통합 검사로 검증했다.

## 저장 대상

사용자가 정확한 신청 회차와 그 회차에 연결된 기관 요청/통보 버전을 선택한다. 연결하지 않은 기관 기록을 임의 귀속하지 않는다. 직접 기록한 절차 분류(미확인·서류 확인/보완·평가 보완·위원회 보완·이의신청 보완·기타), 요청 주체, 요청일, 안내기한과 근거, 연장 상태(미확인·미요청·요청했다고 기록·허용됐다고 기록·불허됐다고 기록), 요청/결과일과 근거, 재심의 등 상태 설명, 완료 근거를 보관한다. 공식 분류/상태의 자동 수집이 아니라 담당자 기록임을 표시한다.

실제 기관 요청·통보의 정확한 ID/버전/내용 digest와 당시 회차 귀속을 스냅샷으로 보관한다. 선택한 추가 증빙은 같은 회사의 자료 버전·인용과 원본 SHA를 기존 공통 reader/이력에 묶는다. 원문을 수정하거나 귀속이 정정되어도 과거 절차 기록은 보존하고 재확인 필요를 표시한다. 새 기록의 근거로 사용할 때는 현재 귀속·현재 요청 버전을 다시 선택한다.

정정은 안정 기록 ID·정확한 이전 버전·새 버전 ID·서버 시각을 가진 추가 이력이다. CAS와 nonce/digest 재확인, 회사당 기록/문자/원본 한도는 기존 준비 이력의 패턴을 따른다. 입력하지 않은 날짜는 미확인이며 미래 날짜·불명확한 근거를 실제 관측으로 자동 승격하지 않는다.

## 기존 기능과의 관계

회사 작업공간 단계, 신청 회차, 기존 요청/통보, 수동 제출 이력, 답변 초안, 보강 업무의 완료 상태를 변경하지 않는다. 연장 기록만으로 기존 업무 기한을 덮어쓰거나 기관 수신·연장 승인·확인서 발급을 확정하지 않는다. 기한 일수를 코드에 추정해서 넣지 않는다. 업무의 기한 정정은 기존 업무 화면에서 근거를 확인하고 별도로 수행한다.

신청 이력에서 회차별 기록을 읽고 정확한 기관 버전을 고른 후 새 절차 기록을 작성한다. 과거 버전을 펼쳐 비교할 수 있으며, 편집 중 기존 진행 관리 폼의 상호 저장·이동 보호를 유지한다.

## 검증 범위

합성 검사로 회사·회차·기관 체인 귀속, 과거/최신 버전, 요청/통보 정정, nonce 응답 유실·충돌, 불변 과거 기록, 근거 원본 변경·교차 이력, 한도·입력 날짜·필수 근거와 기존 단계/업무 불변을 확인한다. 실제 기관 절차의 현재 효력과 연장 성공 여부는 별도 공식 근거·관측으로 검증한다.
