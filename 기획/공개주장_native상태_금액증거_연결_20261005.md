## 후속 저장 통합의 입력

- 공개 진입은 `inspectPublicComparisonNativeArchive(prefix, coverage, {records, financial})`와 원래 nonce lookup이다. records는 runs/events/native receipts/artifacts, financial은 events와 native 영수증에서 투영한 receipts다. 외부 evidence 배열은 거절한다.
- `studio-public-claim-comparison-native.ts`는 목적별 구조/상태 검사이고 기존 budget 모듈이 전체 prefix·원래 scope/nonce/용량과 결합한다. 낮은 수준 함수만 호출한 결과를 전체 원장 감사로 사용하지 않는다.
- 원문 context는 `inspectArchivedPublicClaimPreparation`, 요청은 `inspectArchivedPublicClaimRequest`를 재사용한다. 보관된 원고/claim hash는 참조이며 실제 현재 상태 감사는 후속 기존 live-company 함수/잠금 guard를 호출해야 한다.
- comparison-response는 기존 capture의 허용 필드 JSON이다. 실제 원문 HTTP/헤더/자격증명을 저장하는 형식이 아니다. 공급 JSON과 실제 owner 최초 캡처의 출처는 후속 writer에서 구분해야 한다.
- native 데이터 사용량은 공급된 논리 본문/메타데이터 byte 계산이다. SQLite 물리 파일 크기/페이지 수 검증은 아니다. reserved/settled만으로 종료하지 않고 final artifact까지 검사한다.
- migration/read에서 실제 BLOB UTF-8 bytes와 body hash·size, SQL key/정렬·삽입 순서, native receipt의 예산 투영을 검사한 뒤 이 순수 경계에 전달한다. 호환성을 이유로 원문 body를 다시 직렬화하거나 legacy 행을 필터링하지 않는다.
- schemaVersion3/archiveFormatVersion4는 도메인 형식이다. SQL storageVersion은 현재9 그대로이며 v10 table/gate·migration COMMIT·backup/restore는 아직 구현하지 않았다.
