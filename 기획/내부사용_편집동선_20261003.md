# 한국어 표현 점검과 직접 편집 — 2026-10-03

사용자의 계속 진행 요청에 따라 원고 편집에서 막히는 동선을 보완했다. 기존 점검기는 요약·과제·질문에도 영어 표현을 표시했지만 요약 이동 기능이 없고 과제·질문은 읽기 전용이었다.

## 변경된 동작

1. 사업계획서의 **한국어 표현 점검 → 편집 위치로 이동**을 누르면 해당 입력칸으로 이동한다. 다른 항목이면 항목을 바꾸고, 과제·질문 목록이 접혀 있으면 펼친다.
2. 제목·요약·항목 제목·본문·보강 과제·실사 준비 질문을 문맥에 맞게 직접 고친다. 항목 제목은200자, 과제·질문은 항목당3000자 상한이다.
3. **수정본 저장**은 기존 저장 경로로 수동 새 버전을 만든다. 원래 버전·인용과 과거 검토 판단은 유지된다. 새 버전의 내부 검토 완료는 자동 표시하지 않는다.
4. 다른 검토 판단·수치 대조·주장 근거를 편집 중이면 원고 편집은 잠긴다. 미저장 수정을 두고 다른 버전으로 갈 때는 기존 취소 확인을 거친다.

문자열 점검은 편집 보조다. 인용·고유명사까지 무조건 치환하지 않으며, 표현을 고쳤다고 사실 확인 완료나 기관 제출 완료로 바꾸지 않는다. 새로운 AI 호출이나 지침 변경은 없다.

## 별도 한국어 검토본

[합성 후보 v2 내부 검토본](산출물/내부검토_합성후보_v2_20261003.md)에 요약만 한국어로 편집했다. 10개 본문·인용·보강 과제12개·질문19개는 [실제 생성 원문](산출물/운영검증_합성후보_v2_20261002.md)과 동일하다. 실제 원본 final-result·운영 원장은 수정하지 않았다.

요약의 내부 영어5개를 정리했지만 합성 자료라는 한계와 현재 활동 후보/문서 기재/담당자 설명/계획/미확인의 구분은 유지했다. 이 파일은 사람이 검토할 초안이며 사람의 내용 확인·인수는 아직 별개다.

첫 브라우저 시도는 기존 상·하단 저장 버튼 두 개를 한 선택자로 지정해 중단됐다. 상단을 명시하고 같은 검증 전체를 통과했다. 반복 결과를 점검 수에 중복 합산하지 않았다.

브라우저는 실제 PlanEditor를 시험용 CSS와 합성 입력으로 실행하며 저장 응답은 모의다. 외부 network·운영 DB·키를 사용하지 않는다. 별도 합성 SQLite 회귀는 실제 저장 경로를 검증한다. 운영 앱 전체의 시각 검수나 사람 인수라고 표시하지 않는다. 기존 서버는 재시작하지 않았다.

관련 실행:

~~~powershell
& '..\..\.venturepass-tools\pnpm.cmd' test --project current src/lib/studio-plan-editorial.test.ts src/components/studio/plan-editorial-panels.test.ts src/lib/studio-plan-review.integration.test.ts --maxWorkers=1
node scripts/plan-editor-validation.mjs
~~~

완료된 검사를 반복하기 위한 명령이 아니라 후속 변경 시 사용하는 재현 경로다. 기존 운영 평가·완료 run·유료 호출은 다시 실행하지 않는다.
