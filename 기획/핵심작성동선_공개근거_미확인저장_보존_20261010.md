사용자가 “왜 개발을 안하는거야?”라고 지적했다. 완료한 검사를 반복하지 말라는 원칙을 개발 전체의 대기로 확대했던 잘못을 바로잡는다. 기존 합성 앱 개발 승인은 유지되며 작은 작업 완료를 전체 개발 종료/무기한 대기의 근거로 삼지 않는다. 이번에는 실제 공개 근거 입력 화면 결함을 수정했다. 자동후속 활성과 실제 구현 중은 구분해 보고한다.

공개 근거 저장 응답이 미확인이어도 닫기 확인을 승인하면 원래 sourceId/본문/입력이 사라질 수 있었다. PublicEvidencePanel의 닫기 버튼과 실행 처리기에서 pending을 차단하고 저장 상태 확인 안내를 표시했다. 저장 전 입력의 닫기 취소는 그대로 보존한다. 기존 publicEvidenceSaved의 같은 회사/증가 revision/원래 자료 ID와 본문 대조를 통과한 GET만 pending을 해제한다. 새 writer/승인/자동 재전송은 없다.

**다음 실제 구현:** 공개 근거의 미확인 저장 요청을 새로고침/재접속 뒤에도 이어 확인하도록 연결한다. 현재 draft/pending은 React state이고 beforeunload는 경고뿐이라 새로고침하면 원래 요청이 소실되는 구체적 한계가 남는다. 기존 브라우저 요청 journal/lock과 원래 자료 대조 방식을 읽어 재사용 가능한 부분을 활용한다. 원고/자료 본문·키를 브라우저 저장소에 새로 복제하지 않고, 회사/원래 sourceId/revision·정확한 내용 digest 등 최소 복구 식별만 보관하는 방향을 우선한다. 저장소 접근 실패 시 전송 전 차단, 읽기 복구 전 새 저장 차단, 다른 회사/변조/불일치 거절, 정확한 결과만 원래 기록 해제, 자동 재전송0을 구현·합성 검증한다. 저장 실패의 미확정 상태를 임의 성공/실패로 바꾸지 않는다. 이번 화면 내 닫기 시험을 새로고침 시험으로 세지 않는다.
