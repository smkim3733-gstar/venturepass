## 2. 다음4H9의 고정 입력·수신 계약

기존 read-selected-table-metadata 명령/route를 재사용하고 kind의 네 번째 값 CMMT만 추가한다. topic·candidate 전체·searchRetrievedAt·confirmed:true와8KiB 상한은 그대로다. 회사 ID/원고/자유 검색/키/URL·조건 필드를 추가하지 않는다. 클라이언트 supplied 후보/시각은 서버 선택 영수증이 아니다.

CMMT decoder는 다음만 받는다.

- 배열0~100행.100은 앱의 수신 지원 상한이며 공식 API 최대/전체 주석 개수 보장이 아니다. 101행 이상은 전체 거절, 잘라서 성공 금지.
- 각 행은 문서의6개 key만 허용하는 strict object.
- CMMT_NM 문자열0~40자, CMMT_DC 문자열0~3000자를 앱의 필수 입력으로 정한다. missing/null/숫자/배열이면 거절한다. 필수 여부는 앱의 제한이며 공식 null 보장으로 주장하지 않는다.
- OBJ_ID/ITM_ID는 missing/null 또는 문자열0~40자, OBJ_NM/ITM_NM는 missing/null 또는 문자열0~3000자. 원래 없음/null/빈 문자/공백을 보존한다. 임의 기본 코드나 “전체”를 넣지 않는다.
- 트림·정규화·HTML 해석·번역·정렬·중복 제거0. 같은 분류/분류값에 서로 다른 주석이 있을 수 있으므로 ID로 합치지 않는다. 고유 주석 ID를 만들어 저장하지 않는다.
- 원래 응답 byte 상한은 기존 transport의512KiB다. 클라이언트 수신의 항목/행 상한도 같은 decoder로 대조한다. 사용자 파일/AI 입력 한도로 혼동하지 않는다.

기존 응답 envelope의 command 완전 일치·source/status/시각/metadata.kind·빈 배열 상태 대조와 false 제한을 재사용한다. CMMT 결과도 kind/rows 구조를 유지한다. 새 권한·전체 주석/셀 적용 완료 필드를 추가하지 않는다. TBL/PRD/SOURCE의 기존 계약은 그대로다.

JSON 객체 오류/HTML·decode 실패/미지원 필드/초과/잘못된 명령은 기존 안전한 오류로 남긴다. 원래 제공자 오류본문·키 포함 URL을 사용자/로그에 내보내지 않는다. 오류30을 []로 바꾸거나 오류코드 이름을 추정하지 않는다.

## 3. 실제 화면과 읽기 수명

기존 접힌 “이 표의 기본 정보 확인” select에 “주석 원문”을 추가한다. 기본값은 계속 미선택이며 명시 버튼 한 번만 조회한다. 선택/닫기/후보 변경·회사 화면 이탈에서 현재 요청 취소와 표시 해제를 유지한다. 부모의 후보 전체 key·현재 request controller를 재사용한다. 수동 source의 미저장 제목/본문/메모를 덮어쓰지 않는다.

수신 행은 원래 순서대로 유형·본문을 표시하고 관련 분류/분류값 ID·명칭은 필요할 때 펼쳐 본다. 주석 본문은 whitespace-pre-wrap/안전한 텍스트 렌더와 긴 문자열 줄바꿈을 사용한다. 비어 있는 본문은 “본문이 빈 주석 행”으로 표시하되 원래 값은 바꾸지 않는다. 관련 필드 missing/null과 빈 문자열은 표시상 구분한다. URL/태그 모양의 본문은 활성 링크나 HTML로 만들지 않는다.

결과 안내는 “이 표에 요청한 주석 응답이며 전체 주석이나 선택한 수치·기간의 적용 여부는 확인하지 않았습니다” 범위다. 분류/분류값 표기가 있어도 선택한 셀과 같다고 확정하지 않는다. 빈 행 목록은 “받은 주석 행0”이며 주석 자체가 없다는 증명이 아니다. 기존 하단의 “주석을 읽지 않았다” 문구는 CMMT 결과에 맞춰 고친다. 다른 종류 결과에는 아직 주석을 읽지 않은 상태가 유지된다.

자료/수동 원장/확인일/원고/AI 입력에 자동 전달하거나 영속 저장하지 않는다. 기존 source writer·내보내기·F13 비교 예제를 수정할 이유가 없다.

## 5. 후속 시험 격리·완료 조건

기존 제품은 수정하지 않은 이번 상태에서 다음 작업을 시작한다. 문서 내용만 반복하는 단계는 만들지 않는다.

1. 첫 시험 전 변경 제품·Node fixture·브라우저/route 전이를 소스로 점검한다. 실제 SDK helper/config/운영 storage를 fixture가 우연히 import하지 않도록 기존 mock/순수 합성 fixture를 사용한다. SDK/SQLite/실제 키를 import해 확인하지 않는다.
2. 기존 metadata.test.ts에 CMMT 입력/수신/service/route/표시 시험을 추가하고 이전의 CMMT 거절 기대값은 이제 미지원인 종류로 교체한다. 관련 원래 동작을 삭제하거나 생략해 통과시키지 않는다. 실제 영향 경로만 직접 지정하고 maxWorkers1, 백업/SQL13 전체0이다.
