# 구현 검증 기록

최근 검증일: 2026-09-23. 환경: Windows, Node.js 24.19.0, pnpm 11.19.0.

## Edge 앱·서비스 연결 권한 안내 (2026-09-23)

- 사용자가 제공한 화면에서 공식 `www.smes.go.kr`의 Edge 권한 요청 ‘이 장치에서 다른 앱 및 서비스에 액세스’와 회색 로딩 화면을 확인. 이전 포인터 가림 진단과 일치하는 사용자 화면 증거임.
- 설치 여부나 비밀번호 오류로 단정하지 않고 사이트의 로컬 앱·서비스 연결 권한 요청임을 안내. 해당 요청이 TouchEn 연결에서 발생했는지는 추정이며 개별 네트워크 요청까지 검증하지 않음.
- UI 소스에 요청 도메인·권한 범위·사용자 직접 선택·같은 창에서 로그인 이어가기·새 연결 시 재요청 가능성을 조건부 안내로 추가. native 권한 팝업 자동 탐지·승인, 브라우저 플래그 변경, 계정 로그인 재시도는 추가하지 않음.
- 사용자가 처리 중인 기존 Edge 세션을 보존하기 위해 실행 중인 서버는 재시작하지 않음. 이번 안내 문구는 소스에 반영했으며 현재 실행 중인 빌드에는 아직 적용하지 않음. 실제 권한 선택·로그인 완료는 사용자 진행 후 확인 필요.

## 벤처인 로그인 입력란 탐색 오류 수정 (2026-09-23)

- 사용자 로그인 시 약 19초 후 연결 실패. 공식 공개 로그인 DOM에서 ID·비밀번호의 표시 이름은 `title` 속성이며, `aria-label`과 연결된 `<label>`은 없음을 확인.
- CUA에서 기존 `getByLabel("아이디 입력")`·`getByLabel("비밀번호 입력")`은 각각 0개, 실제 placeholder `아이디`·`비밀번호`와 로그인 버튼은 각각 1개임을 확인. 입력값은 조회하지 않았음.
- 로그인 시작과 이후 상태 확인에 같은 placeholder 선택자를 사용하도록 수정. 브라우저 실행·페이지 접속·입력칸 확인·계정 입력·로그인 요청 단계별 고정 실패 안내를 제공하며 원문 오류와 계정정보는 노출하지 않음.
- 연결 실패 안내를 화면에서 강조하고, 저장 계정을 재입력하지 않고 재시도할 수 있도록 안내.
- 실제 앱의 저장 계정 연결을 한 번 실행하여 입력란 탐색 단계는 통과했지만 로그인 버튼 단계에서 실패함. 자격정보를 넣지 않은 별도 공식 공개 탭에서도 TouchEn 설치 화면(`/venturein/resources/raonnx/install/install.html`)으로 자동 이동하는 것을 확인.
- 확인된 공식 설치 경로를 인식하면 `awaiting_setup`으로 표시하고 안내 창을 유지하도록 보완. 설치 화면에서는 계정 입력과 로그인 성공 판정을 중단하며, 사용자가 설치한 뒤 `설치 완료 후 다시 연결`로 재시작함.
- 별도 Edge의 실계정 연결은 설치 화면 대응 후에도 로그인 버튼 실행 단계에서 완료되지 않음. CUA 공개 탭의 TouchEn 설치 요구와 같은 원인인지는 미확정이며 실계정 인증 성공을 확인하지 못함. 버튼 동작 실패 시 공식 사이트의 창을 유지하고 원문 오류 대신 제한된 진단 분류만 표시하여 사용자에게 실제 안내 확인을 요청함.
- 최종 배포용 앱에서 실제 클릭 실패 분류 `covered`(다른 요소의 포인터 입력 가로채기)를 확인. UI가 `로그인·추가 인증 확인 대기`와 안내를 표시하고 인증 확인·연결 창 닫기 버튼을 유지함. 가리는 화면의 종류는 사용자 확인 대기이며 로그인 성공을 주장하지 않음.
- 전체 테스트 12개 파일, 144개 통과·DPAPI 실환경 선택 시험 1개 제외. 실행기 39개 모의 테스트에는 라벨 선택자 재사용 방지, 7단계 실패 안내의 비밀 미노출, 탐색·입력·로그인 도중 설치 화면 이동 시 중단, 외부/유사 설치 주소 차단, 설치 화면의 로그인 성공 오판 방지, 클릭 오류 6종 분류와 공식 창 유지·비공식 창 종료를 포함. ESLint와 Next 배포용 빌드(TypeScript 포함) 통과.
- 실행 중인 연결 상태를 3초마다 읽어 설치 화면 이동과 창 종료를 UI에 반영. 상태 조회로 재로그인이나 제출을 실행하지 않음.

## 벤처인 계정 연결 추가 검증 (2026-09-23)

- 전체 테스트 12개 파일, 123개 통과·1개 실환경 선택 시험 제외. 제외 시험은 별도로 `VENTURE_TEST_DPAPI=1`로 가상 계정을 이용해 통과 확인.
- 실제 Windows DPAPI 암·복호화, 기업별 엔트로피 불일치·암호문 변조 거부, 별도 계정 CAS와 연결 해제 tombstone, 기업 삭제 시 계정 cascade 확인.
- 계정 API의 외부 Origin 거부·8KB 제한·잘못된 명령·오래된 버전 거부·작업 경합 차단·비밀 미노출 확인. 미지원 자동 제출 명령은 거부함.
- Playwright 실행기는 모의 테스트 18개로 기업 격리·1회 로그인 시도·추가 인증 대기·TTL·창 닫기·중복/취소 경쟁·확인된 로그인 목적지·지연 폼 로딩·오류/디버그 비밀 보호 확인.
- 공개 공식 로그인 화면의 입력란 표시 이름, 로그인 버튼과 신청 URL을 CUA 브라우저로 확인. 당시 표시 이름을 aria-label로 오인했으며 아래 로그인 오류 수정에서 실제 DOM 속성을 다시 검증함. 실제 계정의 로그인 이후 화면·신청·첨부·제출은 미검증.
- ESLint와 최종 Next 빌드(TypeScript 포함) 통과. `playwright-core`는 서버 외부 패키지로 설정.
- 배포용 앱의 브라우저에서 가상기업 계정 저장 성공, 마스킹 표시·저장 후 비밀번호 필드 비움 확인. 일반 기업 JSON에 시험 비밀번호 없음, 자동 제출 비활성화 상태 확인.
- 검증용 가상기업만 삭제했고 기존 사용자 기업은 보존. 가상 계정으로 실제 벤처인 로그인을 시도하지 않음.

현재 자동 제출 기능은 비활성 상태입니다. 사용자에게 계정 직접 입력 화면을 제공했으며 실제 로그인·추가 인증과 신청기업·제출 화면 연결 검증을 이어서 수행해야 합니다. 이 단계의 저장·모의 시험을 실계정 로그인·등록·제출 성공으로 해석하면 안 됩니다.

- `pnpm test`: 9개 파일, 84개 테스트 통과. 원본 통계·검색·필터·날짜와 준비 경로, SQLite 저장 충돌·기업 분리·삭제, 분석·계획서 최신성 무효화, API 입력·호스트/출처 방어, Markdown 내보내기 검증.
- `pnpm lint`: 오류·경고 없이 통과.
- `pnpm build`: 컴파일, TypeScript, 정적 페이지 생성 통과. 기존 경로와 `/studio`, 기업·자료·생성·다운로드 API 경로 생성 확인.
- `pnpm format:check`: 전체 형식 검사 통과.

문서 추출은 실제 텍스트 PDF·XLSX·한글 텍스트와 손상·빈 파일·용량 초과·압축 해제 크기 제한을 검증했습니다. AI SDK는 모의 응답으로 구조화된 분석·원고·독립 검토, 근거 인용 불일치, 누락 항목, 모델 실패 시 저장 방지 등을 검증했습니다. 실제 OpenAI API 호출은 키 미설정으로 실행하지 않았습니다.

## 검증 범위와 남은 연결

검증용 기업과 원고는 가상 데이터이며 검증 후 삭제했습니다. 실제 고객 자료를 외부 AI나 기관에 제출하지 않았습니다.

- 실제 AI 생성 품질·독립 검토, 이미지/스캔 PDF 인식, 녹음 전사: 서버 API 키 설정 후 실제 호출 검증 필요.
- 벤처인 로그인·자동 제출·기관 상태 수신·납부, 이메일/SMS 수신 연동: 미구현. 현재 진행 관리는 담당자가 직접 기록합니다.
- 다중 사용자 로그인·기업별 접근권한·공개 서버 배포·기기 간 동기화: 미구현. 현재는 이 컴퓨터의 로컬 작업공간입니다.
- HWP/HWPX 직접 처리 및 공식 제출 양식 출력: 미구현. 현재 작성본 내보내기는 Markdown입니다.
- 원문 인용 일치와 검토 의견은 문서의 사실성이나 공식 심사 통과를 보증하지 않습니다.
