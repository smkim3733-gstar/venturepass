# 벤처인 연결 안내와 확인 범위

공개 안내 확인일: 2026-10-05. 이 문서는 현재 PC용 VenturePass 구현 범위와 공식 공개 안내를 구분한다.

## 4G5c2 — 현재 MY벤처현황 한 번 읽기

기존 벤처인 연결 화면에서 접힌 ‘MY벤처현황 읽기’를 연다. 앱이 연 별도 Edge 창에 해당 회사의 지원 MY벤처현황 화면이 있어야 한다. 회사·가려진 계정과 읽기 대상 정보를 확인하고 ‘현재 MY벤처현황 한 번 읽기’를 누른다. Codex 내장 브라우저의 로그인은 앱 세션과 공유되지 않는다.

버튼 클릭만 수집한다. 화면 시작·펼침·회사 변경·새로고침은 자동 읽기나 재로그인을 하지 않는다. 다른 편집/작업 중이거나 회사·계정·세션 정보가 맞지 않으면 먼저 현재 연결을 확인한다. 지원하지 않는 페이지나 원래 계정 연결 정보가 없는 세션은 읽기 불가로 남기며 자동 연결하지 않는다.

결과는 신청별 행과 확인서별 행으로 분리한다. 읽은 시각과 화면 날짜/결과/기간을 구분하고, 로컬 신청 회차 연결·공식 접수증·현재 유효성은 미확인이다. 표 없음/빈 표/미지원은 서로 다르며 미신청·미발급의 증거가 아니다. 현재 열린 화면 메모리에서만 표시하며 접기·이탈·회사/버전/세션 변경·다른 작업 때 이전 결과를 지운다. 늦은 응답으로 다시 표시하지 않는다. 원래 계정 폼과 수동 원장/lastCheckedAt, 원고·자료는 바꾸지 않는다.

95/95개 범위와 격리 화면6/6흐름은 합성 검증이다. UI 양성 응답은 fixture이며 실제 기관 인증/결과 조회 성공과 구분한다. 공식 신청번호와 원래 로컬 회차의 연결·정정은 다음 점검 대상이고 실제 접수/심사 결과 자동 귀속은 아직 완료하지 않았다. [상세 구현·검증](../기획/벤처인_MY현황_세션읽기_20261005.md).

## 간단 화면에서 이어가기

1. 계획서를 작성하고 기존 내부 검토·확인 절차를 진행한다.
2. **신청 진행**에서 연결 기록 요약을 읽는다. 계정 저장, 로그인·추가 인증, 항목·첨부 연결, 이전 입력 결과 미확인이 서로 다른 상태로 표시된다.
3. 표시된 버튼으로 기존 벤처인 연결 화면을 연다. 안내 당시 기록과 현재 회사·계정·화면 기록이 일치하면 필요한 영역으로 한 번 이동한다. 화면 열기 자체는 로그인이나 자료 전송을 실행하지 않는다.
4. 기존 연결 화면에서 정확한 회사·계정·원고·자료와 현재 공식 화면을 확인한다. 실제 입력·첨부에는 기존 별도 검토·동의가 필요하다.
5. 최종 제출, 결제·서명, 공식 접수/심사 결과는 해당 공식 화면에서 따로 확인한다.

신청 후속 기록이 이미 있으면 기존 후속 안내가 우선한다. 준비되지 않은 원고는 기존 준비 안내로 돌아간다. 저장된 계정이 있어도 로그인이 완료된 것은 아니다.

### 단계 펼침과 입력 보존

간단 안내와 현재 기록이 일치하면 필요한 단계만 처음 펼친다. 원고 연결과 첨부 연결은 함께, 이전 결과 미확인은 별도로 펼친다. 다른 단계 제목 또는 ‘모든 단계 펼치기’로 열 수 있다. 직접 상세 화면으로 들어오거나 안내가 달라지면 전체 펼침을 유지한다.

접어도 입력값·연결 확인·준비본 검토안·별도 승인 체크는 해당 화면 안에 그대로 남는다. 저장이나 전송은 기존 명시 버튼으로만 진행한다. 회사/원고/자료 변경, 검토 만료와 기존 이동 확인은 그대로 적용되며 접기가 이를 해제하지 않는다. 새로고침 뒤 펼침 상태 복원이나 실제 공식 접수 확인을 뜻하지 않는다.

### 신청 회차·제출 기록 보기

간단 ‘신청·진행’의 접힌 기록 목록에서 회차별 수동 기록을 확인한다. 제출했다고 기록한 날짜, 앱 기록 시각, 당시 원고 버전과 접수 기록 연결 여부를 구분한다. 회차만 등록한 경우 제출 기록이 없다고 표시하며 실제 미제출로 판정하지 않는다. 상단 마지막 기록 시각에는 회차 등록 시각도 포함한다.

‘이 회차 기록 보기’ 또는 ‘이 제출 기록의 원고·접수 근거 보기’는 회사/revision·회차 정보 버전·정확한 제출 기록 버전을 대조한 뒤 기존 상세 이력으로 이동한다. 최신 제출 정정은 원래 보관 순서로 고르며 날짜로 추정하지 않는다. 기존 제출 기록에 고정된 접수 통보 버전을 후속 정정 버전으로 바꾸지 않는다. 연결된 접수 기록이 없거나 확인할 수 없으면 그대로 표시한다.

이동은 읽기와 초점 이동만 수행한다. 기존 편집 중 이동 확인을 유지하고 입력·저장·공식 사이트 조회·AI 실행을 시작하지 않는다. 모호한 이력이나 다른 회사/버전은 자동으로 고치지 않으며 기본 진행 기록 화면에서 확인한다. 새로고침 뒤 이전 이동 대상을 복원하지 않는다. 수동 진술과 로컬 신원 대조는 공식 접수·심사 결과의 진위 검증이 아니다.

### 후속 안내의 회차 연결·원문 보기

보완 요청·납부·확인서 등 기존 후속 안내에는 현재 수동으로 연결된 신청 회차를 표시한다. 회차 미지정, 다른 회차로 변경, 연결 해제, 연결 이력 확인 필요를 구분하며 최근 회차나 접수번호로 귀속을 추정하지 않는다. 기존 주 행동과 우선순위는 그대로다.

접힌 ‘회차 연결·보관 원문 보기’에서 해당 안내의 정확한 원문, 연결 당시 고정된 원문 버전, 현재 연결된 회차 기록으로 이동한다. 예를 들어 안내가 요청 v2여도 회차 연결의 기준이 요청 v1이면 두 버전을 따로 열 수 있다. 회차·연결 정정의 보관 순서와 부모 신원을 대조하며 날짜만으로 최신을 고르지 않는다. 손상되거나 모호한 연결은 회차 이동을 제공하지 않고, 기관 원문 체인이 온전할 때에만 해당 원문을 읽는다.

이동 대상은 원래 회사/revision·기관 체인·정확한 기록 버전에 묶인다. 변경된 회사나 기록으로 자동 대체하지 않으며 기존 상세 기록의 초점 이동만 수행한다. 펼침·이동은 저장, 답변 준비, 로그인, 공식 조회나 전송을 시작하지 않는다. 화면 전환 또는 회사/revision 변경 뒤에는 접힌 상태로 다시 표시한다. 표시와 연결 시각은 담당자 기록이며 공식 접수·심사 결과 확인이나 전체 원장 감사가 아니다.

## 로컬 기록과 공식 상태

| 표시/동작 | 의미 |
| --- | --- |
| 연결 기록 다시 확인 | 이 PC의 회사·계정 상태·메모리 세션·저장 workflow를 읽는다. 공식 사이트를 새로 조회하지 않는다. |
| 연결 기록 조회 시각 | 로컬 조회 시각이다. 공식 접수 확인 시각이 아니다. |

새 연결 요약은 회사/revision에 결합한 읽기 응답만 받는다. 읽기 실패·다른 회사·오래된 revision에서는 이전 안내를 유지하지 않는다. 회사 전환 후 늦은 응답도 표시하지 않는다. 계정 비밀번호·고객 본문은 요약에 포함하지 않는다. 읽기는 실행 승인이나 제출 권한이 아니다.

## 공식 공개 자료에서 확인한 범위

- [공식 홈](https://www.smes.go.kr/venturein/home/viewHome): 벤처확인 절차와 로그인 2차 인증 관련 공지를 확인했다. 실제 계정별 인증 방식은 로그인 시 별도 확인이 필요하다.
- [로그인](https://www.smes.go.kr/venturein/auth/viewLogin): ID/비밀번호 로그인과 인증서 안내를 제공한다. 인증서는 ID/비밀번호 로그인 후 등록하는 절차가 안내돼 있다.
- [확인 신청](https://www.smes.go.kr/venturein/aply/v2): 비로그인 상태에서 로그인 화면으로 이동했다. 로그인 이후 현재 입력 필드/첨부 제한을 실제 확인한 것은 아니다.
- [확인 절차](https://www.smes.go.kr/venturein/institution/processGuide): 신청서와 첨부자료의 최종 제출 뒤 서류 확인·보완, 수수료 납부와 접수 완료, 평가·심의 및 확인서 발급으로 이어진다. My벤처에서 진행·결과를 확인하는 안내가 있다.
- [이용약관](https://www.smes.go.kr/venturein/cmmn/terms): 공개 약관과 제한된 공식 검색을 조사했으나 외부 앱용 신청·제출 API 지원이나 자동화의 공식 허용 범위는 확인하지 못했다. 이를 API 부재 또는 허용의 증거로 해석하지 않는다.

공개 페이지 열람에는 고객 회사명·원문·식별정보를 사용하지 않았다. 실제 인증·로그인·고객자료 전송·접수·납부·서명을 수행하지 않았다.

## 재사용한 기존 기능

- 계정 상태/명시 연결: VentureinPanel, venturein-vault, venturein-runner.
- 저장 화면·진행 단계: getVentureWorkflow, buildVentureJourney, VentureinWorkflowPanel/JourneyPanel.
- 선택 입력·첨부/원문 비교: 기존 inspection, input-comparison, prepared-package 바인딩.
- 전송·불확실 결과: 기존 execution/recovery, 원래 요청·별도 동의와 승인 조건.
- 기관 후속 기록: 기존 guided-followup과 신청 이력 화면.

4G1은 위 기능을 대체하거나 승인 경계를 바꾸지 않고 간단 화면에 로컬 요약과 진입점을 추가했다. 기존 자동 입력 기능이 현재 공식 화면 모든 단계에서 작동한다거나 공식 API 통합을 완료했다는 뜻이 아니다.

## MY벤처현황 읽기 어댑터의 현재 범위 — 4G5b

현재는 내부 함수와 합성 검증만 추가했다. 사용자 화면의 새 공식 결과 조회 버튼이나 결과 보관 기능은 아직 없다. 기존 앱 세션/API·신청 회차 연결은 다음 단계다.

신청 심의결과와 확인서 이력을 분리하고 정확한 예상 신청번호가 있을 때에만 해당 행을 찾는다. 결과 문자나 유효기간 표시를 접수 성공·현재 유효성으로 판정하지 않는다. 분리된 확인서 표의 공통 부모가 불명확하거나 회사/표 구조가 달라지면 미지원·미확인으로 남긴다. 실제 사이트의 분리 표 전체 구조는 추가 검증이 필요하다.

수집 함수는 이미 열린 지원 화면에서 필요한 문자만 읽는다. 버튼·메뉴를 누르거나 URL로 이동하지 않으며 앱의 실제 세션 소유자가 회사/계정/현재 화면 revision을 함께 검사해야 한다. 공급 JSON의 파싱 성공, 수집 결과, 담당자 수동 기록은 각각 다른 출처다. 기존 수동 lastCheckedAt:null, 원래 요청·별도 승인/복구와 DB를 바꾸지 않았다.

[구현·검증 범위와 다음 작업](../기획/벤처인_MY현황_읽기어댑터_20261005.md): 관련143/143개 범위(신규52+기존91), 실제 Edge 합성 DOM20개는 신규52개 안에 포함한다. 실제 계정 재조회/입력·제출은 수행하지 않았다.

## 남은 작업과 검증 한계

4G2a는 안내 당시 기록과 상세 화면의 현재 기록을 대조해 필요한 기존 영역으로 이동한다. 이전 입력 결과 미확인은 세션이 없더라도 결과 영역을 먼저 보여 준다. 회사·계정·revision·화면 기록이 달라지면 이전 안내를 자동 수정하지 않고 재확인을 요구한다. 이동 대상은 현재 창 메모리만 사용하며 새로고침·탭/모드 전환 뒤 지속 복구하지 않는다.

4G2b는 긴 상세 화면에서 현재 필요한 영역을 먼저 보이고 나머지를 펼쳐 볼 수 있도록 연결했다. 미저장 입력과 기존 동의·검토안·원래 요청 복구를 보존한다. 새 화면 관측과 저장 기록 읽기, 선택 입력 결과와 공식 접수 상태를 계속 구분한다.

전체 자동 제출·접수/심사 결과 자동 조회, 현재 실제 계정의 로그인·인증 성공, 실제 공식 원문/접수증의 수집과 대조는 미완료다. 이번 합성 브라우저 검증의 인증/완료/미확인 상태는 응답 fixture이며 공식 사이트 성공 사례가 아니다. 실제 고객 전송·신청·납부·서명에 대한 권한을 이 안내에서 얻지 않는다.

공개 통계의 KOSIS 운영 연결도 키 미설정으로 미검증이다. 해당 설정과 범위는 [PUBLIC_RESEARCH.md](PUBLIC_RESEARCH.md)를 따른다.

## 2026-10-05 실연동 점검 결정

4G4 소스·공개 지원 점검 결과, 선택 입력/첨부와 수동 후속 기록은 구현돼 있지만 최종 제출·공식 접수증/결과 수집은 미완료다. 기존 실행 승인이나 DOM 대조를 공식 접수 증거로 바꾸지 않는다. 인증된 지정 회사 화면의 구조를 입력·제출 없이 읽는 점검 여부가 다음 결정이다. 자동 후속은 해당 결정 대기로 PAUSED이며 전체 제품 완료를 뜻하지 않는다. 상세 범위·소스 근거·재개 절차는 [실연동 점검](../기획/벤처인_실연동_구현검증_점검_20261005.md)을 따른다.

## 4G5c1 — 현재 앱 세션의 MY현황 읽기 서버 경로

기존 앱 Edge 세션이 현재 MY벤처현황 지원 화면에 있고 보이는 인증 표시와 회사번호가 맞을 때만 명시 POST로 읽는다. 최초 세션의 계정 revision, 회사/연결 기록 revision, 세션 시작/인증 시각, 현재 Page·문서와 원래 URL을 전후 대조한다. 자동 이동/인증 갱신/재로그인/키 복호화·수동 기록 쓰기는 하지 않는다. 계정 binding이 없는 이전 메모리 세션은 새 읽기에 미지원이며 자동으로 재연결하지 않는다. CUA 내장 브라우저의 로그인은 앱 Edge 세션과 공유되지 않는다.

이 서버 API에 사용자 읽기 버튼·결과 표시를 연결하는 작업은 4G5c2에 남아 있다. 회사 화면의 관측 결과만 임시 반환하며 공식 신청번호·로컬 회차 귀속은 미확인이다. 기존 기관 기록의 접수번호를 신청번호로 사용하지 않는다. 결과·유효기간 문자를 공식 확인/접수증/현재 유효성으로 해석하거나 lastCheckedAt을 갱신하지 않는다. 실제 운영 계정으로 이 API를 실행하지 않았으며 실제 Edge 합성 DOM/격리 SQLite·라우트 함수 경계만 검증했다.

서버 요청은 read-current-my-status/회사·계정·workflow revision/원래 sessionStartedAt/confirmed:true만 받는다. 고객 본문·자격증명·supplied observation·신청번호를 요청에 넣지 않는다. 외부 Origin/query/추가 입력/8KiB 초과는 거절한다. API 사용은 실제 입력·첨부·최종 제출/납부·서명을 승인하지 않는다.
