# 벤처패스

현재 PC의 내부 업무용 로컬 앱 마감(2026-10-03): [완료 범위와 검증](../기획/로컬앱_최종마감_20261003.md), [PC 재시작·백업·복구](../기획/로컬앱_시작과복구_20261003.md). 이 PC에서 기존 설치를 다시 켤 때는 위 안내를 먼저 따른다. 아래 설치 절은 새 환경에서 소스를 설치하는 경우다.

---

벤처기업확인 **혁신성장유형 전용** 신청 준비 앱입니다. 기존 조사자료는 상위 폴더에 보존하고 앱 코드는 이 `web` 폴더에서 관리합니다.

## 실행

Node.js 24, pnpm 11.19.0 기준입니다. API 키 없이 로컬에서 실행할 수 있습니다.

```powershell
cd web
pnpm install --frozen-lockfile
pnpm dev
```

브라우저에서 http://localhost:3000 에 접속합니다. 기본 서버는 이 컴퓨터의 127.0.0.1에만 바인딩됩니다.

```powershell
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm start
```

OneDrive 아래 작업 폴더에서 기존 `.next` 접근 오류가 발생하면 `pnpm build:local`로 배포 빌드를 검증합니다. 이 명령은 필요한 앱 소스와 공개 데이터만 OneDrive 밖의 고유 임시 폴더에 복사하고 설치된 의존성으로 Webpack 빌드를 실행합니다. 기존 개발 서버와 산출물을 보존하고, 완료된 `.next` 경로를 출력합니다. 로컬 환경 파일·사용자 데이터는 복사하지 않으며 임시 폴더는 검토를 위해 남깁니다. 이 산출물은 임시 폴더 기준이며 원본 폴더의 `pnpm start` 대상과 구분됩니다.

## 구현된 기능

- `/studio`: 기업별 서버 저장, 자료함, 신청 아이템 분석, 사업계획서 작성·편집·검토·버전·다운로드, 진행단계·할 일·기한 관리.
- `/studio` 사전진단: 기본요건의 사용자 검토·원문 인용, 기술·고객 설명과 부족 자료 정리, 기준 버전·과거 결과·재진단 필요 표시, 선택한 보강 과제의 업무 연결. 외부 AI나 기관의 자격 판정 없이 로컬에서 준비 상태를 정리합니다.
- `/studio` 심사·실사 준비: 심사 관점 6개와 증빙 안내, 준비목록 8개, 작성본별 내용·인용·예상 질문 확인, 준비 업무 등록. 제출·납부 단계의 2026년 7월 시행 접수 전 기한 안내.
- `/studio` 벤처인 연결: 기업별 ID·비밀번호의 Windows DPAPI 암호화 저장·변경·삭제, 별도 Edge 창에서 자동 로그인 시도, 추가 인증 후 로그인 표시 확인, 작성본·원본파일 연결과 점검, 검토·승인 후 1회 입력·첨부, 최근 화면별 실행 이력. 실제 회사 정보의 공식 입력·업로드는 별도 검증이 필요하며 저장·동의·최종 제출 버튼은 자동 실행하지 않습니다.
- `/`: 실제 2026년 8월 명단의 업종·지역·신규/재확인 통계 및 차트.
- `/companies`: 26,525개 혁신성장 기록 검색, 지역·업종·구분 필터, 서버 페이지네이션, 기업 상세보기.
- `/application`: 기업정보 입력·검증, 신규 3년 미만/3년 이상·재확인 준비 경로 안내, 경로별 증빙 검토 체크리스트.
- `/application`의 입력정보와 검토 기록은 현재 브라우저의 localStorage에 저장되며 새로고침 후 복원할 수 있습니다. 화면에서 기록을 삭제할 수 있습니다.
- 반응형 메뉴, 접근성 레이블, 로딩·오류·빈 검색 결과 처리.

`/application`의 기존 체크리스트는 사용자의 검토 기록입니다. 새 `/studio`는 이 컴퓨터의 서버에 기업별 자료를 보관하는 로컬 작업공간입니다. 사용자별 로그인·권한, 공개 서비스 배포, 공식 기관 신청 제출·납부·상태 연동은 아직 구현하지 않았습니다. 진행 관리의 단계는 사용자가 기록한 상태이며 기관에서 자동으로 확인한 결과가 아닙니다.

## 사업계획서 스튜디오 사용

### 기업별 사전진단

기업정보와 자료를 보관한 뒤 `사전진단`에서 현재 자료로 결과를 생성합니다. 모르는 기본요건은 확인 필요로 남겨도 됩니다. 중소기업 해당 여부와 신청 제외업종에 관한 긍정·부정 검토를 기록하려면 현재 기준, 같은 기업의 본문이 있는 문서, 정확한 인용과 확인 가능한 위치를 직접 대조해야 합니다. 파일명이나 업종 코드만으로 요건을 자동 확정하지 않습니다. 자료가 바뀌면 이전 검토 연결은 다시 확인해야 합니다.

진단은 기본요건과 기술·고객 설명, 자료 신뢰성을 구분하고 각 항목의 부족 자료와 질문을 보여줍니다. 설명이나 키워드가 있다는 이유로 기술의 우수성·실적의 진위를 확인한 것으로 표시하지 않습니다. 기준과 근거의 버전을 고정한 과거 결과를 보존하며, 회사 설명·자료·검토 답변·적용 기준이 바뀌면 재진단 필요로 표시합니다. 원고 편집이나 업무 완료 체크만으로 결과가 상향되지 않습니다. 선택한 보강 과제는 진행 관리의 업무로 등록하며 임의의 법정 기한이나 완료 상태를 생성하지 않습니다.

기존 `/application`의 브라우저 체크리스트는 보존합니다. 기업별 자료·진단·원고를 연결하려면 해당 화면의 기업 작업공간 링크로 `/studio`를 사용하세요. 브라우저의 기존 확인 표시를 다른 회사의 검토 근거로 자동 가져오지 않습니다.

### 스캔 자료의 로컬 판독과 교정

자료함의 `복수파일 접수·로컬 추출 재개`는 한 번에 최대 10개, 파일당 12MiB, 합계 24MiB의 원본을 파일별로 접수합니다. 접수한 원본과 판독 결과를 별도로 저장하므로 앱 재시작 후 저장 지점에서 확인할 수 있습니다. 원본 접수만으로 본문이나 분석 근거를 만들지 않으며, 각 파일의 로컬 판독을 실행하고 원본과 대조해 교정한 본문을 확인·채택합니다. 화면을 닫기 전 아직 보내지 않은 파일은 다시 선택해야 합니다.

형식이 맞지 않는 파일은 해당 항목에 표시하고 원본이 없는 예약을 취소할 수 있습니다. 요청 결과가 불확실하면 먼저 저장 상태를 확인합니다. 완료한 판독을 자동 반복하지 않으며, 채택한 본문과 보관 중인 판독 초안을 구분합니다. 판독 초안 비우기는 채택 본문을 유지합니다. 외부 AI 전송과 사실 검증·신청 완료는 이 로컬 접수/판독 기능에 포함되지 않습니다.

`자료 분류·기업정보 제안`에서 사용할 자료와 본문/판독 결과의 정확한 버전을 고릅니다. 명시된 회사명·사업자번호·업종·설립일·납입자본금·결산월과 자료 분류 후보를 현재 값·원문 위치와 비교하고, 필요한 항목만 선택·확인해 채택합니다. 제안은 기본 선택하지 않으며 기업번호가 다르면 기업정보 후보를 채택할 수 없습니다. 미검토 판독문에서 기업정보를 선택해도 본문 전체가 분석 근거로 채택되는 것은 아닙니다. 자료 종류는 해당 본문을 먼저 교정·채택한 후 변경합니다. 원문 위치는 실제 파서 정보가 남은 경우에만 페이지·셀·자막 시간 구간으로 표시합니다.

자료함의 본문 미추출 PDF·PNG·JPEG·WebP에서 `이 PC에서 글자 읽기`를 누르면 Windows 한국어 OCR로 미검토 초안을 만듭니다. 판독은 이 PC에서만 수행하며 외부 AI로 보내지 않습니다. PDF는 설치된 `pdf-parse`로 별도 프로세스에서 렌더링합니다. 원본 12MiB·PDF 20페이지·판독 본문 10만 자·전체 2분 한도이며 동시에 한 건만 처리합니다. Windows 한국어 OCR이 없거나 손상·암호·한도 문제로 실패하면 원본 보관 상태를 유지합니다.

페이지별 판독문과 내려받은 원본을 대조해 교정한 뒤 확인 표시를 하고 본문을 저장합니다. 단순 판독·미리보기는 등록 본문이나 기존 분석을 바꾸지 않습니다. 저장 시 회사·자료·버전·원본 SHA256을 재확인하고 수동 입력 본문으로 남깁니다. 본문이 바뀌면 이전 분석과 작성본의 확인 표시를 해제하며 이전 원고 버전은 보존합니다. 이 확인은 사용자의 대조 기록이며, 문서 내용의 진위나 OCR 정확성을 앱이 검증했다는 뜻은 아닙니다. 판독과 저장에 실패해도 원본 파일을 수정하지 않습니다.

1. `기업 추가`에서 기업명과 업종을 등록합니다.
2. 기업정보에 현재 기술·고객·인력·자금·특허와 앞으로의 개발계획을 입력합니다.
3. 자료함에 파일을 올리거나 상담 녹취·메모를 붙여넣고 추출 내용을 확인합니다. 스캔 자료를 보관만 하려면 `원본만 보관 — 본문 미추출`을 선택합니다.
4. 아이템 분석에서 `AI 분석·자동 작성` 또는 `자료 기반 정리본`을 명시적으로 선택합니다.
5. 추천된 아이템의 근거와 부족한 자료를 검토하고 신청 아이템을 선택합니다.
6. 사업계획서를 작성한 뒤 10개 항목을 편집하고 `수정본 저장`으로 새 버전을 남깁니다.
7. 문장·수치·증빙 확인 후 항목별 확인 표시와 내부 검토 완료를 기록합니다. 자료나 전략이 바뀌면 재검토가 필요합니다.
8. Markdown 작성본을 내려받고, 진행 관리에서 보완·납부·실사 등의 할 일과 기한을 기록합니다.

납입자본금은 원 단위 정수, 결산월은 1~12월의 개별 항목으로 저장합니다. 미확정 값은 비워 두고 `재무와 자금`에 출처·기준일·변경 여부를 기록합니다. 벤처인 연결에서 두 항목을 선택하면 원래 입력값과 단위, 이 근거 메모를 함께 검토할 수 있습니다. 계획서가 없어도 기업정보 연결값을 미리 볼 수 있으나 제출 준비 완료로 판정하지 않습니다. 기업자료가 바뀌면 이전 확인 표시를 재사용하지 않고 최신 자료로 연결을 다시 작성합니다.

실사 준비는 `진행 관리 → 제출 내용에서 현장 설명까지`에서 시작합니다. 참고할 작성본이 실제 제출본·보완본과 일치하는지 확인한 뒤 심사 관점별 본문·인용과 예상 질문을 검토합니다. `준비 업무 만들기`로 설명 담당자·답변 요점·자료 위치·기한을 기록할 수 있습니다. 준비목록은 회사 상황에 맞게 선택하는 예시이며 기관이 안내한 준비사항을 우선합니다.

진행 단계를 바꾸면 이전·새 단계, 서버 기록 시각, 선택한 발생일과 근거 메모가 이력에 남습니다. 잘못 기록한 단계는 새 단계 변경과 정정 메모로 바로잡으며 이전 기록을 보존합니다. 담당자 기록과 최초 초안 생성에 따른 앱 자동 변경을 구분하고, 둘 다 기관에서 자동 검증한 결과로 표시하지 않습니다. 기존 회사의 과거 이력은 추정해서 생성하지 않습니다. 최대 500건을 보존하며 한도에 도달하면 이전 기록을 지우지 않고 새 단계 저장을 중단합니다.

작성 프롬프트는 신청기술과 사업계획의 연결, 객관적인 비교 조건, 자체·외부 개발 범위, 완료·계획 구분, 인력·자금·일정의 일치를 점검하도록 구성했습니다. 자료 기반 정리본은 회사 입력의 발췌를 붙인 준비 질문을 제공합니다. 기관의 실제 질문이나 검증된 답변을 제공하는 것은 아닙니다. 기존 작성본은 보존하며 새 기준은 이후 분석·작성에 적용됩니다. 상세 근거와 후속 개발 범위는 상위 `기획/혁신성장유형_심사중점_실사준비_반영안.md`에 기록했습니다.

### 원고 비교·보완 답변·실사 연습

`사업계획서 → 저장 원고 버전 비교`에서 두 저장 버전을 직접 선택하고 비교합니다. 본문·인용·확인 표시·예상 질문의 변경을 원문 그대로 보여 주며, 긴 내용이나 중복 항목 때문에 비교하지 못한 부분은 별도로 표시합니다. 비교만으로 원고를 저장하거나 검토·제출 상태를 변경하지 않습니다.

`진행 관리 → 보완 답변 작성 보조`에서는 최신 기관 요청의 정확한 문장에 원고·자료 인용, 답변 요점, 부족 자료를 연결합니다. `선택 근거로 답변 틀 채우기`로 만든 미검토 초안을 교정하고 `답변 준비 새 버전 저장`을 누릅니다. 이전 준비안·기관 답변과 문구를 비교할 수 있으며, 연결 자료를 확인한 최신 준비안은 `기관 기록에 답변 초안 등록`으로 로컬 이력에 추가합니다. 이 등록은 기관 발송이나 내용 검토 완료가 아닙니다.

`진행 관리 → 실사 모의 답변 · 원고·근거 대조`에서는 원고 버전과 준비용 질문을 직접 선택하고 응답자·답변·정확한 인용을 기록합니다. 최초 답변은 미검토로 저장하며, 이후 새 버전에 담당자의 내부 검토를 기록할 수 있습니다. 내용을 수정하면 검토 선택을 해제합니다. 이전 답변과 기준 질문·원고 버전을 보존하고 DRAFT 기록을 내려받을 수 있습니다. 수치 표기 차이는 기간·단위·대상을 확인하라는 안내이며, 같은 숫자도 사실 일치나 실사 통과를 뜻하지 않습니다.

보완 답변·실사 답변의 원본은 저장 시 읽어 SHA를 고정합니다. 화면의 연결 유지 표시는 현재 등록정보·인용 대조이며 현재 파일 바이트를 다시 검사한 결과가 아닙니다. 미추출 원본을 연결해도 본문 판독·사실 확인이 되지 않으며, 자료가 바뀌면 기존 연결을 확인하고 새 버전으로 남깁니다. 이 기능들은 외부 AI 전송·기관 작업·회사 단계 변경을 실행하지 않습니다.

### 벤처인 계정 연결

`기업 선택 → 벤처인 연결`에서 아이디·비밀번호를 직접 입력하고 `계정 저장` 또는 `저장하고 로그인 시작`을 선택합니다. 실제 계정은 채팅·기업정보·자료함에 입력하지 않습니다. 저장 계정으로 로그인 시작을 누르면 이 PC의 Microsoft Edge에 별도 임시 창이 열리고 공식 로그인 폼에 한 번 입력합니다. 추가 인증이나 안내창은 해당 창에서 직접 처리하고 `인증 완료 후 상태 확인`을 누릅니다.

공식 TouchEn 보안 프로그램 설치 화면으로 이동하면 `보안 프로그램 설치 필요`로 표시하고 창을 유지합니다. 해당 Edge 창에서 공식 안내에 따라 설치한 뒤 `설치 완료 후 로그인 계속`을 누릅니다. 같은 창에서 공식 로그인 화면을 다시 확인하며 새 브라우저를 만들지 않습니다. 설치 화면을 벗어난 뒤에는 현재 화면을 기준으로 상태를 확인합니다. 보안 프로그램을 우회하거나 자동 설치하지 않습니다.

계정 입력 전에 로그인 버튼을 실제로 누를 수 있는지 확인합니다. 회색 로딩 화면 등이 가리고 있으면 계정을 입력하지 않고 `로그인 화면 준비 대기`로 표시합니다. Edge에 `이 장치에서 다른 앱 및 서비스에 액세스` 요청이 나타나면 요청 사이트가 `www.smes.go.kr`인지 확인합니다. 해당 사이트가 PC의 앱·서비스에 연결하는 데 동의하는 사용자가 직접 `허용`을 선택해야 합니다. 회색 로딩이 사라지면 `권한·로딩 확인 후 로그인 계속`을 눌러 저장 계정으로 같은 창에서 이어갑니다. 이미 로그인 버튼 동작을 시도했다면 결과가 불명확하더라도 자동 재전송하지 않으며, 공식 창에서 로그인 결과·추가 인증을 확인한 뒤 `인증 완료 후 상태 확인`을 누릅니다. 이 버튼은 상태만 확인합니다. 권한을 자동 허용하거나 브라우저 보안 기능을 우회하지 않습니다. 창을 닫고 새로 연결하면 권한을 다시 요청할 수 있습니다. [Microsoft의 로컬 연결 권한 설명](https://learn.microsoft.com/en-us/deployedge/ms-edge-local-network-access)

- 로그인 창은 기업별로 격리하며 개인 Edge 프로필을 재사용하지 않습니다. 인증 대기는 최대 15분이며, 처음 로그인 표시를 확인하면 작업시간 15분을 새로 부여합니다. 이후 상태 확인이나 화면 읽기로 시간을 계속 연장하지 않습니다. 창·서버를 닫으면 종료되며 서버 재시작 후 자동 복구되지 않습니다.
- Playwright 디버그 환경변수 `DEBUG` 또는 활성 `PWDEBUG`가 있으면 비밀 입력을 거부합니다. 추적·녹화·스크린샷을 남기지 않습니다.

- 로그인 이력이 확인된 신청 유형 화면에 가이드북·서류 준비 공지가 표시되면 제목·전체 본문·확인 버튼이 확인된 공지와 일치할 때 한 번만 닫은 뒤 로그인 표시를 다시 확인합니다. 다른 문구·입력칸·동의 항목이 있는 창은 자동 처리하지 않습니다. 앱의 일반 안내 확인 메시지와 실제 Edge 권한 요청을 구별해야 합니다.
- 로그인 표시 확인은 신청기업 일치나 제출 검증이 아닙니다. 공식 신청 항목·첨부 규격·동의·제출 결과 화면이 아직 검증되지 않아 자동 제출은 비활성화되어 있습니다. 실제 제출 번호나 접수 완료 상태를 생성하지 않습니다.
- 상용 연동의 이용조건은 벤처인 공식 약관 및 기관 확인이 필요합니다. 2026-09-25 이 PC의 저장 계정으로 로그인한 뒤 공식 메뉴의 로그아웃 표시와 앱 상태 전환을 확인했습니다. 신청기업 일치·등록·제출의 통합 검증은 별도로 수행해야 합니다.

### 검토 의견의 판단 이력

사업계획서 탭에서 저장 원고를 선택하고 `검토 의견 처리 이력`의 의견을 직접 고릅니다. 확인 필요·담당자 해결 판단·보류 중 상태를 선택하고 판단 담당자와 이유를 입력해 저장합니다. 이후 판단은 새 버전으로 추가하며 과거 기록은 유지합니다. 원고·의견·기업자료가 바뀌면 재검토 필요를 표시합니다.

담당자의 해결 판단은 원고 오류를 삭제하거나 확인 필요 항목·내부 검토 완료 제한을 해제하지 않습니다. 실제 내용 수정은 원고의 새 버전으로 저장하고, 해당 버전의 근거와 검토 의견을 다시 확인합니다. 원고 편집과 판단 이력 편집은 한 번에 하나씩 저장하거나 취소합니다.

### 기간·단위·산식 수치 대조

사업계획서 탭의 `기간·단위·산식 수치 대조`에서 새 미검토 대조안을 만듭니다. 수치를 원문의 부호·쉼표·소수 그대로 옮기고, 같은 회사 자료 본문이나 저장 원고 버전의 정확한 인용을 연결합니다. 단위·기간·자료 기재/목표/가정 구분은 직접 선택하며 미확인 값은 비워 둡니다. 본문 미추출 원본은 수치 근거로 선택할 수 없습니다.

관측 수치에서 비교쌍과 합계·차이·곱·나눗셈·비율 산식을 선택합니다. 지원되는 단위 관계와 같은 기간·구분일 때만 정확한 십진수 산술을 수행하며, 자동 단위 환산이나 반올림으로 값을 맞추지 않습니다. 기간·단위가 다르거나 정보가 부족하면 비교 불가로 남깁니다. 숫자 같음·다름은 사실 진위나 자료 의미의 일치 판단이 아닙니다.

최초 대조안은 미검토로 저장합니다. 이후 새 버전에 담당자 판단과 미해결 사항을 기록하고, 수치·인용·산식을 수정하면 판단 선택은 미검토로 돌아갑니다. 과거 버전과 저장 당시 원고·원본 SHA를 보존하며 DRAFT 기록을 내려받을 수 있습니다. 현재 화면은 등록정보·인용 연결만 대조하므로 내려받기가 현재 원본 파일의 재검증이나 기관 제출을 의미하지 않습니다.

### 자료 준비 자동 진행과 제출 준비 묶음

기업 목록은 미완료 업무의 입력된 기한, 미추출 원본, 최신 원고 확인 항목, 사전진단·준비 기록, 최신 요청·답변의 발송 표시를 함께 보여 줍니다. `기한 경과`, `오늘~7일 내 기한`, `확인 필요`로 필터링하고 기한순으로 정렬할 수 있습니다. 각 카드에서 자료함·진단·원고·진행 관리로 바로 이동합니다. 7일은 앱의 확인 편의 범위이며 법정 기한을 계산하는 기능이 아닙니다. 목록은 불러온 시점의 로컬 기록이며 기관 상태나 외부 알림 수신을 의미하지 않습니다.

기업을 열고 `로컬 준비 이어가기`를 누르면 현재 자료의 사전진단과 자료 기반 아이템 분석을 이어갑니다. 아이템을 직접 선택하면 원고와 규칙 점검까지 준비하며, 현재 자료에 맞는 기존 결과·원고는 재사용합니다. 각 단계의 산출물과 진행 위치를 함께 저장하므로 중단 후 `저장 상태 확인`으로 확인하고 재개할 수 있습니다. 외부 AI를 호출하거나 사실 검토 완료·벤처인 입력·동의·제출을 자동 처리하지 않습니다. 과거 준비 기록의 원고 버전과 이후 수동 편집한 최신 버전은 구분해서 표시합니다.

`자료 변경 후 로컬 준비 연결`은 기업별로 기본 꺼짐입니다. 범위를 확인하고 켜면 그 이후 저장한 기업정보·자료·기관 요청/답변의 변경만 모읍니다. 해당 기업 화면이 보이고 편집·다른 작업이 없을 때 기존 로컬 준비를 이어가며, 아이템 선택 이유나 판독문 검토가 필요한 곳에서는 대기합니다. 기관 기록만 바뀌면 요청 확인으로 연결합니다. 화면을 닫으면 새 자동 작업을 시작하지 않으며, 이미 시작한 작업은 `연결 저장 상태 확인`에서 확인합니다. 응답을 받지 못한 요청은 자동 재전송하지 않고 저장 기록을 조회합니다. 연결을 꺼도 기존 원고·기록을 지우지 않습니다.

복수 파일 접수에서 외부 문서 판독·음성 전사를 선택하면 원본 하나의 이름·해시·크기와 전송 목적지·모델·목적을 먼저 확인합니다. 명시 승인 후 한 번만 요청하며 성공 결과는 미검토로 보관합니다. 외부 요청 시작 뒤 결과를 확인하지 못하면 처리·비용이 발생했을 수 있으므로 자동 재전송하지 않습니다. 새 요청은 중복 가능성을 확인한 별도 승인으로 시작합니다. 저장된 결과를 원문과 대조하고 교정·채택하기 전에는 분석 본문으로 사용하지 않습니다.

사업계획서에서 원고 버전을 선택하고 `제출 준비 묶음`의 원본을 직접 선택하면 ZIP으로 내려받습니다. 원고·인용 대조 목록·규칙 점검과 과제·선택 원본 및 SHA256 목록을 포함합니다. 원본은 최대 10개, 개별 12MiB·합계 24MiB입니다. 미검토·오래된 원고도 DRAFT를 명시해 보관할 수 있으며 원본 저장은 내용 검토나 기관 제출을 의미하지 않습니다. 생성 중 기업자료 또는 원본이 바뀌면 다운로드를 차단하고 새 선택을 요구합니다.

### 요청별 담당자·내부 처리 단계·원고 연결

### 신청 회차와 제출 당시 기록

진행 관리에서 신규·재확인 신청 회차를 별도로 등록합니다. 예정일과 적용 기준 메모는 직접 기록하며 차기 회차는 이전 회차를 선택해 연결합니다. 기존 회사의 원고·자료·기관 기록은 자동으로 특정 신청에 귀속하지 않고 회차 미지정 상태로 보존합니다. 회사 전체 작업공간과 신청 회차는 별도이며 등록만으로 현재 진행 단계가 바뀌지 않습니다.

기관 요청/답변 또는 통보/정정 체인은 한 신청 회차에 귀속합니다. 채택할 정확한 기관 기록 버전을 직접 선택하며, 이동·해제·재연결에는 정정 이력과 메모가 남습니다. 제출 당시 연결한 접수 기록과 과거 귀속 이력도 보존합니다. 회차 정보나 제출 기록의 오류는 새 정정 사건으로 남기고 이전 내용을 덮어쓰지 않습니다. 기업별 회차 30개·사건 200개 한도입니다.

`회차별 절차·안내기한`에서는 회차에 연결된 최신 기관 요청·통보를 선택하고 요청일·안내기한·연장·진행 상태와 그 근거를 기록합니다. 정정은 새 버전으로 남고 과거 기한과 원문·원본 연결은 보존됩니다. 날짜를 비워 두면 미확인으로 표시합니다. 기관의 연장 승인·완료 여부를 앱이 자동으로 확인한 기록은 아닙니다.

`기준·서류 조건 버전`에서는 확인한 출처와 서류별 대상·기간·발급일·대체자료 조건을 수동으로 보관하고 신청 회차에 정확한 버전을 연결합니다. 새 기준을 추가해도 이전 회차의 기준은 자동 교체하지 않습니다. 기준·회사·회차 정보가 달라지면 재확인이 필요하다고 표시합니다. 과거 연결에서 내려받은 DRAFT 참고자료는 당시 기준과 회사·회차 정보를 사용하며, 현행 규정·신청 적격성·자동연계 성공을 보증하지 않습니다.

### 결과 사유별 소명 준비

진행 관리에 심사 결과 통보를 기록하면 해당 통보 버전에서 소명 준비를 시작할 수 있습니다. 통보의 사유 또는 본문에서 정확히 인용한 사유별로 기존 주장·원고 부분, 보강할 사항, 기존/추가 증빙, 소명 초안을 정리합니다. 본문 인용은 현재 등록된 문서와 대조하며 본문 미추출 자료는 보관 원본만 연결합니다. 저장할 때 원본 SHA256을 확인하고 이후 변경된 동일 원본의 재연결과 참조 자료 삭제를 차단합니다.

수정은 새 준비 버전으로 보존합니다. 내부 검토는 직접 체크하고 검토자를 기록하며, 새 버전을 열거나 내용을 변경하면 다시 확인해야 합니다. 통보 정정이나 자료 변경 뒤에는 과거 검토를 현재 확인으로 표시하지 않습니다. 원본 파일은 저장 시점에 대조하며 화면의 등록내용 연결 표시는 현재 파일 바이트를 재검증한 결과가 아닙니다.

검토안 내려받기에는 DRAFT, 기준 통보·원고 버전, 사유별 주장·근거·소명·미확인 기한과 저장 당시 원본 SHA를 포함합니다. 기한과 진행 여부는 직접 확인한 안내에 따라 입력하며 이 기능은 기관 제출이나 법률 판단을 자동 실행하지 않습니다.

### 기관 요청·답변·통보와 원본 증빙

진행 관리에서 기관 요청 원문, 담당자가 확인한 날짜·기한과 근거, 답변 초안 또는 담당자 발송 기록을 보관합니다. 요청 정정과 답변은 새 버전으로 추가하며 이전 본문을 덮어쓰지 않습니다. 답변이 참조하는 요청 버전, 서버 기록 시각, 담당자 입력 날짜를 구분합니다. 실제 발송·납부·기관 접수나 법정 기한을 자동 확인하는 기능은 아닙니다.

`연결 원본 현재 상태 확인`은 저장된 원본·자료 정보와 현재 파일을 읽기 전용으로 대조합니다. 동일 크기 내용 변경도 구분하며, 이름·본문 수정 시각 등 자료 정보 변경도 표시합니다. 이 결과는 조회 당시의 로컬 파일 비교이며 기관 수신 증명이 아닙니다. 다운로드 링크는 현재 자료함 파일이므로 먼저 상태를 확인하세요. 기록은 회사별 200개·본문 등 합계 200,000자까지이며 한도에서는 이전 기록을 유지하고 추가 저장을 거부합니다. 같은 저장 요청의 재시도는 중복 기록을 만들지 않습니다.

### 신청기업 대조와 입력·첨부 연결안

로그인 후 `같은 Edge에서 신청 화면 확인`을 누르면 기존 연결 창으로 공식 신청 주소를 열고, 화면에 표시된 기업정보와 입력 항목의 이름·필수 여부·글자 수·허용 파일 형식을 읽습니다. 첫 화면의 유형 선택은 `혁신성장유형 화면 확인`을 사용합니다. 확인된 유형 바로가기와 제목·전체 본문이 일치하는 일반 준비 공지의 `확인`만 처리하며, 동의·저장·제출 버튼은 누르지 않습니다. 공지의 내용이나 동작이 달라지면 현재 창에서 직접 확인하도록 안내합니다. 이미 공식 사전확인 화면에 있다면 유형 확인을 다시 눌러도 현재 창에서 읽기를 이어갑니다. 주소에 쿼리·해시가 있어도 이를 재작성하거나 탐색에 사용하지 않고 현재 URL을 보존하며 로그인 표시를 새로 확인합니다. 계정정보·숨김 입력·인증 토큰·브라우저 저장소·일반 입력란의 값·전체 HTML을 수집하지 않습니다.

연결 기록은 별도 로컬 `venture_workflows` 테이블에 보관하며 일반 기업 JSON·AI 입력에 포함하지 않습니다. 기업 삭제 시 함께 삭제됩니다. 같은 화면의 연결 기록에는 버전 충돌 검사를 적용합니다.

화면 읽기와 로컬 연결안 검토 후 **입력·첨부 검토안 준비 → 전송 승인 → 1회 실행**을 지원합니다. 선택 항목의 입력 준비와 전체 제출 준비는 별도로 표시합니다. 기업 일치·현재 계정/세션/화면·확인된 대응 관계·선택한 값과 원본 검증을 통과해야 입력 검토안을 준비할 수 있습니다. 계획서 원고를 선택하면 최신 작성본과 내부 검토가 필수이며, 기업정보·원본만 선택한 경우 계획서 미완료는 남은 제출 과제로 보존합니다. 미선택 필수 항목과 동의도 그대로 남겨 두며 자동 완료하지 않습니다. 알 수 없는 오류나 전역 수집 제약은 입력을 차단합니다.

준비 단계는 브라우저를 조작하지 않고, 서버가 계산한 기업·공식 주소·필드·정확한 값과 재무 근거, 첨부 파일명·형식·크기·SHA256과 전체 제출 전 남은 과제를 보여 줍니다. 승인은 이번 선택 항목에만 적용됩니다. 승인은 2분 동안만 유효하며 값이나 계정·기업·화면·원본 내용이 바뀌면 폐기됩니다. 텍스트·단일 선택·첨부 입력란을 합쳐 한 번에 50개, 텍스트는 항목당 20,000자·합계 100,000자까지 지원합니다. 파일은 최대 10개, 개별 12MiB·합계 24MiB까지입니다. 이 용량은 앱의 실행 제한이며 기관의 업로드 제한을 대신하지 않습니다.

`현재 화면과 연결안 대조`는 최신 연결안의 선택 값·원본과 공식 화면을 읽기 전용으로 비교합니다. 일치·빈칸·상충·미확인과 관측 시각만 보여 주며 현재 화면의 실제 값·파일 내용은 대조 응답에 반환하지 않습니다. 첨부는 개수·순서·이름·크기·형식·SHA256을 비교합니다. 기업·계정·세션·문서·항목·연결안·원본이 바뀌면 결과를 폐기합니다. 대조는 과거 승인을 복원하거나 입력·첨부를 다시 실행하지 않습니다. 빈 파일 선택란은 기존 서버 업로드가 없었다는 증거가 아니며, 전부 일치해도 서버 저장·접수 완료나 기존 불확실한 실행의 성공을 뜻하지 않습니다.

첨부 원본은 해당 기업의 자료 ID로만 읽고 경로·부모 폴더·링크·읽기 전후 파일 상태를 검사합니다. 준비와 실행 때 원본 SHA256을 비교하며, 승인된 바이트를 메모리에 고정해 실행합니다. 브라우저 실행기에 로컬 절대 경로를 넘기지 않습니다. 첨부만 있는 화면도 지원하며 공식 `accept`·다중 선택 규칙과 빈 파일 입력란을 확인합니다. 파일 선택의 `input/change` 이벤트로 사이트에 즉시 업로드될 수 있어 파일명을 포함한 전송 승인이 필요합니다.

텍스트만 포함했던 중단 실행은 `미시도 빈 텍스트 새 검토`로 이어갈 수 있습니다. 실행 당시 전체 대상과 값의 해시, 기업·계정·화면·세션 및 누적 시도 기록이 모두 일치해야 합니다. 새로 읽은 화면에서 일치하는 값은 보호하고, 과거에 한 번도 입력을 시도하지 않은 빈 항목만 정확한 값·출처·공식 주소를 보여 준 뒤 별도의 2분 단회 승인을 받습니다. 쓰기 직전 같은 브라우저 평가에서 회사·로그인·항목·보호값을 다시 확인하며, 이번에 새로 쓴 값도 후속 입력에서 보호합니다. 첨부가 포함된 실행, 기록 없는 이전 실행, 진행 중·결과 미확인, 이미 시도했던 빈칸, 상충 값은 이 경로에서 처리하지 않습니다. 최초 시도를 포함한 최대 10회 이력은 덮어쓰거나 자동 삭제하지 않습니다. 완료 표시는 이번 새 입력의 화면 확인이며 기관 저장·접수 확인이 아닙니다.

실행 전에 최근 화면과 원래 주소·문서, 로그아웃 표시, 기업번호, 항목의 메타데이터와 빈값을 다시 검사합니다. 기존 값 덮어쓰기·자동 재시도·롤백은 하지 않습니다. 입력 도중 기업자료·계정 변경을 잠그며, 첫 입력 전에 실행 시작 기록을 로컬 저장합니다. 중단 시 확인된 항목과 마지막 시도 항목을 구분하고 결과가 불확실하면 같은 화면에서 재실행하지 않습니다. 검토 결과 내보내기 v2의 `latestExecutionExternalWritesPerformed`는 **최근 실행**에서 확인된 입력 유무이며, 불확실하면 `null`입니다. 전체 과거 입력 이력이 없었다는 뜻이 아닙니다.

입력 대상은 표준 HTML 텍스트 input·textarea·단일 select·file input을 지원합니다. 대상 요소를 고정하고 마지막 빈값 검사와 기본 value/files setter, input/change 이벤트 처리를 하나의 동기 동작으로 수행해 중간의 요소 교체나 선입력에 의한 덮어쓰기를 막습니다. 실행 후 모든 텍스트 값과 파일의 이름·형식·크기·SHA256을 재확인하고 비동기 해시 계산 중 변경된 화면도 다시 검사합니다. 사용자 정의 편집기, 특수 보안 입력기나 별도의 키 입력 이벤트가 필요한 제어의 호환성은 확인되지 않았습니다. 화면 값·첨부의 재확인이 실패하면 완료로 기록하지 않습니다.

입력·첨부 완료 표시는 화면의 값과 선택된 파일 내용이 확인되었다는 뜻입니다. 사이트 처리 방식에 따라 값·파일이 즉시 전송·자동 저장될 수 있지만, 별도 업로드·저장·동의·최종 제출 버튼은 실행하지 않습니다. 다음 단계·숨긴 항목·외부 프레임·사용자 정의 편집기·공식 사이트의 서버 검증은 별도 확인이 필요합니다. 실행 잠금과 브라우저 세션은 이 PC에서 앱 프로세스 하나를 사용하는 구성입니다. 여러 서버 프로세스나 여러 PC가 같은 저장소를 동시에 쓰는 구성은 지원하지 않습니다. 이번 개발 검증은 가상 입력·원본·모의 브라우저를 사용했고 실제 회사 정보의 공식 입력·업로드는 수행하지 않았습니다.

`신청 화면별 진행 상태`는 연결부터 결과 확인까지 현재 필요한 작업을 표시하고 최근 12개 화면의 실행 결과를 보관합니다. 실행 후 공식 Edge에서 결과를 확인하고 필요한 다음 단계로 이동한 뒤 `다음 화면 연결`을 누르면 현재 열린 화면을 새로 읽습니다. 이 버튼은 공식 사이트의 다음·저장·동의·제출 버튼을 누르지 않습니다. 새 화면에는 새 대응표와 전송 승인이 필요하며, 이전 실행 기록은 보존합니다. 이력은 화면 관측 기록으로 기관 접수·심사 결과를 뜻하지 않습니다.

자동 검사의 DPAPI 실환경 시험은 가상 계정만 사용하며 `VENTURE_TEST_DPAPI=1`로 활성화합니다. 기본 시험은 운영체제 비밀 저장소와 브라우저 의존성을 모의화합니다.

### AI 연결

`web/.env.example`을 참고해 `web/.env.local`을 만들고 서버용 키를 설정한 뒤 앱 서버를 다시 시작합니다. 키를 채팅·코드 저장소·브라우저 공개 환경변수에 넣지 마세요.

```dotenv
OPENAI_API_KEY=발급받은_API_키
OPENAI_MODEL=gpt-5.4
OPENAI_TRANSCRIBE_MODEL=gpt-4o-mini-transcribe
```

기본 모델은 환경변수로 변경할 수 있습니다. API 이용에는 별도 API 접근 권한과 사용량 비용이 필요합니다. 앱에서 AI 모드를 실행하면 기업정보와 등록자료의 본문이 OpenAI로 전송됩니다. 생성 요청은 `store:false`를 사용하며, 이것이 외부 서비스의 모든 데이터 보관을 배제한다는 의미는 아닙니다.

AI 분석은 자료에 기반한 후보와 질문을 생성합니다. AI 사업계획서 작성은 구조화된 원고 생성 후 별도 AI 검토를 수행해 주장·근거의 관련성, 실적과 계획의 구분, 실행계획의 모순 등을 검토 의견으로 남깁니다. 원문에 없는 인용이나 잘못된 출력 구조는 저장하지 않습니다. AI 검토 의견 또한 기업의 사실 확인을 대신하지 않습니다.

키가 없을 때 `자료 기반 정리본`은 실제 입력의 발췌와 항목별 질문을 배치합니다. AI가 작성한 서술형 사업계획서 또는 검증된 추천으로 표시하지 않으며, AI 실패 때 이 모드로 자동 전환하지 않습니다.

### 자료 형식과 저장

- 로컬 추출: 텍스트 PDF, DOCX, XLSX, TXT·MD·CSV·TSV·SRT·VTT.
- 원본만 보관: PDF·PNG·JPEG·WEBP를 외부 AI 전송 없이 보관합니다. `본문 확인 필요` 상태의 빈 본문은 아이템·작성본·검토의 근거에서 제외합니다. 원본을 검토해 본문을 직접 입력하면 수동 자료로 전환되며 원본 파일은 유지합니다. 원본 보관과 사실 확인·기관 첨부는 별개입니다.
- AI 인식: PNG·JPEG·WEBP 이미지, 텍스트 없는 스캔 PDF, MP3·M4A·WAV·MP4·WEBM·OGG 녹음. AI 연결과 원본 전송 선택이 필요합니다.
- HWP·HWPX·DOC·XLS는 지원 형식으로 변환합니다. 이미지·차트가 포함된 문서는 텍스트 추출에서 빠질 수 있어 원본 대조가 필요합니다.
- 파일당 12MB, PDF 120페이지, 자료당 본문 100,000자, 기업당 최대 40개 자료·기업정보 포함 총 160,000자. 초과분을 조용히 잘라 저장하지 않습니다.
- Excel 수식은 실행하지 않고 저장된 결과값을 읽습니다. 녹음 전사는 시간코드를 임의로 만들지 않습니다.
- 기업정보·작성 이력은 기본 `web/.venture-pass/studio.sqlite`, 업로드 원본은 같은 디렉터리 아래에 저장합니다. `VENTURE_DATA_DIR`로 별도 로컬 저장 위치를 지정할 수 있습니다.
- 원본·DB·API 키 파일은 Git 제외 대상으로 설정했습니다. 수동 보관은 서버 종료 후 현재 `VENTURE_DATA_DIR`로 지정한 디렉터리 전체를 복사하며, 검증 가능한 백업은 아래 CLI를 사용합니다. 미설정 시 기본 위치는 `web/.venture-pass`입니다. 로컬 파일은 OS 계정의 접근권한에 의존하며 별도 DB 암호화·다중 사용자 인증은 포함하지 않습니다.

### 검증 가능한 로컬 백업과 새 경로 복원

`pnpm data:local`은 현재 서버를 종료하거나 설정을 바꾸지 않고 로컬 백업·검증·복원 후보를 만드는 운영 도구입니다. 앱이 실행 중이고 정상 WAL/SHM 파일이 있는 상태의 온라인 백업을 권장합니다. Node.js의 SQLite backup API로 DB 스냅샷을 만든 뒤 원본을 순차 복사하고, 전체 DB 행·원본 SHA256·경로·소유 관계를 다시 검사합니다. 작업 중 자료가 바뀌면 완료하지 않으며 자동 재시도하지 않습니다.

PowerShell 예시입니다. 경로는 사용자가 직접 입력합니다. 백업과 복원 목적지의 부모 폴더는 있어야 하고 목적지 폴더 자체는 새 경로여야 합니다.

```powershell
$sourceData = Read-Host "현재 VENTURE_DATA_DIR 전체 경로"
$backupData = Read-Host "새 백업 폴더 전체 경로"
pnpm data:local backup --source "$sourceData" --destination "$backupData"
pnpm data:local verify --source "$backupData"

$restoredData = Read-Host "새 복원 후보 폴더 전체 경로"
pnpm data:local restore --source "$backupData" --destination "$restoredData"
pnpm data:local verify --source "$restoredData"
```

완성된 백업에는 `studio.sqlite`, 등록된 원본, `backup-manifest.json`, `COMPLETE.json`이 있습니다. 완료 표시와 manifest·파일 해시가 모두 맞아야 검증을 통과합니다. 실패한 새 폴더는 조사할 수 있도록 남기며 완료된 백업으로 취급하지 않습니다. 기존 목적지, 원본과 겹치는 경로, Git 저장소·OneDrive 아래 목적지, 링크·재분석 지점·하드링크, 누락되거나 예상하지 못한 원본, 알 수 없는 DB 구조는 거부합니다. 상한은 기업 500개, 원본 20,000개, 원본별 12MiB·합계 2GiB, DB 64MiB입니다. 원본 복사는 64KiB 단위로 처리합니다.

기존 3개 테이블의 회사 DB와 `studio_prepared_packages`가 추가된 현재 DB를 모두 지원합니다. 준비본 테이블은 지정된 구조·제약만 허용하며 기업 관계, 보관 버전·요청 식별자, 메타데이터·원고·ZIP의 SHA와 크기를 검사합니다. 과거 원고나 현재 원본을 삭제한 뒤에도 보관된 준비본 ZIP은 백업·복원에 포함됩니다. 복원하면서 현재 자료로 준비본을 다시 만들거나 과거 검토 상태를 바꾸지 않습니다. DB 64MiB 제한에는 준비본 ZIP도 포함되므로 보관량에 따라 한도를 초과할 수 있습니다. 이때 완료 표시를 만들지 않고 중단하며 준비본을 자동 삭제하지 않습니다. 별도 품질평가 DB는 `quality-backup / quality-verify / quality-restore`로 관리합니다.

품질 전용 백업은 기존 평가 3테이블의 v1, 합성 후보 버전·요청을 포함한 5테이블의 v2, 모의 실행·이벤트·요청까지 포함한 8테이블의 v3를 지원합니다. 정확한 스키마·버전 연결·해시·요청·실행 순서를 검사하며 빈 저장소, 후보만 등록한 저장소, 평가와 실행을 함께 보관한 저장소도 복원할 수 있습니다. 기존 평가 저장소를 덮어쓰지 않습니다. 화면의 버전별 JSON은 조회용이므로 전체 복원에는 전용 백업을 사용합니다.

설정의 개발·검토 도구에서 고정 50개 개발 회귀 평가와 별도로 합성 후보 12개의 원문 버전을 등록할 수 있습니다. 후보는 AI가 작성했으며 등록만으로 사람 정답표·독립 검증 세트·실제 AI 평가를 완료 처리하지 않습니다. 후보 등록은 최대20버전·버전당8MiB, 전체 평가와 합산 본문256MiB 한도를 적용합니다.

등록본을 연 뒤 후보 하나를 선택하면 무료 모의 실행 준비안을 확인할 수 있습니다. 등록 버전·입력 SHA·엔진 프롬프트/schema·모델·호출 범위를 고정하며 로컬 모의 공급자로 작성 1회와 검토 1회만 시험합니다. 실제 API 키·회사 자료·외부 AI를 사용하지 않습니다. 모의 원고는 제출용 원고가 아니며 출력 검증 완료를 의미 품질 합격으로 표시하지 않습니다. 실제 AI의 가격 근거·금액 상한·전송 승인이 없는 현재 실행 화면은 실제 유료 호출을 제공하지 않습니다.

실행 시작과 각 전송 직전·응답 수신·출력 검증을 불변 이력으로 보관합니다. 응답이 유실되면 같은 요청 번호로 조회하며 자동 재전송하지 않습니다. 아직 기록을 관측하지 못한 경우에만 동일 요청의 명시 재확인을 제공합니다. 시작 기록은 있으나 결과가 미확정이면 조회만 가능하며, 해당 후보를 새 요청 번호로 다시 실행하지 않습니다. 실행은 최대20개·단계당1MiB·실행당7단계, 기존 품질 기록과 합산256MiB 한도이며 원고·검토 결과와 특정 버전 JSON을 보관합니다. 실제 공급자 청구서·사람 검토·독립 평가와 구분해 사용하세요.

정상 종료된 WAL DB에서 `-wal`·`-shm`·`-journal`이 모두 없는 경우도 지원합니다. 원본 DB를 SQLite로 열지 않고 안전하게 복사한 고유 임시 디렉터리에서만 무결성·전체 논리 데이터를 검사하고 DELETE 저널로 정규화합니다. 원본 DB·디렉터리의 식별자·수정 정보·SHA256과 보조파일 부재를 완료 직전까지 다시 검사하며, 도중 앱 재시작이나 변경이 감지되면 완료 표시를 제거하고 중단합니다. 검증된 임시 파일만 개별 정리하며 낯선 파일이나 경로 교체가 발견되면 그 디렉터리는 남깁니다.

WAL/SHM 중 하나만 있거나 `-journal`이 있으면 `SOURCE_WAL_NOT_READY`로 거부합니다. 이때 보조파일을 임의로 지우지 말고 앱의 정상 연결·종료 상태를 확인하세요. 보조파일 부재와 무결성 검사는 과거 WAL이 유실되지 않았다는 증명이 아니며 현재 DB 바이트의 구조만 검증합니다. 수동 복사본은 완료 표시가 있는 검증 백업과 구분합니다. 온라인 읽기는 SQLite 잠금·공유메모리를 사용하지만 기업의 논리 데이터와 원본 바이트를 수정하지 않습니다.

백업 DB에는 기업 본문과 Windows DPAPI로 암호화된 계정 보관 기록이 포함됩니다. `.env.local`, API 키, DPAPI 비밀키, 브라우저 프로필은 복사하지 않으며 외부로 전송하지 않습니다. 백업 자체는 별도로 암호화하지 않으므로 접근권한을 관리하고 Git·공유 폴더에 넣지 마세요. 다른 PC나 Windows 사용자에서는 저장 계정을 복호화하지 못할 수 있어 앱에서 다시 등록해야 합니다. 과거 연결·입력 기록은 보존하지만 살아 있는 브라우저 세션이나 단회 승인을 복원하는 기능은 아닙니다.

복원은 항상 **새 경로의 후보**를 만들며 기존 데이터, `.env.local`, 서버 실행 상태를 바꾸지 않습니다. 전환하려면 기존 `VENTURE_DATA_DIR` 값을 별도로 보존하고, 검증된 새 경로로 해당 값만 수동 변경한 뒤 앱을 재시작하세요. 회사별 자료·원고·이력을 앱에서 확인하고 문제가 있으면 기존 경로로 되돌립니다. `verify`는 구조·관계·파일 바이트 검증이며 전체 업무 스키마, 계정 복호화, 기관 처리 성공을 보증하지 않습니다. 복원 경로를 앱에서 사용한 뒤의 정상 편집은 원래 manifest와 달라지므로 **전환 전에** 스냅샷 검증을 마쳐야 합니다.

파일 접수의 원본 저장이 중단된 경우 `SOURCE_INTAKE_RECOVERY_REQUIRED`로 백업을 중단합니다. 자료함의 접수 목록에서 해당 파일의 저장 상태를 복구한 뒤 새 백업을 만드세요. 파일이나 DB를 직접 지우지 마세요. 원본 저장을 마친 뒤의 미검토 판독문·접수 이력도 DB에 함께 보관되며, 복원만으로 본문 검토나 채택을 완료 처리하지 않습니다.

합성 자료만 사용하는 운영 회귀검사는 `pnpm test:local-data`입니다. 일반 Vitest 검사와 별도이며 백업→검증→새 경로 복원, 실패와 원본 보존을 확인합니다. 명령 출력에는 결과 코드와 개수만 표시하고 회사명·본문·키·실제 경로를 출력하지 않습니다.

- 서버는 기본적으로 `127.0.0.1`에만 바인딩합니다. Studio API는 외부 Host·교차 출처 요청을 거부합니다. 공개 배포 전에 인증·권한·암호화·비밀 관리와 운영 저장소 구성을 추가해야 합니다.

동시에 편집한 자료는 revision 충돌 시 덮어쓰지 않습니다. 자료 수정·삭제·재분석은 기존 검토 완료 상태를 취소하고, 작성본은 버전 이력으로 유지합니다. 자료 삭제 시 이전 작성본에 이미 포함된 인용은 이력에 남습니다. 기업 삭제는 해당 기업의 전체 이력과 원본을 삭제합니다.

### 아이템 선택 이유와 후보 구분

아이템 분석에서 추천 근거와 부족 자료를 확인한 다음 ‘이유를 적고 아이템 선택’을 누릅니다. 선택 이유는 직접 입력하며 추천 설명을 자동 복사하지 않습니다. 같은 후보의 이유를 정정해도 과거 선택과 당시 후보 설명을 유지합니다. 새 원고 생성과 로컬 준비의 다음 단계는 현재 분석에 맞는 선택 이유 저장 뒤 진행합니다. 기존 원고 조회·다운로드·수동 수정은 계속 가능합니다.

후보의 ‘현재 신청 후보’, ‘근거 확인 후 후보’, ‘향후 개발 제안’은 추천 분류입니다. 사실·기술 보유·기관 적합성의 확인 완료가 아닙니다. 구형 기록과 자료 정리 모드에서 분류하지 않은 후보는 미확인으로 표시합니다. 과거 기록의 분류나 해시를 소급 변경하지 않습니다.

### 기업 연락처·신청 담당 역할

기업정보 화면에서 소재지, 대표·담당 연락 메모, 자료 제공·최종 내용 확인·납부 담당자를 선택 입력합니다. 공란은 미확인이며, 정정은 새 버전으로 저장합니다. 이 이름과 연락 메모는 계정 권한·발송 동의·납부 승인을 뜻하지 않습니다.

연락 메모는 기업의 기술·사업 설명과 따로 보관합니다. 분석·원고 생성·진단·제출 준비 ZIP에 자동 포함하지 않으며 기존 원고/제출 기록을 수정하지 않습니다. 전체 로컬 데이터 백업에는 다른 내부 기록과 함께 보관되므로 백업 파일도 같은 수준으로 관리합니다.

### 주장·근거 검토와 자료 변경 영향

사업계획서의 `주장·근거 검토 기록`에서 정확한 원고 버전·항목·문장을 직접 선택합니다. 근거 자료, 주장 성격, 확인 방식, 담당자와 기한을 기록하고 이후 버전에 판단자·이유·확인일을 남깁니다. 기존 수치 대조나 검토 의견의 정확한 버전을 참고로 연결할 수 있습니다. 최초 기록과 내용을 수정한 편집은 미검토로 시작합니다.

같은 주장을 새 원고 버전의 같은 항목에 다시 연결할 때는 인용과 원고 검토 참조를 다시 고릅니다. 과거 문장·원고·판단은 이전 버전에 남습니다. 판단 저장은 원고의 확인 필요 표시나 신청 단계를 변경하지 않습니다.

자료함의 `자료 변경 영향 · 연결 대상 재확인`에서 자료별로 연결된 후보·원고·주장·답변을 확인합니다. 변경 또는 정보 부족인 연결에서 정확한 기록 화면으로 이동할 수 있습니다. 보조 수치·검토 기록을 거친 연결은 별도로 표시합니다. 등록 시각·인용 대조와 현재 원본 바이트의 무결성 검사는 구분합니다.

### 실사 질문·답변 출력 묶음

진행 관리의 `실사 질문·답변 출력 묶음`에서 정확한 저장 원고 또는 수동 제출 기록을 고릅니다. 해당 원고의 답변 버전과 포함할 원본을 직접 선택하면 질문·답변·담당 역할·근거 위치·미확인 사항을 ZIP으로 내려받습니다. 답변이나 원본을 선택하지 않은 묶음도 만들 수 있습니다.

과거 제출 기록은 그때의 원고에 연결하며 최신 원고나 답변으로 교체하지 않습니다. 선택 원본은 저장 당시 식별값과 현재 바이트를 대조합니다. 내려받은 파일은 DRAFT 실사 준비 자료이며 실제 제출·기관 수신·실사 완료·내용 검토 완료를 뜻하지 않습니다. 연락 메모와 선택하지 않은 답변·원본은 자동 포함하지 않습니다.

### 요청·녹취의 답변 근거 제안

진행 관리의 보완 답변 준비 항목 또는 실사 모의 답변 편집에서 `선택 자료에서 미검토 답변 근거 제안`을 펼칩니다. 보완 항목에는 최신 요청의 정확한 문장을 먼저 인용하고, 실사 답변에는 저장 원고의 질문을 선택합니다. 같은 요청 문장이 여러 곳에 있으면 정확한 위치도 직접 고릅니다.

등록 본문을 최대 6개·합계 60,000자까지 선택하고 `이 PC에서 근거 제안`으로 원문 후보를 확인합니다. 로컬 후보는 문장과 단어의 일치를 돕는 기능이며 관련성·진위를 보장하지 않습니다. 미채택 판독문과 본문 없는 원본은 사용하지 않습니다. 실제 저장된 좌표가 현재 본문과 일치하는 경우에만 페이지·셀·시간 구간을 표시합니다.

후보를 직접 선택해 편집기에 가져옵니다. 기존 초안·답변이 있으면 변경 선택이 필요하며, 답변은 미검토 상태로 채웁니다. 준비안이나 질문·자료가 바뀌면 이전 제안은 무효화됩니다. 기존 편집기의 저장을 별도로 눌러야 이력에 남습니다. 글자·근거 한도를 넘으면 자동으로 자르지 않고 선택을 줄이도록 안내합니다.

`AI 전송 내용 먼저 확인`은 정확한 요청·질문과 선택 본문 전체, 목적지·모델·목적을 표시하는 미리보기입니다. 2분 안에 명시 동의한 한 번의 요청만 전송하며 원본 파일·미선택 자료·계정 정보는 포함하지 않습니다. AI는 인용 범위만 제안하고 서버가 원문 일치를 다시 검사합니다. 응답을 받지 못하면 자동 재전송하지 않으며 새 미리보기와 중복 처리 가능성 확인이 필요합니다. 실제 AI의 의미 판단 품질과 실자료 사용은 별도 검증 범위입니다.

## 데이터와 근거

서버전용 `data/venture-companies.json`은 사용자 제공 「벤처기업명단(2026년8월).xlsx」 분석 결과에서 혁신성장유형만 추출한 자료입니다. 대표자명은 앱 데이터에서 제외했습니다. 전체 8MB 명단을 브라우저에 보내지 않고 검색한 페이지와 작은 통계만 전달합니다.

원본의 분석 중간자료가 상위 폴더 `분석/workbook_data.json`에 있을 때 다음 명령으로 다시 가져올 수 있습니다. 스크립트는 원본 엑셀의 SHA-256, 연번, 날짜 및 집계의 일치를 확인합니다.

```powershell
pnpm data:import
```

데이터는 정적인 2026년 8월 스냅샷입니다. 파일 갱신 후 가져오기를 실행하고 서버를 다시 시작하거나 다시 빌드해야 캐시가 갱신됩니다. `next.config.ts`는 배포 시 `data/*.json`을 서버 파일 추적에 포함합니다.

해석 기준:

- 기업 수는 원본의 기록 수입니다. 사업자등록번호가 없으므로 같은 이름을 임의로 합치지 않습니다.
- 원본 연번을 ID로 쓰고, 원본 지역 `전남광주`를 유지합니다.
- 유효시작일은 설립일이 아닙니다. 원본의 ‘신규’도 창업 직후라는 뜻이 아닙니다.
- 보유 명단의 구성비는 승인율·선정 이유·합격확률이 아닙니다.
- 준비 경로는 입력한 날짜의 3주년을 기준으로 안내합니다. 윤일의 3주년은 해당 연도 2월 말일로 계산합니다. 기관의 실제 적용 규칙·사실관계 확인은 별도입니다.

제도 근거는 상위 폴더 「2026 벤처기업확인제도 가이드북」 인쇄 27쪽(지표), 28쪽(제출서류)과 공식 [혁신성장유형 안내](https://www.smes.go.kr/venturein/institution/requireGuide?rgCd=C), [확인절차](https://www.smes.go.kr/venturein/institution/processGuide)를 참고했습니다. 지표별 준비 안내와 기관의 심사 판단을 구분합니다.
